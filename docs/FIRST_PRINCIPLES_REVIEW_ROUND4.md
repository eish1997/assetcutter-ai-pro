# 第一性原理代码审查报告（第四轮）

## 本轮目标
第四轮聚焦一个问题：

1. `App.tsx` 中对话会话、临时库与批量操作状态过于集中

## 第一性判断
- 会话列表、当前会话、临时库、筛选与批量选择都属于同一个“对话工作区”状态域，不应散落在入口组件里。
- `App.tsx` 更适合承载业务编排和页面装配，不适合继续堆积对话域状态细节。

## 已完成优化
- 新增 [`hooks/useDialogWorkspace.ts`](../hooks/useDialogWorkspace.ts)，集中管理：
  - 对话会话初始化与当前会话解析
  - 当前会话消息更新
  - 临时库增删与筛选
  - 临时库批量选择与批量下载
  - 会话新建、归档、删除
- 在 [`App.tsx`](../App.tsx) 中移除一组分散的 `useState/useMemo/useEffect` 与临时库辅助函数，改为调用 `useDialogWorkspace()` 返回的统一接口。
- 会话标题异步生成逻辑改为按 `sessionId` 更新，避免异步返回时误写到后来切换到的活动会话。

## 收益
- `状态边界更清晰`：对话工作区状态被收口到单一 hook，入口组件不再同时维护多份同域状态。
- `后续拆发送链路更安全`：下一步可以继续把理解、生图、重生图等链路从 `App.tsx` 中拆出，而不必先处理会话/临时库状态耦合。
- `回归风险更低`：新建、归档、删除会话与临时库清理逻辑现在走同一入口，减少分叉修改。

## 验证结果
- `npm run typecheck` 通过
- `npm run lint` 通过（仍保留历史 warning，未新增 error）
- `npm run test` 通过
- `npm run build` 通过

## 剩余风险
- `App.tsx` 里对话发送、理解、生图、重生成、裁切、检测仍然集中，主复杂度尚未完全下降。
- `three-core` 仍然是当前构建中最大的单个 chunk，性能面优化空间还在。

## 下一轮建议
- 第五轮优先继续拆对话发送链路，把“理解/问答/生图/重生成”抽成专用 hook 或 service 编排层。
- 然后再视收益决定是否继续细拆 3D 相关依赖与能力入口。
