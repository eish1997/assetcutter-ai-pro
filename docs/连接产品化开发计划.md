# 连接产品化开发计划

状态：待执行  
目标读者：产品、前端、Local Companion、Copilot/Agent 开发者  
当前约束：workflow 正在迁移进本地伴侣能力体系，本计划不把 workflow 回归作为连接闭环的阻塞项。

## 1. 背景判断

当前“连接”已经从旧宿主中心里抽离出来，具备能力包草稿、对象对话、启动/关闭/识别运行、安装、探测、导入导出、云端版本、Copilot 处理入口等基础能力。

但用户仍然会感觉它像玩具，原因不是页面不够漂亮，而是产品闭环不够硬：

1. 用户看到的是卡片和按钮，不是一个可信的“连接对象”。
2. Copilot 能调用动作，但还没有稳定地经营一个连接，从诊断、授权、执行、失败修复到复测。
3. 多数软件只能创建草稿或启动，缺少真实安装和真实探测模板。
4. 失败后缺少产品化解释：为什么失败、现在能做什么、下一步由谁做、需要什么权限。
5. 页面缺少成熟度表达，用户无法判断“这个连接到底到了哪一步”。

因此，本计划的核心不是继续堆宿主，也不是单纯美化连接页，而是把“连接”做成 Copilot 可长期操作、可验证、可复用的本机能力对象。

## 2. 产品目标

一句话目标：

> 用户只描述目标或拖入软件快捷方式，Copilot 能把一个软件推进到“已真连通”，或者明确告诉用户还差什么，并把过程沉淀在这个连接对象里。

具体目标：

1. 连接是能力对象，不是宿主列表。
2. 每个连接有独立对象对话、事件日志、失败摘要、下一步建议。
3. Copilot 有受控权限，可以执行连接闭环，而不是只帮用户点按钮。
4. 真正连通必须来自真实软件信号，不能用文件存在、卡片存在、安装记录冒充。
5. 页面展示的是产品状态：能启动、能安装、能探测、已连接、需要修复、模板未接入。
6. 至少跑通一个非 Photoshop 的真实端到端样板，证明架构不是演示玩具。

## 3. 非目标

1. 不恢复旧 62 宿主中心作为默认产品页面。
2. 不把所有宿主一次性迁移到新连接体系。
3. 不允许 Copilot 任意执行 shell 命令、任意写路径、任意杀进程。
4. 不把 workflow 迁移中的本地运行器争议作为连接产品化的阻塞。
5. 不用 mock probe 或测试卡片冒充真实连接成功。
6. 不让普通用户发布或切换云端版本。

## 4. 完成定义

连接产品化完成，不以“页面有卡片”或“按钮能点击”为标准。

必须同时满足：

1. 用户拖入一个真实软件快捷方式后，系统能创建 `software_connection` 能力包草稿。
2. 连接卡片能显示成熟度、目标路径、最近失败、下一步建议。
3. Copilot 可以接管该连接对象，执行受控 loop。
4. loop 能按权限完成诊断、识别运行、启动、安装、探测、写事件、复读上下文。
5. 对支持真实桥接模板的软件，能安装真实脚本或插件，并通过真实信号 probe 成功。
6. 对暂不支持真实桥接模板的软件，页面和 Copilot 明确说明“当前只支持启动/识别运行，真实连接模板待接入”，而不是表现为产品故障。
7. 失败记录必须留在该连接对象中，重新打开对象对话时可继续修复。
8. 自动测试和至少一个人工真实软件验收通过。

## 5. 状态模型

每个 `software_connection` 必须能归入以下成熟度之一。

| 状态 | 含义 | 用户看到的解释 | 是否可发布 |
| --- | --- | --- | --- |
| `draft` | 已创建草稿 | 已记录目标，尚未完成诊断 | 否 |
| `path_ready` | 有启动路径 | 已找到软件位置，可尝试启动 | 否 |
| `process_ready` | 可识别/启动进程 | 可启动或识别运行中的软件 | 否 |
| `bridge_supported` | 有真实桥接模板 | 可安装连接脚本或插件 | 否 |
| `bridge_installed` | 桥接已安装 | 已写入脚本/插件，仍需软件内加载并探测 | 否 |
| `probe_failed` | 真实探测失败 | 未收到真实软件信号，可继续修复 | 否 |
| `connected` | 已真连通 | 已收到真实 heartbeat/health/command port/plugin callback | 是，管理员可提交 |
| `template_missing` | 模板未接入 | 当前只能启动/识别，真实连接模板待 Copilot 或开发者接入 | 否 |
| `needs_user_action` | 需要用户动作 | 需要用户打开软件、选择目录、授权安装或在软件内运行入口 | 否 |

## 6. 权限模型

Copilot 处理连接时使用对象级权限，不使用无限权限。

当前推荐权限：

| 权限 | 能做什么 | 风险 | 约束 |
| --- | --- | --- | --- |
| `context.read` | 读取连接上下文、manifest、事件 | 低 | 只读当前能力包 |
| `process.discover` | 识别运行中的目标软件 | 中 | 只能按 hostId/进程白名单 |
| `process.launch` | 启动目标软件 | 中 | 路径必须匹配目标软件白名单或保存路径 |
| `bridge.install` | 安装连接脚本/插件 | 高 | 只能写入已允许的脚本/插件目录 |
| `connection.probe` | 探测真实连接信号 | 低 | 不能 mock 成功 |
| `event.write` | 写入失败、修复、复测事件 | 中 | 只能写入当前能力包事件 |
| `conversation.open` | 打开对象对话 | 低 | 绑定当前连接 session |

验收要求：

1. `ac.capability.connection_loop_run` 必须要求显式 `permissions`。
2. 未授权的动作不得执行。
3. loop 必须有最大步数，默认不超过 6，硬上限不超过 8。
4. 每一步都必须返回结构化 `steps`。
5. `connection.probe` 成功必须来自真实探测函数。

## 7. 阶段计划

### P0：连接对象状态可信化

目标：让页面和对象上下文能准确表达“这个连接到了哪一步”。

修改位置：

1. `local-companion/src/capabilities/capabilityPackages.ts`
2. `local-companion/src/capabilities/capabilityContext.ts`
3. `local-companion/src/capabilities/capabilityLifecycle.ts`
4. `companion-desktop/shell/capability-card-schema.js`
5. `companion-desktop/shell/connection-page.js`
6. `tests/capabilityPackages.test.ts`
7. `tests/shellConnectionPageUi.test.ts`
8. `tests/shellCapabilityCardSchema.test.ts`

执行任务：

1. 新增连接成熟度计算函数。
   - 输入：`CapabilityPackage`、`manifest`、`lastInstall`、`lastProbe`、`events`。
   - 输出：`maturity`, `availableActions`, `blockedReason`, `nextAction`, `publishEligible`。
2. 后端 context 返回成熟度。
   - `GET /v1/capability-packages/:id/context` 返回 `connectionState`。
   - `contextPrompt` 包含成熟度、最近失败、下一步。
3. 前端卡片使用成熟度。
   - 显示“可启动 / 可安装 / 待探测 / 已连接 / 模板待接入”。
   - 不再只显示 `draftStatus`。
4. 禁用或降级不可用动作。
   - 对 `template_missing`，安装/探测不表现为坏掉，而是提示“交给 Copilot 接入模板”。
   - 启动/识别仍可用时保留。

自动验收：

```powershell
node --check companion-desktop/shell/connection-page.js
node --check companion-desktop/shell/capability-card-schema.js
npm run local-companion:typecheck
npx vitest run tests/capabilityPackages.test.ts tests/shellConnectionPageUi.test.ts tests/shellCapabilityCardSchema.test.ts
```

人工验收：

1. 拖入未知 exe。
2. 页面显示“模板待接入”，而不是“探测失败”。
3. 卡片显示目标路径、最近事件、下一步。
4. 点击 Copilot 处理后，对象对话能解释当前只支持哪些能力。

完成标准：

1. 每个连接都有明确成熟度。
2. 用户不再需要猜“失败是产品坏了还是模板没做”。
3. 探测成功仍必须来自真实信号。

### P1：Copilot 连接经营者闭环

目标：让 Copilot 从“动作调用器”变成“连接经营者”。

修改位置：

1. `companion-desktop/agent-tool-schemas.cjs`
2. `companion-desktop/agent-body-host.cjs`
3. `companion-desktop/brain-adapters/codex.cjs`
4. `companion-desktop/shell/copilot-panel.js`
5. `tests/agentToolSchema.test.ts`
6. `tests/agentP2L2.test.ts`
7. `tests/copilotSettingsUi.test.ts`

执行任务：

1. 完善 `ac.capability.connection_loop_run`。
   - loop 开始先读取 context。
   - 根据成熟度决定动作顺序。
   - 执行后再次读取 context。
   - 返回 `steps`, `finalContext`, `nextAction`, `needsUserAction`。
2. 增加 loop 策略。
   - `path_ready`：优先 discover，再 launch。
   - `bridge_supported`：安装后要求用户重启或在软件内运行入口。
   - `bridge_installed`：优先 probe。
   - `probe_failed`：写事件并打开对象对话继续修复。
   - `template_missing`：生成模板接入建议，不假装安装。
3. Copilot 对象对话必须绑定 session。
   - 同一连接持续对话不串到其它连接。
   - 失败事件进入当前连接 context。
4. 页面按钮“Copilot 处理”只发送 loop 目标，不手写具体桥接方案。

自动验收：

```powershell
node --check companion-desktop/agent-tool-schemas.cjs
node --check companion-desktop/agent-body-host.cjs
node --check companion-desktop/brain-adapters/codex.cjs
npx vitest run tests/agentToolSchema.test.ts tests/agentP2L2.test.ts tests/shellConnectionPageUi.test.ts
```

人工验收：

1. 打开已有连接。
2. 点击“Copilot 处理”。
3. Copilot 回复中必须说明当前状态、要执行的动作和权限。
4. 执行失败后，刷新连接页仍能看到最近失败。
5. 重新进入对象对话能继续修复同一个连接。

完成标准：

1. Copilot 可以经营一个连接对象，而不是只点按钮。
2. loop 过程可审计。
3. 失败后能继续，不丢上下文。

### P2：真实端到端样板

目标：选一个非 Photoshop 软件，完成真实连接闭环。

推荐样板优先级：

1. Blender：Python 插件/脚本路径明确，适合做 HTTP health。
2. Maya：已有 Command Port 思路，但版本和安全设置更复杂。
3. Unreal：项目插件更重，适合作第二个样板。

本阶段建议先选 Blender。

修改位置：

1. `local-companion/src/bridges/blenderBridgeInstall.ts`
2. `local-companion/src/bridges/hostAppProcess.ts`
3. `local-companion/src/capabilities/capabilityLifecycle.ts`
4. `local-companion/src/capabilities/softwareConnectionAdapter.ts`
5. `tests/hostAppProcess.test.ts`
6. `tests/capabilityPackages.test.ts`
7. `tests/hostBridgeInstallers.test.ts`

执行任务：

1. Blender manifest 识别。
   - 拖入 `blender.exe` 或快捷方式后，写入 `hostId=blender`。
   - 保存 `executablePath`、版本候选、安装目标提示。
2. 启动闭环。
   - `launch` 使用保存的 Blender 路径。
   - `discover_running` 能识别正在运行的 Blender。
3. 安装真实桥接。
   - 写入 Blender scripts/startup 或 addon 目录。
   - 安装结果记录写入路径和版本。
4. 真实 probe。
   - Blender 内脚本启动本机 HTTP health 或 heartbeat。
   - probe 必须读取真实进程/脚本信号。
5. 软件内入口。
   - 用户能在 Blender 内看到或触发 AssetCutter 连接入口。
   - 若需要重启，页面和 Copilot 明确说明。

自动验收：

```powershell
npm run local-companion:typecheck
npx vitest run tests/capabilityPackages.test.ts tests/hostAppProcess.test.ts tests/hostBridgeInstallers.test.ts
```

人工验收：

1. 安装真实 Blender。
2. 拖入 Blender 快捷方式或 exe。
3. 页面创建 Blender 连接。
4. 点击 Copilot 处理。
5. Copilot 启动或识别 Blender。
6. Copilot 安装连接脚本。
7. 按提示重启 Blender 或运行入口。
8. 点击探测或让 Copilot 继续探测。
9. 页面显示“已连接”。
10. 对象事件包含安装、探测、成功证据。

完成标准：

1. 非 Photoshop 软件真实 probe 成功。
2. 过程不依赖旧 62 宿主页面。
3. 用户不需要理解桥接模板。
4. 失败时可继续修复。

### P4：模板缺失到模板生成

目标：当用户连接一个未支持的软件时，Copilot 不只说“不支持”，而是能生成接入计划，并在权限允许时创建连接模板草稿。

2. `local-companion/src/capabilities/capabilityLifecycle.ts`

5. `companion-desktop/agent-body-host.cjs`
6. `tests/capabilityPackages.test.ts`
7. `tests/agentP2L2.test.ts`

执行任务：

1. 新增模板草稿类型。
   - 不直接写进生产 bridge definition。
   - 作为连接对象的 `templateDraft` 或事件保存。
2. Copilot 识别软件连接类型。
   - 可执行软件
   - 脚本型 DCC
   - 项目插件型软件
   - 命令端口型软件
   - heartbeat 型软件
3. 生成接入计划。
   - 需要写哪些文件。
   - 需要用户选择哪些目录。
   - 探测信号是什么。
   - 安全边界是什么。
4. 模板草稿必须可验证。
   - 未真实验收前不能显示“已支持”。
   - 不能发布到云端正式版本。

1. 未支持软件也有产品化路径。

## 8. 测试矩阵

| 场景 | 自动测试 | 人工测试 | 成功标准 |
| --- | --- | --- | --- |
| 拖入未知 exe | `shellConnectionPageUi` | 拖入本地 exe | 创建草稿，状态为模板待接入 |
| 拖入已知软件 | `capabilityPackages`, `hostAppProcess` | 拖入 Blender/Maya | 写入 hostId 和 executablePath |
| 启动软件 | `hostAppProcess` | 点击启动 | 只启动白名单目标 |
| 识别运行 | `hostAppProcess` | 软件已打开后识别 | 保存运行目标 |
| 安装桥接 | `hostBridgeInstallers` | 选择真实目录 | 写入允许目录 |
| 探测连接 | `capabilityPackages` | 软件内加载后 probe | 收到真实信号 |
| Copilot 处理 | `agentToolSchema`, `agentP2L2` | 点击卡片按钮 | 对象对话持续处理 |
| 失败修复 | `capabilityPackages` | 故意缺入口或不启动软件 | 失败写入对象事件 |
| 云端发布 | `capabilityPackages` | 管理员发布 | 未 probe 不可发布 |

## 9. 真实验收脚本

每完成一个真实软件样板，必须记录以下内容到 `docs/连接改造执行状态.md`：

1. 软件名称和版本。
2. 安装路径。
3. 创建方式：拖入快捷方式、拖入 exe、对话创建。
4. 是否成功启动。
5. 桥接写入位置。
6. 软件内入口位置。
7. probe 信号类型。
8. probe 成功证据。
9. 失败重试记录。
10. 最终状态截图或日志摘要。

人工验收必须能复现，不接受“开发机刚好成功但没有证据”。

## 10. 开发顺序建议

推荐顺序：

1. P0：成熟度模型。
2. P1：Copilot loop 策略。
3. P3：连接页第二轮产品化。
4. P2：Blender 真实端到端样板。
5. P4：未知软件模板草稿。

原因：

1. 先有成熟度，页面和 Copilot 才知道自己在处理什么。
2. 先有 loop，真实样板失败时才有可持续修复能力。
3. 页面第二轮能立即降低玩具感。
4. 真实样板证明产品闭环。
5. 模板生成最后做，避免在地基未稳时扩大范围。

## 11. 每轮开发完成后的固定动作

每轮都必须做：

1. 更新对应测试。
2. 更新 `docs/连接改造执行状态.md`。
3. 如果改动 `local-companion/` 或 `companion-desktop/` 运行时代码，执行：

```powershell
npm run restart:local-companion
```

4. 若 workflow 迁移导致全量 typecheck 或回归失败，记录为“workflow 迁移中已知阻塞”，不要把连接闭环测试改成跳过真实门禁。

## 12. 近期最小可交付

下一轮最小可交付建议只做 P0：

## 13. Agent 执行协议

本节用于 AI Agent 持续执行本文档。执行者不需要一次吞完整计划，必须按小任务循环推进。

### 13.1 每轮循环

每一轮只执行一个任务，固定顺序如下：

1. Observe：读取本文档、`docs/连接改造执行状态.md`、任务指定文件和最近测试输出。
2. Select：选择第一个 `pending` 且依赖已完成的任务。
3. Act：只修改任务列出的文件，除非测试证明必须增加相邻文件。
4. Verify：先跑任务自己的 focused 检查，再按需要跑更宽检查。
5. Record：把完成证据追加到 `docs/连接改造执行状态.md`。
6. Continue/Stop：如果任务完成，继续下一个任务；如果遇到真实阻塞，按阻塞规则记录并停止。

### 13.2 选择规则

1. 优先执行 P0，P0 未完成前不做 P1/P2/P3/P4。
2. 同一阶段按编号顺序执行。
3. 不跳过失败任务，除非失败被确认是 workflow 迁移等无关阻塞，且任务 focused gate 已通过。
4. 如果用户提出新的最高优先级问题，以用户最新要求为准，并在状态文档记录插队原因。

### 13.3 记录格式

每完成或阻塞一个任务，追加如下记录：

```markdown
## P0-001 执行记录

时间：YYYY-MM-DD HH:mm
状态：completed | blocked

改动文件：
- `path/to/file`

完成内容：
- ...

验证：
- `command`：通过/失败，摘要

人工验收：
- 未执行/通过/失败，证据

遗留风险：
- ...

下一任务：
- P0-002
```

### 13.4 阻塞规则

1. workflow 迁移导致的 typecheck 或 capability workflow 测试失败，不阻塞连接 focused gate；必须记录为“workflow 迁移中无关失败”。
2. 真实软件未安装时，不阻塞自动测试；人工验收标记为 pending。
3. 缺少管理员、登录、权限、真实软件操作时，停止并请求用户执行具体动作。
4. 同一任务连续三次同类失败，记录 blocked，不继续扩大修改范围。
5. 产品语义不明确时，先选择更保守、不扩大权限、不假装成功的方案。
