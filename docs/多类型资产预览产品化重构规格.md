# 多类型资产预览产品化重构规格

**日期**：2026-07-15
**状态**：产品化设计稿 / 开发前规格
**适用范围**：工作台资产卡片、资产大预览、资产树、资产版本切换、文/图/视频/3D/音频/文件预览

## 1. 背景判断

当前资产预览已经开始支持文字、图片、视频、3D、音频、文件等类型，但实现路径更像从图片预览逐步扩展：

- 大预览底座仍是 `ImagePreviewOverlay`。
- 文本、视频、音频、3D 在图片预览壳里各自塞入一个独立面板。
- 卡片态每种类型各自补占位、补角标、补按钮。
- 大预览中出现“外层预览套内层预览”的视觉结构。
- 类型切换、版本切换、工具栏、详情区缺少统一规则。
- 部分中文文案出现乱码，进一步放大了“临时拼装”的感受。

这不是单纯样式问题，而是资产系统还没有形成统一的产品协议。下一阶段不应继续零碎补 UI，而应先把资产卡片、大预览、资产树、类型渲染器的职责拆清楚。

一句话目标：

> 资产预览不再是图片预览的扩展，而是一个统一资产工作台。图片、文本、视频、3D、音频只是不同的资产渲染器。

## 2. 产品原则

### 2.1 统一外壳，不统一内容

所有资产类型共用同一个预览外壳：

- 顶部标题栏
- 中心预览区
- 资产树 / 版本切换区
- 右侧详情区
- 底部状态区或辅助信息区
- 统一关闭、复制、下载、更多操作

但中心内容由类型渲染器决定：

- 文本像文档查看器
- 图片像图片查看器
- 视频像播放器
- 音频像音频播放器
- 3D 像模型查看器
- 文件像文件详情页

### 2.2 卡片是入口，不是缩小版大预览

资产卡片只承担快速识别和快速操作，不应把大预览能力缩小后塞进卡片。

卡片必须统一：

- 整卡预览封面
- 类型标识
- 状态
- 版本数量
- hover 操作

卡片不再拆成“上面预览、下面信息”两个固定区域。整张卡只保留预览图显示，标题、来源、版本、状态通过角标、轻量遮罩或 hover 浮层承载。

卡片不做复杂编辑，不放完整播放器，不放大段说明，不放嵌套面板，也不在底部另起一块信息栏。

### 2.3 媒体型资产和集合型资产分开建模

资产不只有“单个可预览文件”。需要明确分成两类：

- 媒体型资产：文本、图片、视频、3D、音频、文件。它们的核心是一个或多个可预览版本。
- 集合型资产：资产集、分镜表、组合/组。它们的核心是组织一组子资产、结构或镜头，不等同于单个媒体文件。

集合型资产在卡片上仍然是一张统一封面，但打开后进入集合视图：左侧或中心展示集合结构，用户再选择里面的图片、文本、视频、3D、音频等子资产进行预览。

### 2.4 大预览是主工作区，不再套小面板

打开资产后，用户看到的是一个完整资产预览工作区，而不是图片 Lightbox 里面再出现一个文本卡片、视频卡片或音频卡片。

大预览里只能有一套顶栏、一套操作区、一套边栏。不同类型只替换中心 Viewer。

### 2.5 类型 UI 要有合同

每种资产类型都要明确：

- 卡片态显示什么
- 大预览中心区显示什么
- 工具栏有哪些操作
- 详情区有哪些字段
- 缺资源时如何降级
- 是否支持编辑
- 是否支持加入输入框或作为后续任务输入

没有合同的类型不进入正式 UI，只能进入 `file` 或 `unsupported` 降级态。

### 2.6 资产树负责导航，Viewer 负责呈现

资产树只负责切换资产和版本，不负责展示内容细节。

中心 Viewer 只负责显示当前选中的版本，不负责管理全局资产列表。

## 3. 信息架构

### 3.1 统一结构

```text
AssetPreviewOverlay
  AssetPreviewChrome
    AssetPreviewTopBar
    AssetPreviewBody
      AssetPreviewTree
      AssetPreviewCanvas
        AssetPreviewRenderer
      AssetPreviewInspector
    AssetPreviewFooter
```

### 3.2 职责边界

| 模块 | 职责 | 不负责 |
|---|---|---|
| `AssetPreviewOverlay` | 打开/关闭、焦点、遮罩、快捷键、布局 | 具体类型渲染 |
| `AssetPreviewTopBar` | 标题、类型、主操作、更多菜单 | 类型内部状态 |
| `AssetPreviewTree` | 资产组、资产、版本/产物切换 | 渲染预览内容 |
| `AssetPreviewCanvas` | 中心区域尺寸、滚动、背景 | 业务按钮 |
| `AssetPreviewRenderer` | 按类型分发 Viewer | 管理资产列表 |
| `AssetPreviewInspector` | 元信息、来源、尺寸、格式、任务链路 | 播放器控制 |
| `AssetCardShell` | 卡片骨架、选择、拖拽、hover 操作 | 类型复杂交互 |
| `AssetCardPreviewRenderer` | 卡片封面渲染 | 大预览能力 |

## 4. 资产卡片规范

### 4.1 统一卡片骨架

```text
┌────────────────────┐
│ 类型角标       状态 │
│                    │
│                    │
│      整卡封面       │
│                    │
│                    │
│ 标题/版本 hover浮层 │
└────────────────────┘
```

所有类型必须保持同一套比例、圆角、阴影、角标位置和 hover 行为。卡片不再有固定底部信息栏，避免预览区域被切碎。

### 4.2 卡片统一字段

| 元素 | 必填 | 说明 |
|---|---|---|
| 类型标识 | 是 | 文、图、视频、3D、音频、文件、资产集、分镜 |
| 状态 | 是 | ready、loading、missing、error、unsupported |
| 整卡封面 | 是 | 有真实封面用真实封面，无封面用统一占位 |
| 标题 | 是 | 默认隐藏在轻量遮罩或 hover 浮层，优先资产标题，其次文件名，其次来源任务名 |
| 来源 | 否 | hover 浮层展示，生成任务、上传、本地伴侣、历史版本 |
| 版本数 | 否 | 用角标展示，有多个产物时显示 |
| 主操作 | 是 | 点击打开大预览 |
| 次操作 | 否 | hover 后显示复制、下载、更多 |

### 4.3 卡片信息承载规则

卡片常驻只显示：

- 整卡封面
- 左上角类型角标
- 右上角状态或版本角标
- 必要的播放、3D、集合等视觉标识

hover 或选中时显示：

- 标题
- 来源
- 版本数量
- 快捷操作

特殊情况：

- 文本资产没有图片封面时，封面本身就是文本摘要，但仍然铺满整卡。
- 音频资产没有封面时，封面本身是统一波形图，但仍然铺满整卡。
- 文件资产没有封面时，封面本身是统一文件占位，但仍然铺满整卡。
- 资产集和分镜表的封面可以是拼贴图、首张图、镜头网格或自动生成封面，但不能在卡片内展开子列表。

### 4.4 各类型卡片 UI 合同

| 类型 | 卡片封面 | 卡片信息 | 不应该出现 |
|---|---|---|---|
| 文本 | 铺满整卡的标题 + 摘要 | hover 显示字数、段落数、版本 | 大文本编辑器、复杂统计表、底部信息栏 |
| 图片 | 缩略图 | 尺寸、来源、版本 | 内嵌图片工具栏 |
| 视频 | poster + 播放标识 | 时长、分辨率、版本 | 完整播放器控件 |
| 3D | poster / 统一 3D 占位 | 格式、文件数、版本 | 内嵌 3D 控制器 |
| 音频 | 铺满整卡的波形占位 / 封面 | 时长、格式、版本 | 完整 audio 控件 |
| 文件 | 铺满整卡的文件占位 | 文件名、大小、格式 | 伪装成图片卡片 |
| 分镜表 | 首帧/镜头网格/分镜封面 | 镜头数、缺图数、子资产数 | 大段表格内容、卡片内展开镜头 |
| 资产集 | 拼贴封面 / 主视觉封面 | 资产数、类型构成 | 嵌套完整资产列表 |
| 组合/组 | 堆叠封面 / 拼贴封面 | 成员数、最近更新 | 多层小卡片 |

### 4.5 卡片视觉统一规则

- 类型徽标固定在左上角。
- 状态徽标固定在右上角。
- 标题不占固定底部区域，默认进入 hover 或选中态遮罩。
- 卡片 hover 后只出现一层操作浮层。
- 缺封面时使用统一占位组件，不允许每个类型临时写一套背景。
- 音频波形、文件图标、文本摘要都要使用同一套颜色、字号和间距。
- 卡片中禁止出现独立标题栏、独立边框面板、独立下载栏、固定底部信息栏。

## 5. 大预览规范

### 5.1 统一布局

```text
┌────────────────────────────────────────────┐
│ 顶栏：标题 / 类型 / 主操作 / 更多 / 关闭     │
├──────────────┬────────────────┬──────┬──────┤
│ 缩略图树      │ 中心预览区       │ 详情 │ 资产 │
│ 版本/产物节点  │ Viewer Canvas   │ 面板 │ 列表 │
├──────────────┴────────────────┴──────┴──────┤
│ 底部：状态、来源、提示、快捷操作              │
└────────────────────────────────────────────┘
```

移动端可调整为：

- 顶栏固定
- 中心预览区优先
- 左侧缩略图树通过底部抽屉打开
- 详情区通过右上角信息按钮打开
- 右侧资产列表在移动端收为横向资产胶片条或抽屉

### 5.2 顶栏统一内容

| 元素 | 说明 |
|---|---|
| 标题 | 当前资产或当前版本名称 |
| 类型 | 文、图、视频、3D、音频等 |
| 版本 | 当前版本 / 总版本数 |
| 主操作 | 按类型显示最重要的操作 |
| 通用操作 | 复制、下载、打开源文件、更多 |
| 关闭 | 固定右上角 |

顶栏不显示类型内部控件。例如视频播放、3D 材质切换、文本阅读模式不放在全局顶栏。

### 5.3 中心预览区规则

中心预览区只显示当前版本的 Viewer。禁止出现“外层大预览 + 内层卡片预览”的嵌套观感。

每个 Viewer 的根元素应该铺满中心区：

- 无额外大圆角边框
- 无重复标题栏
- 无重复关闭按钮
- 无重复下载栏
- 自己只保留类型必要的内部控制

### 5.4 右侧详情区

详情区展示可扫描信息，而不是堆满调试字段。

统一字段：

- 类型
- 文件名 / 标题
- 来源任务
- 创建时间
- 当前版本
- 存储状态
- 尺寸 / 时长 / 格式 / 字数
- 对象 Key / 本地 Key，默认折叠
- 可用于哪些后续任务

## 6. 左侧缩略图树和版本切换

### 6.1 资产节点类型

左侧缩略图树负责版本和产物切换，需要区分三层概念：

| 节点 | 含义 | 示例 |
|---|---|---|
| 媒体资产 | 一个具体资产，可包含多个版本或产物 | 图片 A、文本 B、视频 C、3D D |
| 集合资产 | 一个容器，内部组织多个子资产或结构节点 | 资产集、分镜表、组合/组 |
| 版本/产物 | 某个资产下的具体可预览结果 | 原图、重绘结果、视频结果、GLB、改写文本 |

集合型资产不是普通媒体资产，也不是文件夹的简单 UI 别名。它本身有元信息、封面、来源、可操作能力，同时包含一组子资产。

右侧缩略条不承担版本控制，只显示当前资产列表中的资产预览，便于在同一批资产之间快速切换。

### 6.2 树结构

```text
项目资产
  文本 A
    原文
    改写结果
    文生图结果
  图片 B
    原图
    局部重绘
    生视频结果
    生成 3D 模型
  视频 C
    原视频
    截帧
  3D D
    GLB
    FBX
    预览截图
  资产集 E
    图片 01
    文本提示词
    3D 模型
    音频参考
  分镜表 F
    镜头 01
      文本描述
      参考图
      生成视频
    镜头 02
      文本描述
      参考图
```

### 6.3 切换规则

- 点击资产节点：选中资产，并默认打开最近活跃版本。
- 点击版本节点：选中具体版本，中心 Viewer 立即切换类型。
- 点击集合资产节点：中心区显示集合总览，而不是直接随机打开某个子资产。
- 点击集合内子资产：中心 Viewer 切到对应子资产类型。
- 点击分镜镜头节点：中心区显示该镜头的结构化内容和关联资产。
- 右侧资产缩略条点击只切换资产，不切换版本。
- 图片版本显示图片工具。
- 文本版本显示文本工具。
- 视频、音频、3D 显示各自工具。
- 不可预览版本显示文件详情和下载入口。

### 6.4 树节点字段

| 字段 | 说明 |
|---|---|
| 类型图标 | 当前节点类型 |
| 名称 | 资产标题或版本名 |
| 来源 | 原始、生成、派生、上传 |
| 状态 | ready、missing、error |
| 子节点数量 | 有多个版本时显示 |

## 7. 集合型资产设计

### 7.1 资产集

资产集是一个“资产容器”，不是一个单独媒体文件。

卡片态：

- 整卡显示拼贴封面或主视觉封面。
- 左上角显示资产集角标。
- 右上角显示子资产数量或状态。
- hover 展示资产类型构成，例如图片 8、文本 2、3D 1。

打开后：

- 中心区默认显示资产集总览。
- 总览可以是拼贴墙、类型分组、最近更新或主资产预览。
- 左侧资产树展开资产集的子资产。
- 点击子资产后，中心区切到对应类型 Viewer。

资产集详情区：

- 子资产总数
- 类型构成
- 来源
- 创建时间
- 最近更新
- 可用于哪些后续任务

不应该出现：

- 在卡片里展开完整子资产列表。
- 把资产集当成一张普通图片。
- 打开资产集后随机进入第一张图，导致用户不知道集合结构。

### 7.2 分镜表

分镜表是“结构化集合资产”，核心不是单个表格截图，而是镜头结构和每个镜头关联的多类型资产。

卡片态：

- 整卡显示首帧、镜头网格或分镜封面。
- 左上角显示分镜表角标。
- 右上角显示镜头数量。
- hover 展示缺图、缺视频、待生成等状态。

打开后：

- 中心区默认显示分镜总览。
- 总览包含镜头列表、镜头缩略、状态和关键字段。
- 左侧资产树按镜头展开。
- 点击镜头节点后，中心区显示该镜头详情。
- 点击镜头里的图片、文本、视频、音频、3D 子资产后，进入对应 Viewer。

分镜详情区：

- 镜头数
- 已生成图片数
- 已生成视频数
- 缺失项
- 来源任务
- 可继续执行的任务，例如补图、生成视频、导出分镜

不应该出现：

- 把分镜表只当作一张表格图片。
- 在卡片中塞大段表格文字。
- 镜头和镜头产物混在同一级，导致用户不知道当前选的是镜头还是资产。

### 7.3 组合 / 组

组合或组更像“临时集合”或“工作流选择集”。

卡片态：

- 整卡显示堆叠封面或拼贴封面。
- 角标显示组。
- hover 展示成员数和主要类型构成。

打开后：

- 中心区显示组总览。
- 左侧列出成员资产。
- 点击成员资产进入对应 Viewer。

组合和资产集的区别：

- 资产集偏长期保存和复用。
- 组合/组偏临时编组、批量操作或工作流上下文。

## 8. 各类型大预览 UI 合同

### 8.1 文本资产

中心区：

- 阅读模式
- 编辑模式
- 结构模式
- 原文模式

工具：

- 复制全文
- 加入输入框
- 导出 TXT
- 导出 Markdown
- 保存修改

详情：

- 字数
- 段落数
- 行数
- 来源任务
- 是否超过输入上限

不应该出现：

- 图片式缩放控件
- 图片背景棋盘
- 内层独立卡片标题栏

### 8.2 图片资产

中心区：

- 适应窗口
- 原尺寸
- 放大缩小
- 拖动画布
- 透明背景 / 棋盘背景

工具：

- 下载
- 复制图片
- 打开源文件
- 进入局部重绘 / 去背景 / SAM / 高度 3D 等图片能力

详情：

- 宽高
- 文件格式
- 来源任务
- 版本

不应该出现：

- 视频播放器控件
- 文本编辑控件

### 8.3 视频资产

中心区：

- 原生视频播放器或统一播放器
- poster
- 时长
- 进度条

工具：

- 播放 / 暂停
- 静音
- 下载
- 复制链接
- 截帧，后续可作为图片资产

详情：

- 时长
- 分辨率
- 格式
- 来源模型

不应该出现：

- 图片缩放工具
- 二次标题栏

### 8.4 3D 资产

中心区：

- 轨道控制
- 模型加载状态
- 材质 / 线框 / 预览图模式
- 环境光和背景

工具：

- 重置视角
- 切换材质模式
- 下载模型
- 截图保存为图片资产

详情：

- 格式
- 文件数
- 主模型 URL
- 贴图/材质状态
- 来源任务

不应该出现：

- 图片预览里的“3D 模式补丁感”
- 独立包裹卡片

### 8.5 音频 / 音乐资产

中心区：

- 波形或频谱占位
- 播放器
- 当前时间 / 总时长

工具：

- 播放 / 暂停
- 下载
- 复制链接
- 设为后续任务输入

详情：

- 时长
- 格式
- 采样率，若有
- 来源模型

不应该出现：

- 假视频 UI
- 图片封面强依赖

### 8.6 文件 / 未知资产

中心区：

- 文件图标
- 文件名
- 格式
- 可下载状态
- 无法预览原因

工具：

- 下载
- 复制链接
- 打开源文件

详情：

- 文件名
- MIME 类型
- 大小，若有
- 存储 Key

不应该出现：

- 伪造成图片或视频
- 空白黑框

## 9. 状态和降级规范

所有资产类型统一使用以下状态：

| 状态 | 卡片表现 | 大预览表现 |
|---|---|---|
| `ready` | 正常封面 | 正常 Viewer |
| `loading` | 骨架屏 | 加载状态 + 可取消 |
| `missing` | 缺失占位 | 显示缺失原因、Key、恢复建议 |
| `unsupported` | 文件占位 | 显示文件信息、下载入口 |
| `error` | 错误占位 | 错误摘要、重试、复制诊断信息 |

降级态也要产品化，不能只显示空白、黑框或浏览器默认错误。

- 文、图、视频、3D、音频卡片风格一致。
- 大预览不再出现明显双标题栏。

当前落地状态：

当前落地状态：

- 图片预览顶栏已支持将当前资产加入底部输入框/拖入槽，继续走现有主图或参考图任务链路。

- 视频、音频、3D、文件目前尚未建立专用二进制输入槽；在后续供应商模型支持对应输入能力后，应升级为真正的媒体输入协议，而不是只传引用文本。

## 12. 验收清单

### 产品验收

- 打开任意资产，不会出现“大预览套小预览”的观感。
- 所有类型的卡片布局一致。
- 所有类型的缺失、错误、不可预览状态一致。
- 用户能明确当前选中的是哪个资产、哪个版本、哪个产物。
- 文本资产像文档，视频像播放器，3D 像模型查看器，音频像音频播放器。
- 详情区信息可读，不像调试面板。

### 技术验收

- 非图片类型不再直接依赖图片 Lightbox 的内部布局。
- 资产类型判断集中在 `workflowAssetVariants` 或等价服务中。
- Viewer 组件没有互相判断其它类型。
- 卡片和大预览共享同一套类型、状态、版本协议。
- 新增类型只需新增 Viewer 和卡片封面渲染，不需要改大预览主体结构。

### 体验验收

- 桌面端无错位、无重叠、无双标题栏。
- 移动端中心预览优先，树和详情可折叠。
- 文案无乱码。
- 所有按钮风格统一。
- 空状态和错误状态有明确下一步。

---

## 13. 当前结论

当前多类型资产预览已经打通了能力，但还不是产品化产物。真正的优化方向不是继续给现有预览补按钮，而是：

1. 统一资产卡片协议。
2. 建立真正的资产预览外壳。
3. 将每种类型拆成独立 Viewer。
4. 用资产树管理资产和版本切换。
5. 统一状态、详情、操作和降级体验。

按这个方向改完后，资产预览会从“能打开”升级为“能管理、能理解、能继续生产”的工作台核心能力。
