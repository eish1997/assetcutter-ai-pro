# 本地伴侣发布前检查清单

用于 `companion-desktop` 发布前的统一检查，避免漏项。

**主站（静态站 + auth-api）部署、环境与「第一版」范围说明**见 **[`网站与发布检查清单.md`](./网站与发布检查清单.md)**。

## 1) 基础构建

**推荐（固定发行流程）**：仓库根执行 **`npm run companion-desktop:release:pack`**（见 skill `companion-release-pack`）。会停掉本机伴侣 → 打到 **`companion-desktop/dist-out-<去点版本>/installer/`** → 小工具 ZIP 到 **`dist-out-shell-tools/`** → 写 SHA256 → 再重启伴侣。升 patch：`npm run companion-desktop:release:pack -- -BumpPatch`。

- [ ] 执行 `npm run companion-desktop:release:pack` 成功（或下方分步命令）
- [ ] 执行 `npm run companion-desktop:pack` 成功（生成 **`companion-desktop/dist/pack/win-unpacked`**）
- [ ] 执行 `npm run companion-desktop:dist:portable` 或 `npm run companion-desktop:dist:retry` 成功
- [ ] 便携产物存在：**`companion-desktop/dist/portable/AssetCutterCompanion-<version>-<buildTag>-x64.exe`**（`<buildTag>` 为时间戳或环境变量 **`COMPANION_ARTIFACT_SUFFIX`**）
- [ ] NSIS 产物存在：**`companion-desktop/dist/installer/`** 或 **`dist-out-XXX/installer/AssetCutterCompanion-<version>-<buildTag>-x64.exe`**（及同目录 **`.blockmap`**，若启用差分更新）
- [ ] 小工具 ZIP 存在：**`dist-out-shell-tools/<id>-<semver>.zip`**


## 2) 签名（上线前）

- [ ] 环境变量 `CSC_LINK` 已配置
- [ ] 环境变量 `CSC_KEY_PASSWORD` 已配置
- [ ] （可选）时间戳服务可达

> 可运行预检查：  
> `powershell -NoProfile -ExecutionPolicy Bypass -File "scripts/companion-desktop-release-check.ps1" -RequireSigning`

## 3) 更新发布（上线前）

- [ ] 确认更新源地址（建议环境变量：`COMPANION_UPDATE_FEED_URL`）
- [ ] 若使用 **本站 auth-api** 生成 YAML：Path A feed 为 **`/api/companion-artifacts/electron-updater/win32/stable`**（客户端请求 **`…/latest.yml`**）；须配置 **`COMPANION_DIST_PUBLIC_HTTP_BASE`** 或 **`R2_PUBLIC_BASE_URL`**，登记 **sha512**；部署后 **`npm run companion-desktop:verify-update-pipeline`** 通过（见 [`本地伴侣-插件与发行.md`](./本地伴侣-插件与发行.md) §2）
- [ ] 若发布 Copilot/Codex 一键配置：先运行 `npm run companion:codex-auth-env` 生成 `.env.codex-shared-auth.local`，将其中 `CODEX_SHARED_AUTH_JSON_BASE64` 与 `CODEX_SHARED_AUTH_UPDATED_AT` 填入 Render 的 `assetcutter-auth-api` 环境变量并 redeploy；登录用户请求 `/api/team/codex/auth` 应返回 200。未登录应返回 401，未配置身份应返回 `codex_shared_auth_not_configured`，404 代表线上代码未部署到该接口。
- [ ] 上传/登记桌面壳前运行 `npm run companion:desktop-upload-manifest`；如需命令行发布，先 dry-run：`npm run companion:desktop-publish -- --dry-run`，确认无误后设置 `COMPANION_ADMIN_COOKIE` 或传 `--cookie=...` 再执行 `npm run companion:desktop-publish` 上传 `.exe` 与 `.blockmap` 并登记 `desktop_shell / win32 / stable / sha512`；登记后 `npm run companion:codex-production-check` 应看到更新源包含当前版本。
- [ ] 发布最新安装包到更新源（公网 URL 与 YAML 内 **`files[].url`** 一致）
- [ ] 记录版本号、构建时间、产物 SHA256

> 可运行预检查：  
> `powershell -NoProfile -ExecutionPolicy Bypass -File "scripts/companion-desktop-release-check.ps1" -RequirePublishUrl`
> `powershell -NoProfile -ExecutionPolicy Bypass -File "scripts/companion-desktop-release-check.ps1" -RequirePublishUrl -RequireCodexOneClick -CodexAuthUrl "https://你的线上域名/api/team/codex/auth" -CodexAuthCookie "已登录用户Cookie"`
> `npm run companion:codex-one-click-check -- --strict --auth-url=https://你的线上域名/api/team/codex/auth --cookie=已登录用户Cookie`
> `npm run companion:codex-production-check -- --auth-base=https://你的线上域名 --cookie=已登录用户Cookie`

## 4) 验收回归

### 4a) 任意用户机（上线门禁，勿只用开发机）

- [ ] **版本已 bump**（勿与已知坏包同 semver；如 0.2.5 spawn 秒崩后须 ≥0.2.6，否则 electron-updater 盖不住）
- [ ] **勿上传**确认仍含旧 `local-companion-bundle` 的目录（例：修复前打的 `dist-out-025`）；以新 `dist-out-XXX` 为准
- [ ] 打包日志含 `[bundle-local-companion-runtime] ok`，且内置 `main.cjs` 含 `__ac_import_meta_url`（CJS `import.meta.url` polyfill；缺则 18765 秒崩）
- [ ] **干净 Win 机**（无仓库、无 Vite、无本机 auth-api:9100）：卸载旧版 → 装新包 → `http://127.0.0.1:18765/v1/health` 200
- [ ] 概览**不应**长期「本地服务未连接」；失败时托盘提示 + `%LOCALAPPDATA%\AssetCutterCompanion\sandbox\desktop-shell\local-companion-spawn.log` 无 `fileURLToPath`/`ERR_INVALID_ARG_TYPE`
- [ ] 工作台能打开公网主站（系统代理不可达时也应能靠 direct 回退打开）
- [ ] 设置配对保存后，工作台侧能探测本机伴侣（健康或落盘任一项）
- [ ] 在干净 Win 机上运行 `npm run companion:codex-one-click-check -- --strict`，确认本机依赖、Codex CLI、本机身份文件与云端身份接口风险均已处理。
- [ ] Copilot 面板点击 **一键配置** 后能自动检查本机、安装缺失 Node/npm 与 Codex CLI、拉取团队 Codex 身份，并在成功后直接发送第一条对话。

### 4b) 常规

- [ ] 启动后托盘可打开主窗口与本机管理页
- [ ] 退出托盘后子进程结束
- [ ] **设置 → 与网站配对**（本机通信密码 + 允许的网站地址，对应环境变量）保存并生效

## Codex one-click release commands (ASCII addendum)

Before publishing a Codex one-click desktop build:

1. Export the current machine Codex auth file for the cloud service:
   `npm run companion:codex-auth-env`
2. Validate the generated env file before pasting it into Render:
   `npm run companion:codex-auth-env:check -- --env-file=.env.codex-shared-auth.local`
3. Paste `CODEX_SHARED_AUTH_JSON_BASE64` and `CODEX_SHARED_AUTH_UPDATED_AT` into the `assetcutter-auth-api` service env and redeploy.
4. Verify the logged-in cloud payload with a real team session cookie:
   `npm run companion:codex-production-check -- --auth-base=https://assetcutter-auth-api.onrender.com --cookie=<logged-in-cookie> --strict`
5. Publish/register the desktop artifact with admin auth:
   `npm run companion:desktop-publish -- --auth-base=https://assetcutter-auth-api.onrender.com --cookie=<admin-cookie>`
6. Run the finalizer with separated cookies when both are available:
   `npm run companion:codex-finalize-production -- --publish --strict --auth-cookie=<logged-in-cookie> --cookie=<admin-cookie>`
