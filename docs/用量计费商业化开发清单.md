## 0. 北极星与边界

### 0.1 产品北极星

用户能回答三个问题：

1. **我用了多少**（按能力、按项目、按时间）  
2. **还剩多少 / 会不会被停**（套餐、余额、硬顶）  
3. **某次工作流花了多少**（可下钻到步骤 / 任务，非黑盒）

运营/财务能回答：

1. **本月上游成本**（与 GCP / Tripo 等官方账单可对账）  
2. **毛利与异常**（重试重复、测试流量、定价滞后）  
3. **谁该升级套餐**（用量分布、超额用户）

### 0.2 架构原则（必须遵守）

| 原则 | 含义 |
|------|------|
| **双账本** | **用户账本**（实时、可分到 user/project/step）与 **成本账本**（官方账单、日/月汇总）分离；不共用 GCP Console 当用户后台 |
| **合同对齐** | 计量单位与供货商合同一致：token / 张 / 秒 / task；轮询状态默认不计费 |
| **单写入口** | 业务 UI 不直接记用量；经 **BFF / 网关 / 任务适配器** 在「合同完成点」写 `usage_events` |
| **幂等** | `idempotencyKey`（`requestId` / `upstreamTaskId` / `asyncJobId`）防重试重复扣费 |
| **价表外挂** | 模型注册表可挂 `billingSku`；**单价**在独立 Price Catalog，可热更新 |
| **展示与扣费解耦** | 对用户可展示「积分 / 次数 / 美元」；底层统一为 `usage_quantity + sku` |

### 0.3 非目标（首版明确不做或延后）

- 自研完整支付清算（首版可对接 Stripe / 人工开票）  
- 与 GCP 账单「单次请求」实时 1:1 金额一致（仅近似 + 月末对账）  
- 所有历史请求回填精确 token（无 `usageMetadata` 的旧数据只估或标 `estimated`）  
- 组织级多租户 SSO 计费拆分（可先账号级，预留 `orgId`）

### 0.4 与官方计费后台的关系

| 层级 | 职责 | 对齐方式 |
|------|------|----------|
| **实时** | 上游响应 `usageMetadata` / 任务创建回执 | 按官方计量写用户账本 |
| **价目** | Price Catalog | 定期同步官方公示价 + 内部 markup |
| **对账** | Billing Export / 商户后台 CSV | 按 SKU + 日期汇总，与用户账本 ± 误差带比对 |
| **用户发票** | 你们系统 | 基于用户账本 + 套餐规则，**不**直接暴露 GCP 账单 |

## 1. 现状盘点（As-Is）

| 能力 | 已有实现 | 缺口 |
|------|----------|------|
| 试用 Gemini | `trial-gemini` 按日 **次数**；访客 localStorage | 无 token / 美元；与 `userId` 弱绑定（访客） |
| 公平队列 | `costWeight` 排队 | 非计费 |
| 云存储 | `workspace-storage-usage` 字节账本 + 配额 | 模式可复用；与 AI 未打通 |
| 工作流审计 | `workflowAuditEvents`、时间线 | R3.5 未接 `usage_events` |
| Gemini 代理 | 返回 `text/candidates` | **未透传** `usageMetadata` |
| Tripo 3D | 建任务 vs 查状态已产品区分 | 未落 `usage_events` |
| 管理后台 | 用户配额、Dashboard、审计导出 | 无 AI 用量 Tab |
| 模型注册表 | 规划 `billingSku` | **未落地** |

**结论**：具备「配额型商业化」骨架；缺 **统一 usage 事件模型 + 价表 + 用户侧查询 + 成本对账**。

## 3. 目标架构（To-Be）

```
┌─────────────────────────────────────────────────────────────┐
│ 门面：用量卡片 / 账单页 / 工作流步骤「消耗」chip / Admin 报表   │
└───────────────────────────┬─────────────────────────────────┘
                            │ GET /api/usage/*
┌───────────────────────────▼─────────────────────────────────┐
│ 计费服务（auth-api 或独立 billing-api）                        │
│  - 准入：套餐余额 / 速率 / 硬顶                               │
│  - 记账：append usage_events（幂等）                          │
│  - 聚合：日/月 rollup                                          │
│  - 对账：import vendor_bills                                  │
└───────────────────────────┬─────────────────────────────────┘
                            │
        ┌───────────────────┼───────────────────┐
        ▼                   ▼                   ▼
  unifiedAiGateway    tripoService         videoBridge
  gemini-proxy        tencentService       capabilityExecutor
        │                   │                   │
        └───────────────────┴───────────────────┘
                            ▼
                    上游供货商 API
```

### 3.1 核心数据模型（建议 Postgres）

**`usage_events`**（append-only，真源）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | uuid | PK |
| `idempotency_key` | text unique | 幂等 |
| `user_id` | uuid | 扣费主体 |
| `workspace_id` | uuid nullable | 可选归因 |
| `project_id` | text nullable | 工作流项目 |
| `workflow_step_id` | text nullable | 步骤 |
| `audit_log_id` | uuid nullable | 关联审计 |
| `provider` | text | `vertex` / `gemini` / `tripo` / … |
| `registry_id` | text nullable | 站内模型 id |
| `billing_sku` | text | 价目键 |
| `meter_kind` | enum | `token` / `image` / `second` / `task` / `byte` |
| `quantity_in` | numeric nullable | 输入 token 等 |
| `quantity_out` | numeric nullable | 输出 token 等 |
| `quantity` | numeric | 主计量（张数/任务数/总 token） |
| `unit` | text | `token` / `image` / `task` / … |
| `cost_usd_est` | numeric nullable | 按价表估算 |
| `cost_confidence` | enum | `exact` / `estimated` / `unknown` |
| `status` | enum | `pending` / `succeeded` / `failed` / `refunded` |
| `upstream_task_id` | text nullable | Tripo / async job |
| `request_id` | text nullable | 链路追踪 |
| `meta_json` | jsonb | 模型名、分辨率、error 码等 |
| `created_at` | timestamptz | |

**`price_catalog`**（版本化）

| 字段 | 说明 |
|------|------|
| `billing_sku` | 与注册表一致 |
| `meter_kind` + 单价列 | 如 `input_per_1m`, `output_per_1m`, `per_task` |
| `vendor_sku_ref` | 对账用官方 SKU |
| `effective_from` | 生效时间 |
| `markup_pct` | 可选 |

**`user_plans` / `user_balances`**

- 套餐：`plan_id`, `included_credits`, `period_start/end`  
- 余额：`credits_remaining` 或 `usd_remaining`  
- 与现有 `workspaceQuotaBytes` **并行**（存储 ≠ AI）

**`usage_daily_rollups`**（查询加速）

- `user_id`, `day`, `billing_sku`, `sum_quantity`, `sum_cost_usd_est`

**`vendor_reconciliation`**（对账）

- 导入官方账单行 + `matched` / `variance_usd` / `notes`

### 3.2 API 契约（草案）

| 方法 | 路径 | 用途 |
|------|------|------|
| POST | `/api/usage/events` | 内部服务记账（HMAC / service token） |
| GET | `/api/usage/summary` | 用户：周期汇总 |
| GET | `/api/usage/events` | 用户：明细分页（脱敏） |
| GET | `/api/usage/projects/:id` | 项目级消耗 |
| GET | `/api/admin/usage/dashboard` | 运营：Top 用户 / SKU / 趋势 |
| GET | `/api/admin/usage/reconciliation` | 财务：对账状态 |
| POST | `/api/admin/price-catalog` | 运营：更新价目（RBAC） |
| POST | `/api/admin/users/:id/credits` | 手工加额 |

**准入钩子**（替代或增强 `trial-gemini/consume`）：

- `POST /api/usage/reserve` → `{ allowed, remaining, reservationId }`  
- 成功完成后 `commit`；失败 `release`（可选两阶段；v1 可简化为单阶段成功记账）

## 8. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 无 usageMetadata（旧 SDK/失败） | `cost_confidence=estimated`；价目表注明 |
| 重试双计 | 强制 `idempotencyKey`；审计重复告警 |
| 记账拖慢主路径 | 异步写入 + 本地队列补传 |
| 价目滞后亏本 | markup 安全垫 + 对账周报 |
| 访客绕过 | 设备指纹 + IP 限速；核心能力需登录 |
| 隐私合规 | 不存 prompt；导出脱敏 |
| 与试用逻辑冲突 | Phase 2 兼容期双写对比 |
