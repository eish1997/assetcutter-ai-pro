## 1. 产品形态与安装包

| 项 | **已决** | 曾考虑的选项 |
|----|----------|----------------|
| **安装包壳** | **首版安装包采用 Electron**，壳内托管/启动现有 **Node** 宿主（与当前 `local-companion` 协议一致）；**P0 验证期**仍可直接 `npm run dev` 跑 Node + 浏览器打开本机管理页 | Tauri、原生+WebView2 |
| **托盘 / 窗口** | **系统托盘必选**；**主窗口可选**（设置、状态、打开本机管理页、退出）；配对在 **桌面壳设置 → 与网站配对** | 仅窗口 |
| **开机自启** | **默认关闭**；仅在安装向导或伴侣设置中 **显式勾选** 并说明用途 | 默认开启 |
| **卸载与 Volume** | **默认保留**本机卷数据（`COMPANION_VOLUME_ROOT`）；卸载向导提供 **「同时删除本机仓库数据」** 可选勾选项 | 默认删卷 |
| **进程名与路径** | 主进程名 **`AssetCutterCompanion`**（可执行文件名 `AssetCutterCompanion.exe` 等）；**安装与用户数据路径使用英文**（如 `%LOCALAPPDATA%\AssetCutterCompanion\`）；**不把 Volume 默认放到 `Program Files`**（避免权限问题） | Program Files 写卷 |

## 2. 仓库与工程边界

| 项 | **已决** | 曾考虑的选项 |
|----|----------|----------------|
| **宿主与 Relay** | **中期**：以 **`local-companion` 为宿主**（HTTP + Storage + Compute）；**Relay（`local-bridge`）以子进程** 由宿主拉起并统一管理生命周期（托盘呈现为一个产品）；**长期**：代码合并为 **单进程单仓库**，短期接受开发期双进程 | 长期仅并行、立刻单进程 |
| **HTTP 端口** | **默认 `18765`**；与 `local-bridge` **勿同端口并行**；冲突时由 UI/文档引导改 **`COMPANION_HTTP_PORT`** | 端口段 |
| **monorepo** | **维持多仓现状** 至 Relay 合并方案落地；合并时 **一次性迁移**，避免反复拆合 | 立即合一仓 |

## 3. 网络、安全与跨域

| 项 | **已决** | 曾考虑的选项 |
|----|----------|----------------|
| **监听地址** | **默认仅 `127.0.0.1`**；若未来需局域网调试，单独 **「开发模式」开关**（非默认）+ 强警示 | 默认 `0.0.0.0` |
| **CORS / Origin** | **开发构建**：允许宽松（含 `*`）便于联调；**安装包正式版**：**Origin 白名单**（生产站域名 + `http://localhost:*` 等开发源）+ **配对 Token**（与总规范 §8、现有 **auth-api / bridge 设备会话** 对齐；细节由后端定稿，伴侣存 **短期可撤销 secret**） | 长期 `*` |
| **HTTPS 调本机失败** | **产品文案**统一提示：*「当前网络或安全策略可能阻止浏览器访问本机伴侣，请检查企业代理 / 防火墙或联系管理员」*；**技术增强**（反向代理等）列为 **P1** | 仅技术处理 |

## 4. 存储与资源模型

| 项 | **已决** | 曾考虑的选项 |
|----|----------|----------------|
| **`projectId`** | **与网站工作区 / 云端 `projectId` 尽量一致**（字符集落在伴侣 **安全 id** 规则内）；不一致时由 **主站显式传 `projectId`** | 伴侣内独立 UUID |
| **分块上传** | **P1** 再做 `POST /v1/storage/session`；**P0 仅用 PUT** 直至单文件上限（见本地程序开发文档） | P0 上分块 |
| **manifest 并发** | **P0：单进程单写者**（与现实现一致）；**P1：`If-Match` / etag** | 一上来分布式锁 |
| **catalog** | **P1+**：manifest 可查询稳定后再做 **catalog / AssetHandle 索引** | P0 上 DB |

## 5. 计算与 Job

| 项 | **已决** | 曾考虑的选项 |
|----|----------|----------------|
| **进度** | **P0：短任务同步返回 + `GET /v1/compute/jobs/:id` 轮询**；**P1：`WS /v1/jobs/:id/stream`**（总规范 §5.3） | 仅 WS |

## 9. 执行优先级（已定，非再讨论）

1. **Electron 壳 + 托盘（M0）**：`companion-desktop/` + 根脚本 `companion-desktop:start`；托盘 **左键打开桌面窗口**；**与网站配对**在 **设置 → 与网站配对**（落盘 `pairing-config.json`）。宿主 **共享 Token** 由桌面壳设置页 + 主站设置 + `companionClient` 接通。  
2. ~~宿主侧实现 **子进程拉起 `local-bridge`** 与端口协商~~ → **进行中（2026-04-27）**：`local-companion` 已支持 **`COMPANION_RELAY_CMD` / `COMPANION_RELAY_CHILD_HTTP_PORT`**；Electron 托盘后再固化为默认安装行为。  
3. **安装包版** 收紧 **Origin + Token**：宿主已支持 **`COMPANION_ALLOWED_ORIGINS`**、**`COMPANION_SHARED_TOKEN`**（见 `local-companion/src/accessGate.ts`、本地程序开发 §3）；主站设置已存 Token 并由 **`companionClient`** 带 Bearer。**与 auth-api / bridge 设备会话对齐、可撤销密钥** 仍待后端联调。  
4. ~~**首个真实 Compute Adapter**（修缝链路）~~ → **进行中（2026-04-27）**：`seam_repair` 已转发 **WebSeamRepair `/api/repair`**（Volume 内 `objKey`/`textureKey`/`maskKey`）；**Relay M1**：主站 **`companionClient/relay.ts`** 读 **`capabilities.relay`**（WSS/单站点执行仍依 `local-bridge` 与后端）。  
5. ~~**`services/companionClient/`** 与 **`types/companion.ts`** 补齐~~ → **进行中（2026-04-27）**：已落地 `services/companionClient/*`（probe/storage/compute/**relay**、**`submitCompanionSeamRepairJob`**）、主站设置「拉取项目 id」+ **检测连接** 后展示 **Relay / 修缝** 摘要；`types/companion.ts` 占位已建，随 API 演进扩充。
6. **最终闭环优先（新增）**：以「网站可见完整自动化链路」为主线推进 M2：`task.accepted`→`reply.delta`→`reply.completed/failed`、断线续传、故障提示与可执行修复动作。
