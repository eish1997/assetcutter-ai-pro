## 1. 背景与目标

### 1.1 背景

当前桌面壳左侧导航为三页：**首页**、**工作台**（内嵌主站 `BrowserView`）、**设置**。本机能力主要通过：

- **本机引擎**（SamLocal / rembg / PaddleOCR 等）— 内置 Job，偏工作流算力；
- **扩展包**（`host_plugin_bundle`）— ZIP 落盘 + `run.json` probe/exec，偏管线与可选计算；
- **本机管理页**（`http://127.0.0.1:18765/`）— 运维调试，非产品向工具入口。

缺少面向普通用户的 **本机小工具集合**：例如「为指定路径批量转换图片格式」，开发完成后打成 **包**，由管理员在发行后台上传，用户 **无需重装 Electron 壳或本地伴侣安装包** 即可安装/更新。

### 1.2 目标

| 目标 | 说明 |
|------|------|
| **工具页** | 与首页 / 工作台 / 设置 **同级** 的第四壳内视图（`data-view="tools"`）。 |
| **可插拔** | 每个小工具以 **`shell_tool_bundle` ZIP** 交付；安装后出现在工具架。 |
| **热更新** | 通过管理后台登记新版本 → 本机 `install-from-url` → 刷新工具列表；**不必**重装 `companion-desktop`。 |
| **壳式 UI** | 带 UI 的工具 **不是** 独立网页或第五个 BrowserView；而是在 **统一工具壳框架** 内挂载 **壳模块**（与主壳 home/settings 同一产品范式）。 |
| **首版范围** | 仅 **`launch.kind: shell_module`**（声明式 `panel.json` + 包内 `run` 脚本）；`script` / `exe` / 独立子窗口为后续扩展。 |

### 1.3 非目标（首版）

- 在工具页内嵌远程主站或任意第三方 URL（与工作台职责分离）。
- 每个工具自带完整 HTML / `handlers.mjs` 注入 DOM（避免「小网站」与 XSS 面）。
- 包内任意 JavaScript 由壳动态加载执行（首版 **否决**；见 §5.3、§7）。
- 与工作流 `host_bundle.exec` 能力预设自动打通（Phase 2+ 再议）。
- 工具市场浏览、评分、付费（**用户自建上架走审批**，不是开放市场评分）。
- `run` 异步 Job 队列（首版 **同步** spawn + 超时；Phase 2 再接 `compute/jobs`）。

> **2026-07-29 增补**：全员可通过 Copilot / 工具架「新建」创建与管理员同规格的 `shell_tool_bundle`（草稿在 `shell-tools-authored/`，开发态保存即热重载）；仅本人本机可见；可导出/导入 ZIP；提交审批后管理员在 `/admin/shell-tool-submissions` 通过，进入公开 catalog。见 `local-companion/src/shellToolAuthored.ts`、`ac.shell_tool.scaffold|authored_upsert|export|import`。

## 2. 概念与术语

| 术语 | 含义 | 与现有概念关系 |
|------|------|----------------|
| **工具页** | 壳内 `#view-tools`，含工具架与模块详情两级视图 | 对标 `#view-home` / `#view-settings` |
| **工具架** | 工具页默认态：已安装工具卡片网格、更新提示、安装入口 | 非独立进程 |
| **壳模块** | 包内 `module/panel.json` 描述的 UI + 动作，由 **统一模块渲染器** 绘制 | **≠ 网页**；≠ `host_plugin_bundle` 的 compute 语义 |
| **小工具包** | `shell_tool_bundle` ZIP，落盘 `{volume}/shell-tools/<toolId>/` | 安装管道与 `host_plugin_bundle` **共用核心**（§4.2） |
| **工具壳运行时** | 模块渲染器 + bridge API + 主题/布局（壳内 `tools-module.js`；数据来自伴侣 HTTP） | 一次性基建 |
| **扩展包** | 现有 `host_plugin_bundle`，工作流 probe/exec | 职责不同，**不混目录** |

产品侧一句话：

> **扩展包** = 本机算力/管线（可选）；**小工具包** = 用户在本机随手用的工具（工具页入口）。

## 3. 用户交互

### 3.1 导航（已决）

左侧 `nav.shell-sidebar` 条目顺序 **固定**：

**首页** → **工作台** → **工具** → **设置**

- 图标：工具箱 / 扳手类 SVG；保留 `aria-label` / `title="工具"`。
- `applyShellView('tools')` 时 **detach 工作台 BrowserView**（与 home/settings 一致）。

### 3.2 工具页内两级结构

```
#view-tools
├── [工具架] tools-rack          ← 默认
│     ├── 已安装工具卡片（图标、名称、版本、简介）
│     ├── 「检查更新」/ 可更新角标
│     └── 「从发行目录安装…」（拉 catalog 中 shell_tool_bundle）
└── [模块视图] tools-module      ← 点击某工具后
      ├── 顶栏：返回工具架、工具名、版本
      └── 内容区：统一渲染器根据 panel.json 绘制（白名单控件，§5.3）
```

- **返回**：顶栏或 Esc 回到工具架，不清除已安装包。
- **首版不做** 独立 `BrowserWindow`；后续可新增 `launch.kind: shell_window`（见 §8.4）。

### 3.3 与首页「扩展包」区关系

| 入口 | 对象 | 用户 |
|------|------|------|
| 首页 · 扩展包 | `host_plugin_bundle` | 进阶 / 工作流 |
| 工具页 | `shell_tool_bundle` | 日常小工具 |

设置 → 本地伴侣 可保留 **高级区** 安装小工具包（与扩展包并列），但 **主入口在工具页**。

### 4.1 分层更新边界

| 变更类型 | 是否需重装 Electron 壳 |
|----------|------------------------|
| 新小工具包 / 包升级 | **否** |
| 伴侣 API / 安装逻辑 / `bundleInstallCore` | **否**（重启 Node 伴侣进程） |
| `panel.schemaVersion` 升级（新控件类型） | **是**（渲染器在壳内，须发壳） |
| 新增 IPC 能力（如新 permission） | **是**（扩展 preload 一次） |
| 工具页侧栏入口 | **是**（一次性） |

### 4.2 共用安装核心（已决）

**禁止** `shellToolBundles.ts` 与 `hostPluginBundles.ts` 各写一套下载/校验逻辑。抽取：

| 模块 | 职责 |
|------|------|
| `local-companion/src/bundleInstallCore.ts` | https 白名单、流式下载、sha256/bytes 校验、ZIP 魔数、zip-slip 解压到 **调用方指定 staging 目录** |
| `hostPluginBundles.ts` | 目标路径 `host-bundles/<semverDir>/`；写 `host_plugin_bundle` manifest |
| `shellToolBundles.ts` | 目标路径 `shell-tools/<toolId>/`；写 `shell_tool_bundle` manifest；**staging 原子切换**（§5.5） |

单测：`tests/bundleInstallCore.test.ts` 覆盖 zip-slip、checksum 失败、staging 未提交不影响旧版。

## 5. 小工具包契约

### 5.1 包布局（ZIP）

安装后目录（`toolId` = `tool.json.id`，与落盘目录名一致）：

```
shell-tools/
└── image-format-converter/
    ├── manifest.json       # 安装器写入：kind、semver、sha256、installedAt…
    ├── bundle.bin          # 原始 ZIP 归档
    └── extracted/          # 当前活跃版本
        ├── tool.json
        ├── module/panel.json
        ├── scripts/convert.mjs
        └── assets/icon.png
```

升级失败或回滚时可能存在（仅保留 **一份**）：

```
└── extracted.bak/          # 上一次成功版本的拷贝
```

**禁止**在包内放置供壳动态加载的 `.html`、浏览器可执行 `.js`（`scripts/` 下脚本仅由宿主 **spawn** 执行，不由渲染进程 `import`）。

### 5.2 `tool.json`（ToolSpec v1）

```json
{
  "schemaVersion": 1,
  "id": "image-format-converter",
  "name": "图片格式转换",
  "description": "为指定文件夹内图片批量转换格式",
  "semver": "1.0.0",
  "icon": "assets/icon.png",
  "launch": {
    "kind": "shell_module",
    "module": "module/panel.json"
  },
  "run": {
    "command": ["node", "scripts/convert.mjs"],
    "cwd": ".",
    "paramsMode": "env",
    "timeoutMs": 600000
  },
  "permissions": ["path.pick", "tool.run"],
  "minCompanionSemver": "0.1.0"
}
```

| 字段 | 必需 | 说明 |
|------|------|------|
| `schemaVersion` | 是 | 固定 `1`（ToolSpec 主版本） |
| `id` | 是 | `^[a-z][a-z0-9-]{1,63}$`；与落盘目录名一致 |
| `name` / `description` | 是 | 工具架展示 |
| `semver` | 是 | 与发行记录对齐 |
| `launch.kind` | 是 | 首版仅 `shell_module` |
| `launch.module` | 是 | 相对 `extracted/` 的 panel 路径 |
| `run` | 否 | 有 `run` 动作时必需；见 §5.4 |
| `run.paramsMode` | 有 run 时 | 首版 **仅允许** `"env"`；缺省视为 `"env"` |
| `permissions` | 是 | bridge 白名单，见 §7 |
| `minCompanionSemver` | 否 | 不满足时工具架显示「需要更新伴侣」 |
| `requires.localEngines` | 否 | **Phase 2+**；如 `["rembg"]`，工具架展示依赖未就绪 |

JSON Schema：`local-companion/schemas/tool.schema.json`（CI + `npm run validate:shell-tools` 校验样例包）。

### 5.3 `panel.json`（PanelSpec v1）

声明式 UI，由壳内 **`shell/tools-module.js`** 解释。**非自由 HTML**；未知 `type` / `kind` **拒绝渲染** 并显示错误条（不静默忽略）。

```json
{
  "schemaVersion": 1,
  "title": "图片格式转换",
  "sections": [
    {
      "id": "input",
      "fields": [
        {
          "type": "path",
          "id": "sourceDir",
          "label": "图片文件夹",
          "pick": "directory",
          "required": true
        },
        {
          "type": "select",
          "id": "format",
          "label": "目标格式",
          "options": [
            { "value": "webp", "label": "WebP" },
            { "value": "png", "label": "PNG" },
            { "value": "jpg", "label": "JPEG" }
          ],
          "default": "webp"
        }
      ]
    }
  ],
  "actions": [
    {
      "id": "convert",
      "label": "开始转换",
      "kind": "run",
      "style": "primary"
    }
  ],
  "outputs": [
    { "type": "log", "id": "runLog", "label": "运行日志" }
  ]
}
```

#### `panel.schemaVersion` 演进规则（已决）

| 变更 | 处理方式 |
|------|----------|
| 新增 `field.type` / `action.kind` | **递增** `panel.schemaVersion`；壳渲染器须发版支持 |
| 仅文案、字段顺序调整 | 保持 `schemaVersion` 不变 |
| 壳版本过旧无法识别 schema | 模块视图显示「需要更新桌面伴侣」 |

#### 首版白名单：`field.type`

| type | 说明 |
|------|------|
| `path` | IPC `pickPath`；`pick`: `directory` \| `file` |
| `select` | 自定义下拉（**禁止**原生 `<select>`，与项目 UI 规范一致） |
| `text` | 单行文本 |
| `toggle` | 布尔开关 |

#### 首版白名单：`action.kind`

| kind | 行为 |
|------|------|
| `run` | 表单值 → `POST /v1/shell-tools/:id/run`（仅 `actionId` + `params`） |
| `openPath` | 打开已选路径（需 `path.pick`） |

#### 首版白名单：`outputs[].type`

| type | 说明 |
|------|------|
| `log` | 追加 `run` 返回的 stdout/stderr 文本 |

**首版否决**：包内 `handlers.mjs`、自定义组件、内联 HTML。复杂交互留 Phase 2，须单独立项与 ADR（见 §15）。

JSON Schema：`local-companion/schemas/panel.schema.json`。

### 5.4 `run`：请求体与 params 注入（已决）

#### HTTP 请求体

`POST /v1/shell-tools/:id/run`：

```json
{
  "actionId": "convert",
  "params": {
    "sourceDir": "D:\\exports\\shots",
    "format": "webp"
  }
}
```

请求体中的 `command`、额外 env、shell 元字符 **一律忽略**。

#### paramsMode（v1 仅 env）

| 模式 | 首版 | 说明 |
|------|------|------|
| `env` | **支持（默认）** | 每个 param 写入 `TOOL_PARAM_<UPPER_SNAKE>` |
| `params-file` | **v1.1 规划** | 宿主写临时 JSON，追加 `--params-file`；首版不实现，避免脚本接口分裂 |

环境变量命名：`sourceDir` → `TOOL_PARAM_SOURCE_DIR`（非字母数字 → `_`，连续 `_` 合并，大写）。

#### 执行语义（首版）

- **同步**：HTTP 请求阻塞至子进程结束或超时。
- 返回：`{ ok, exitCode, stdout, stderr }`（stdout/stderr 各截断 64KB）。
- 超时：默认 600s；`run.timeoutMs` 可覆盖，上限 3600s。
- Phase 2：超过 60s 的任务可改提交 `compute/jobs`，响应 `{ jobId }`（非首版）。

### 5.5 安装与升级：staging 原子切换（已决）

同 `toolId` 升级 **必须** 遵循下列顺序；任一步失败 **不得** 破坏当前 `extracted/`：

```
1. 下载 → 校验 sha256/bytes
2. 解压到 shell-tools/<toolId>/.staging/<uuid>/extracted/
3. 校验 .staging 内 tool.json（schema + id 与目标一致）
4. 校验 panel.json（schema + 白名单 type）
5. 若已有 extracted/：mv extracted → extracted.bak（删除旧 .bak）
6. mv .staging/.../extracted → extracted/
7. 写 manifest.json（kind、semver、installedAt…）
8. 删除 .staging；删除 extracted.bak（仅保留一轮备份，磁盘占用可控）
```

| 场景 | 行为 |
|------|------|
| 步骤 3–4 失败 | 删除 `.staging`，保留旧 `extracted/` |
| 步骤 6 失败 | 若有 `extracted.bak`，尝试 `mv extracted.bak → extracted` 回滚 |
| 全新安装 | 无步骤 5；直接步骤 6 |

## 6. HTTP API（local-companion）

Bearer 与 CORS 规则与现有 `/v1/*` 一致（见 `accessGate.ts`）。

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/v1/shell-tools` | `{ tools: ToolSummary[] }` |
| `GET` | `/v1/shell-tools/:id` | 详情 + 解析后 `panel` + `permissions` |
| `POST` | `/v1/shell-tools/install-from-url` | Body：`{ url, semver, sha256, bytes, label? }`；走 §5.5 |
| `POST` | `/v1/shell-tools/:id/run` | 同步 run，见 §5.4 |
| `DELETE` | `/v1/shell-tools/:id` | 卸载整个 `<toolId>` 目录（P4） |

`GET /v1/capabilities` 可选追加 `shellTools: { installedCount }`。

### 6.1 错误码（已决）

HTTP 响应体统一：`{ error: string, message?: string, detail?: string }`。

| `error` | HTTP | 说明 |
|---------|------|------|
| `tool_not_found` | 404 | 未安装该 id |
| `tool_invalid_manifest` | 422 | tool.json / panel 校验失败 |
| `permission_denied` | 403 | 缺少 permission 或 action 未授权 |
| `install_checksum_mismatch` | 400 | sha256 或 bytes 不符 |
| `install_staging_failed` | 500 | staging 流程失败（旧版应仍在） |
| `run_not_configured` | 422 | 工具无 `run` 段 |
| `run_timeout` | 504 | 子进程超时 |
| `run_failed` | 200 | `ok: false` + exitCode（业务失败非 HTTP 错） |
| `invalid_params` | 400 | 缺必填 param 或路径非法 |

### 6.2 与 `host_plugin_bundle` 差异

| 项 | host_plugin_bundle | shell_tool_bundle |
|----|--------------------|-------------------|
| 落盘目录 | `host-bundles/<semverDir>/` | `shell-tools/<toolId>/` |
| 目录命名 | semver 消毒名 | **tool.json.id** |
| 多版本 | 多目录并存 | **同 id 覆盖**（staging + `.bak`） |
| 安装核心 | `bundleInstallCore.ts` | 同上 |

## 7. 安全

| 规则 | 实现要点 |
|------|----------|
| 下载源 | 仅 https + R2 域 / `COMPANION_HOST_BUNDLE_TRUST_HOSTS` |
| 完整性 | sha256 + bytes |
| 命令注入 | `run.command` 仅来自磁盘 `tool.json` |
| params 注入 | 仅 `paramsMode: env`；禁止拼接 shell 字符串 |
| 路径 | `pickPath` 经壳 IPC；宿主校验存在；拒绝 `..` |
| 权限 | 未声明 `permissions` → IPC/API 403 |
| zip-slip | `bundleInstallCore` 统一防护 |
| XSS | **禁止**包内 HTML/壳侧动态 `eval`；UI 仅 JSON panel 白名单渲染 |
| 日志隐私 | 安装/运行错误写本地 `local-companion` 日志；**不上传**用户路径到云端 |
| 输出截断 | stdout/stderr 各 64KB |

### 7.1 首版 `permissions` 枚举

| permission | 能力 |
|------------|------|
| `path.pick` | 壳 `dialog.showOpenDialog` |
| `tool.run` | `POST .../run` |
| `host.open` | `POST .../open-in-host`（注入已开 DCC；首版 Maya Command Port） |

Maya 类工具契约与用法见 **[本地伴侣-Maya工具页注入.md](./本地伴侣-Maya工具页注入.md)**。

Phase 2+：`companion.storage.read`、`shell.notify`。

## 8. 发行（auth-api + 管理后台）

### 8.1 artifact kind

`companion_artifacts.kind = **shell_tool_bundle**`：

- 平台：`universal` / `all`
- 渠道：`stable` / `beta`

## 11. 示例：图片格式转换包

### 11.1 用户路径

1. 侧栏 **工具** → **图片格式转换**
2. 选择文件夹、目标格式 **WebP** → **开始转换**
3. 日志区输出进度 → 完成

### 11.2 开发者路径

1. 编写 `tool.json` + `module/panel.json` + `scripts/convert.mjs`
2. `npm run validate:shell-tools` 通过 schema
3. `npm run pack:shell-tool -- <目录名>` 打 ZIP → 仓库根 **`dist-out-shell-tools/<id>-<semver>.zip`**（统一发行落盘，不入库）
4. 管理后台登记 `shell_tool_bundle` `1.0.0`
5. 用户工具页安装（无需重装壳）

### 11.3 依赖策略（已决）

| 优先级 | 方案 |
|--------|------|
| **推荐** | 包内 **纯 Node**（如 `sharp` 打进 `scripts/` 依赖或 bundle `node_modules`） |
| 备选 | 调用已安装 **本机引擎**（Phase 2 `requires.localEngines`） |
| **不推荐首版** | 依赖用户本机 ImageMagick / 任意 PATH 二进制（不可复现） |

`convert.mjs` 仅通过 `process.env.TOOL_PARAM_*` 读参；进度 `console.log` 进 `log` 输出区。
