# 架构未收口清单

**创建日期**：2026-07-16
**用途**：集中记录“架构方向已经定了，但实现还没有完全闭环”的事项，避免多轮改造后遗忘。
**维护原则**：这里只登记已经形成架构口径、但仍未完全闭环的事项。完成闭环后应从本清单移出，验收证据同步到对应设计文档或 `docs/交接文档.md`。

## 状态口径

| 状态 | 含义 |
|---|---|
| `open` | 架构已定，尚未开始或只做了文档 |
| `in_progress` | 已有部分实现，但还不能宣称闭环 |
| `blocked` | 需要外部条件，例如 Key、上游能力、产品拍板 |

## 维护规则

- 不在这里写完整方案，完整方案仍放在对应设计文档；这里写“别忘了收口”的索引。
- 每条必须有：状态、已定架构、未收口点、下一步、关联文档/代码。
- 如果某个入口在 `services/workflowAiPickIndex.ts` 里是 `partial_gateway` 或 `legacy`，这里必须有对应条目。
- 如果某个供应商或模型在管理端可见，但不能“接 Key 后发布并执行”，这里必须有对应条目。
- 如果某个 UI/资产体验已经定了产品化原则，但实现仍靠补丁式分支，也必须登记。
- 已完成事项不留在本清单里占位；如果首版已完成但仍有缺口，只记录剩余未收口点，状态保持 `in_progress`。
