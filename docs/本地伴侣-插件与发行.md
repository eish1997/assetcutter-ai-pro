# 本地伴侣：插件能力 vs 发行资产

为减少「插件 / 宿主包 / SamLocal / rembg」混名，产品侧统一两套说法：

| 说法 | 是什么 | 典型入口 | 与网站工作流的关系 |
|------|--------|----------|---------------------|
| **本机引擎** | 伴侣 **内置计算 Job** 所需的**本机进程与环境**（如 `sam_segment` → SamLocal HTTP；`remove_bg` → Python rembg） | **桌面伴侣 → 设置 → 本机引擎**（一键安装或手动配置）；网站「设置 → 本地伴侣」做探测与说明 | **大图本机分割、去背景**默认只依赖本机引擎 |
| **扩展包** | 主站登记的 **`host_plugin_bundle`** ZIP，解压到 `host-bundles/`，在能力表里以 **`plugin.host_bundle.<dirName>`** 出现 | 桌面伴侣首页「扩展包」、网站「设置 → 本地伴侣」高级区、工作流里可选的 host_bundle 能力 | **可选**；用于 ZIP 交付、probe/exec 管线等，**不是**分割/去背景的默认前置 |

技术细节仍以本文后续章节与 `docs/本地伴侣-本地程序开发.md` 为准；**Windows 沙盒物理布局**见 **`docs/本地伴侣-沙盒目录.md`**。

## 1. 概念对照

| 名称 | 含义 | 典型形态 | 更新是否要重装桌面壳 |
|------|------|----------|----------------------|
| **运行时插件 / 能力** | `local-companion` 在 `/v1/capabilities` 宣告的服务（存储、计算、后续如 Segment Anything 子进程等） | 由宿主进程加载或子进程提供 | **不必**。由宿主拉取插件包、重启 **Node 伴侣进程** 即可；Electron 仅负责托盘与拉起宿主。 |
| **桌面壳（Electron）** | `companion-desktop` 安装包 / 便携 exe | `.exe`、NSIS、portable | **需要新壳** 仅当改了 Electron 层（托盘、IPC、向导、自动更新逻辑等）。 |
| **扩展包 / 宿主插件包（`host_plugin_bundle`）** | 预置给 `local-companion` 解压加载的 ZIP/目录（含 Python 环境、模型权重等）；用户可见名称以 **扩展包** 为主 | 大体积 artifact | **不必**重装壳；登记为 `host_plugin_bundle`，由宿主侧更新与校验（规划：下载至 volume、manifest、重启宿主）。 |

**Segment Anything 等开源能力**：建议作为 **宿主侧子进程或独立 runtime 目录**，由 `local-companion` 配置路径与健康检查；更新走 **host_plugin_bundle** 或专用拉取管道，与 **桌面壳安装包** 分离。

## 2. 主站「发行」功能（已实现骨架）

- **管理后台**：`/admin/companion-artifacts`（**本地伴侣发行**）— 管理员预签名上传至 R2 前缀 `public/companion-distribution/`，登记 `semver`、平台、渠道、`sha256` 等；上传时浏览器会同时计算 **`sha512`（hex）** 并写入登记（可选用于 **electron-updater** 的 `latest.yml`）。**平台**可选 **`universal` / `all`**：一条记录对所有 `win32` / `darwin` / `linux` 请求可见；**`GET …/latest`** 在同时存在「当前平台精确条目」与「全平台条目」时**优先精确平台**（再按发布时间）。
- **删除**：`DELETE /api/admin/companion-artifacts/:id` 在 R2 已配置时**先删对象再删元数据**；若 R2 删除失败则整笔不删并返回 502。
- **元数据存储**：若进程配置了 **`DATABASE_URL`**（如 Render 上的 auth-api），则存 **Postgres 表 `companion_artifacts`**，避免每次部署清空临时磁盘导致「全站看不到已发布安装包」。未配置时回退为 **`server/data/companion-artifacts.json`**（本地开发常见；首条登记时自动创建）。
- **公开摘要**：含 `sha256`、`bytes`，供本机宿主安装时做完整性校验。
- **用户下载桌面壳**：登录用户在工作区侧栏底部「伴侣」区域可下载 **`desktop_shell`** 最新 **stable** 包（按浏览器推断 `win32` / `darwin` / `linux`）。
- **宿主插件包落盘（local-companion）**：
  - `GET /v1/host-plugins/bundles` — 已安装列表（`manifest` + `bundlePath` 等）；若存在 **`extracted/run.json`** 且解析成功，每条带 **`runSpec`**（`schemaVersion: 1` 与 `probe`/`exec` 等，见下文 **§4**）。
  - `POST /v1/host-plugins/install-from-url` — Body：`{ url, semver, sha256, bytes, label? }`；从 **https** URL 流式下载、校验大小与 SHA256，写入卷内。URL 主机须为 `*.r2.cloudflarestorage.com` / `*.r2.dev`，或在环境变量 **`COMPANION_HOST_BUNDLE_TRUST_HOSTS`**（逗号分隔）中追加；体积上限默认 512MB，可用 **`COMPANION_HOST_BUNDLE_MAX_BYTES`** 调整。响应含 **`runSpec`**（安装后即时解析）。
  - **主站设置 → 本地伴侣**：「安装最新扩展包到本机」调用 **`services/hostPluginBundleClient.ts`**：若 **`GET /api/companion-artifacts/latest`** 返回的摘要含 **`publicInstallUrl`**（见上文 catalog 规则），则**直接使用直链**调伴侣 `install-from-url`，**无需** `resolve-download`；否则串联预签名（**需登录**）。同区块提供 **刷新已安装包列表**、下拉选择包、**运行 probe/exec**（调用 **`POST /v1/compute/jobs`**，类型 **`host_bundle.probe` / `host_bundle.exec`**），并把 **`jobId` 填入「任务进度」** 以便 SSE/轮询（见 **`docs/本地伴侣-本地程序开发.md`** §3 / §4.1）。**`services/companionClient/hostPlugins.ts`**、`compute.ts` 封装对应 HTTP。
- **API**（auth-api，需已配置 R2）：
  - `GET /api/companion-artifacts/catalog` — 公开摘要列表；当服务端配置 **`COMPANION_DIST_PUBLIC_HTTP_BASE`** 时，`kind=host_plugin_bundle` 的条目额外包含 **`publicInstallUrl`**（与 electron-updater 同源拼接规则），供 **桌面壳首页「扩展包」** 免登录一键调伴侣 **`install-from-url`**；自定义公网域名时本机伴侣须 **`COMPANION_HOST_BUNDLE_TRUST_HOSTS`** 放行该主机。
  - `GET /api/companion-artifacts/latest?kind=&platform=&channel=` — 最新一条摘要；
  - `POST /api/companion-artifacts/resolve-download` — 需登录，返回短时 GET 预签名 URL；跨域静态站与 **`/api/r2` 相同**不在此路径做双端 CSRF 头校验（依赖白名单 `Origin` + 会话 Cookie）。
  - **`GET /api/companion-artifacts/electron-updater/{platform}/{channel}/latest.yml`** — **Path A**（桌面壳 **electron-updater** generic 默认 feed）；`platform` 如 `win32` / `darwin` / `linux`，`channel` 如 `stable`；`kind` 固定为 **`desktop_shell`**；
  - **`GET /api/companion-artifacts/electron-app-update.yml`** — **legacy**：查询参数与 **`latest`** 一致（`kind` / `platform` / `channel`），返回同构 YAML；服务端须配置 **`COMPANION_DIST_PUBLIC_HTTP_BASE`**（或回退 **`R2_PUBLIC_BASE_URL`**，公网可读前缀无尾斜杠），与 **`r2Key`** 拼接下载 URL；YAML 内 **`sha512`** 为 **Base64**（由登记 hex 转换），见 **`server/companion-electron-feed.js`**；
  - 管理端：`GET/POST/DELETE /api/admin/companion-artifacts`、`POST /api/admin/companion-artifacts/upload-url`。

## 3. 安全与运维注意

- 对象键必须为 `public/companion-distribution/` 前缀；下载仅在**登记记录存在**时服务端代签 URL，避免任意 key 泄露。
- 管理端删除发行记录时，若 R2 已配置，会**同步删除对象**后再删元数据（失败则保留元数据并返回错误）。
- 大文件注意 R2 出站流量与浏览器超时；后续可接 **CDN / 分块 / 壳内 updater**（`COMPANION_UPDATE_FEED_URL` 见 `companion-desktop/README.md`）。

## 4. `run.json` 与计算接入（已实现）

- **`host_plugin_bundle` + ZIP**：若 `bundle.bin` 为 ZIP（魔数检测），安装后自动解压到 **`extracted/`**，`manifest.json` 记 `bundleFormat: zip`、`extractedRelativeDir: "extracted"`（实现见 **`local-companion/src/hostPluginBundles.ts`**，**zip-slip** 防护）。
- **`extracted/run.json`（RunSpec v1）**：**`schemaVersion: 1`**；可选 **`description`**；**`cwd`** 相对 extracted 根；**`probe` / `exec`** 各含 **`command: string[]`**，可选 **`cwd`**、**`env`**（值须为字符串）。解析见 **`local-companion/src/hostBundleRunSpec.ts`**。
- **计算任务**：**`host_bundle.probe`** / **`host_bundle.exec`** 仅接受 **`inputs: { dirName }`**（与 `host-bundles` 下目录名一致）；**命令行不得来自浏览器请求体**，仅来自磁盘 **`run.json`**。适配器 **`host_bundle@v0.1.0`**，超时 **`COMPANION_HOST_BUNDLE_EXEC_TIMEOUT_MS`**。详见 **`docs/本地伴侣-本地程序开发.md`** §3、§4.1 与 **`docs/本地伴侣-存储与计算规范.md`** §5。
- **`/v1/capabilities`**：除静态插件表外，动态追加 **`plugin.host_bundle.<目录名>`**；`detail` 会提示是否已解析 **run.json**、是否含 **exec/probe**。
- **electron-updater**：登记 **`sha512`（hex）** 后，**`electron-app-update.yml`** 与桌面壳 **`COMPANION_UPDATE_FEED_URL`**（`electron-builder` generic）可共用同源版本元数据；公网基址 **`COMPANION_DIST_PUBLIC_HTTP_BASE`** 须与实际上传对象的可读 URL 一致。

**桌面壳自动更新（安装包）**：打包时设置 **`COMPANION_BUILD_AUTH_API_ORIGIN`** 写入 `build-constants.json`；安装后 **electron-updater** 默认从 Path A **`…/electron-updater/{platform}/stable/latest.yml`** 检查更新，**后台下载**，首页进度条 + 托盘 **「安装更新并重启」**；登记 NSIS 时建议同时上传 **`.blockmap`**（`blockMapSize` 写入 YAML，blockmap 文件须与安装包同目录公网可读，通常为 `{exeUrl}.blockmap`）。未配置更新源时，仍按 auth-api / 设置中的 **`latest`** 轮询（约 45s 后首次，每 4h），仅气泡提示去主站下载。部署后运行 **`npm run companion-desktop:verify-update-pipeline`**。

## 5. SamLocal 与本机分割（发行侧说明）

- **当前默认**：桌面壳 / `local-companion` **NSIS 包不捆绑** Python 与 SamLocal；有仓库源码时优先 **`npm run setup:sam-local`**（见 **`docs/本机分割一键安装指南.md`**），其余按 **`docs/本机分割故障排除.md`**；开发期可用仓库根 **`npm run dev:companion-sam-stack`**（伴侣随启 `dev:sam-local`）。
- **定制安装器 / 企业部署**：若将 SamLocal 装到固定目录，可在 **系统环境变量** 或 **快捷方式目标进程** 上为 **桌面壳** 或 **单独启动的伴侣** 设置：
  - **`COMPANION_SPAWN_SAM_LOCAL_CMD`**：例如 `npm run dev:sam-local`（需 **`COMPANION_SPAWN_SAM_LOCAL_CWD`** 指向 monorepo 根），或 `"<Python>\\python.exe" -m uvicorn app.main:app --host 127.0.0.1 --port 18081`（此时 **`COMPANION_SPAWN_SAM_LOCAL_CWD`** 指向 `SamLocal` 目录）。
  - 与 **`COMPANION_RELAY_CMD`** 相同：**由伴侣子进程 shell 执行**，字符串需在本机可解析。
- **长期**：大体积 PyTorch / 权重建议走 **§1 宿主插件包（`host_plugin_bundle`）** 落盘与更新，避免把推理运行时塞进 **Electron NSIS** 主包。
- **SamLocal 骨架**：仓库 **`SamLocal/host-plugin-bundle/`**（`extracted/run.json` 仅 **`probe`**）；打包 **`npm run pack:sam-local-bundle`** → **`SamLocal-release/sam-local-host-bundle-<version>.zip`**（已 `.gitignore`）。**不**用 **`host_bundle.exec`** 常驻 `uvicorn`，见该目录 README。
- **Windows 一键安装（桌面壳）**：大依赖落在 **`%LOCALAPPDATA%\AssetCutterCompanion\sandbox\runtimes\<runtimeId>\<version>\`**（嵌入 Python + pip 安装的 PyTorch 等）；**`…\sandbox\desktop-shell\sam-local-runtime\`** 仅保留 **薄 `sam-app`**、权重、`start-sam-local.cmd`、`state.json`。同一 `runtimeId@version` 可被后续其它插件复用。实现见 **`companion-desktop/sam-local-bootstrap/sam-local-bootstrap.cjs`**；沙盒总览见 **`docs/本地伴侣-沙盒目录.md`**；`runtimes\…\manifest.json` 记录 **`samRequirementsFingerprint`**，依赖未变时跳过重复 pip。

## 6. 共享宿主运行时（约定）

面向「多个后续插件可能共用 Python / PyTorch」的落盘方式，与 **§1 宿主插件包** 互补：插件包尽量 **薄**（业务与专用 wheel），**重运行时**按条固定 artifact 安装到本机 **共享目录**，多条插件声明依赖同一 **`runtimeId@semver`** 时 **只保留一份物理拷贝**。

| 字段 / 路径 | 说明 |
|-------------|------|
| **`runtimeId`** | 稳定字符串，例如 `py311-sam-torch-cpu-win-amd64`（平台与档位编码进 id，避免误用） |
| **`runtimeVersion`** | 同 id 下大版本，升级 Python 或整体 torch 档位时递增，对应新子目录 |
| **本机根路径** | `%LOCALAPPDATA%\AssetCutterCompanion\sandbox\runtimes\<runtimeId>\<runtimeVersion>\` |
| **`manifest.json`** | 位于该目录下；至少含 **`schemaVersion`**、**`samRequirementsFingerprint`**（或泛化为 **`requirementsFingerprint`**）与安装时间，供安装器判断 **是否跳过 pip** |
| **薄应用目录** | 仍由各功能独占（如 SamLocal 的 **`sandbox\desktop-shell\sam-local-runtime\sam-app`**），启动脚本将 **`PATH`** 指向前述共享 **`python\`** |

**演进**：后续插件可在自身安装脚本或 `host_plugin_bundle` 的 post-install 中检测 **`manifest.json` + fingerprint**；若已满足则只解压自身代码。从 R2 拉取 **预打好的 runtime zip** 与当前「壳内 bootstrap」可并存：先解压 runtime，再跑薄包。

## 7. 后续可演进

- **工作流一键触发 `host_bundle.exec` / `host_bundle.probe`（已实现）**：能力预设可选字段 **`companionHostBundle`**（`dirName`、可选 `phase`）；`executeCapability` 在 **`services/capabilityExecutor.ts`** 内向本机伴侣 **`POST /v1/compute/jobs`**；工作区队列与能力集合执行时附带 **`companionProjectId`**（当前工作区项目 id）。配置入口：**能力预设** 编辑区「本机伴侣 · 宿主包」；拖入图片或文字卡均可触发（见 **`workflowAssetAllowedForCapabilityDrop`**）。若集合末级为纯 **`host_bundle`** 文字节点且无下游生图，**输出节点**可能缺少图像输入，需自行构图。
- 更强隔离：宿主包子进程 **资源上限**、**并发队列**。
