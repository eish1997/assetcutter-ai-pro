# 本地伴侣 · 本机能力用户体验与产品化路线图

本文将「体验优先、产品化」的讨论沉淀为**可执行规格**：面向产品、设计与工程，便于排期、拆任务与验收。与纯技术契约（端口、子进程、错误码）配合使用；技术排障仍以 **`docs/本机分割故障排除.md`**、**`docs/本地伴侣-本地程序开发.md`**、**`docs/附录-伴侣错误码.md`** 为准。

---

## 1. 文档目的

| 目标 | 说明 |
| --- | --- |
| 统一叙事 | 用户侧尽量只感知 **「本地伴侣」+「本机能力」**，弱化「SamLocal / rembg / 子进程 / 多端口」等实现词（技术详情可折叠展示）。 |
| 降低心智负担 | 状态、错误、修复入口 **一条路径** 可完成闭环，避免「装好了但不知道谁没起」。 |
| 可拆任务 | 下文 **§6 执行 backlog** 按优先级列出建议改动面与验收口径，便于进迭代或开 issue。 |

---

## 2. 北极星（产品一句话）

**用户只和一个东西打交道：本地伴侣；本机算力（分割、抠图、后续能力）是伴侣提供的「本机能力」，而不是用户要分别安装、分别盯状态的多套小软件。**

---

## 3. 用户真正在抱怨什么（而非表面诉求）

用户很少抱怨「为什么 18081 和 18765 是两个数」。更常见的是：

| 痛点 | 期望 |
| --- | --- |
| 「已就绪」与「子进程未运行」同时出现，**语义打架** | 顶层只展示 **一条结论**：能用 / 需修复 / 未启用；矛盾时以 **阻塞项** 为准并解释。 |
| 只看到 `exit=1` 等**无语义错误** | 映射为**人话 + 下一步**（重试、打开诊断、打开安装日志、复制报告）。 |
| 步骤像运维：伴侣、Sam、URL、环境变量 | **成功路径短**：安装包或向导默认配好；高级项折叠。 |
| 不知道 18765 和 18081 分别是什么 | **默认不向用户强调端口**；必要时二级页展示「技术详情」。 |

## 4. 三层包装（执行框架）

### 4.1 第一层：语言与界面（低成本、高收益）

**原则**：主界面、托盘、设置首屏使用 **用户词**；实现词进「详情」或「复制给支持」。

| 方向 | 建议 |
| --- | --- |
| 统一称谓 | 对外：**本机能力** / **本机处理**；**本地伴侣** 作为唯一入口品牌。SamLocal、rembg 等作为**详情**中的「引擎名称」可选展示。 |
| 状态合成 | 将「伴侣在线」「Sam 随启子进程」「`/health` 可达」合成为**一条主状态**（见 §5.1 状态模型草案）。子项可作为绿/黄/红列表折叠。 |
| 错误呈现 | 任意失败必须具备：**简短原因（人话）** + **主按钮（下一步）** + **次要操作（日志 / 复制）**。禁止裸展示 `exit=1` 作为唯一信息。 |
| 端口 | 主路径文案中**不默认展示端口号**；在「连接详情」或「诊断报告」中展示 `127.0.0.1:18765`（伴侣）与 `127.0.0.1:18081`（本机分割 HTTP）等。 |

**验收**：未读过技术文档的用户，能在 30 秒内理解「当前能不能用本机分割」以及「点哪里修复」。

---

### 4.2 第二层：流程（安装、修复、升级）

**原则**：成功路径短；失败路径可恢复且**同一入口**。

| 方向 | 建议 |
| --- | --- |
| 安装 | Windows：**一键安装** 与伴侣启动链衔接已有基础；需保证完成后有明确「可用了」反馈（不仅是脚本就绪）。 |
| 修复 | 提供统一 **「修复本机能力」**：顺序可设计为：检测端口占用 → 校验关键文件 → 可选重装运行时 → 重启伴侣；避免用户猜「该重装谁」。 |
| 非 Windows | 明确说明一键安装/随启策略与 Win 差异，并给 **文档内最短路径**（如仅开发机：`npm run dev:companion-sam-stack`），避免「已就绪」与平台能力不对齐的挫败感。 |
| 日志 | **安装日志 / 诊断日志** 与错误码联动；支持一键复制（脱敏）给支持或粘贴到 issue。 |

**验收**：常见故障（端口占用、依赖损坏、子进程退出）在**不超过两次点击**内能触发诊断或修复路径。

---

### 4.3 第三层：架构（对用户透明，可渐进）

**原则**：多进程、多端口可以是**实现手段**，不应是**用户心智模型**。

| 阶段 | 描述 | 用户感知 |
| --- | --- | --- |
| **当前** | 伴侣（Node）与子服务（Python 等）分进程；本机 HTTP 多端口（如 18765、18081）。 | 通过 UI 包装为「一个伴侣 + 本机能力状态」。 |
| **中期** | 伴侣聚合状态与健康检查；网站侧只对接伴侣 Base URL；错误与修复入口统一。 | 仍可能多端口，但**用户不记端口**。 |
| **长期（可选）** | 伴侣作为**唯一对外 HTTP 入口**（反向代理或等价路由），子服务仅本机回环或 IPC。 | 「只连伴侣一个地址」；加新能力**不增加用户可见的 URL 数量**。 |

**说明**：TCP 同一 `IP:端口` 只能有一个监听进程，因此「真·单端口」需要网关或合并进程；产品路线图应接受**分阶段**，优先做「单心智入口」再做「单 TCP 端口」。

**验收（长期项）**：新用户文档中可不出现「分割服务端口」即可完成本机分割配置。

## 5. 状态模型与多端口（产品化说明）

### 5.1 主状态合成（草案）

建议将以下信号**合成一条主状态**（示例枚举，可按实现微调）：

| 主状态 | 含义（用户可见） | 典型技术信号（实现侧） |
| --- | --- | --- |
| **正常** | 本机分割等能力可用 | 伴侣健康；`COMPANION_SAM_SEGMENT_URL` 指向的 `/health` 正常；若启用随启则子进程存活（或明确为「用户自管进程」模式且不报未运行）。 |
| **需修复** | 伴侣在，但本机能力不可用或可恢复 | 随启配置存在但子进程退出；`/health` 失败；503 / 缺权重等。 |
| **未启用** | 未安装或未配置本机能力 | 未一键安装 / 未配置 URL 等。 |
| **离线** | 伴侣不可用 | 连接失败、未配对等。 |

**规则**：当「脚本已就绪」与「子进程未运行」冲突时，主状态应以 **需修复** 为优先，并说明「启动脚本已生成，但服务未保持运行」。

### 5.2 端口在用户沟通中的位置

| 端口（默认） | 角色 | 对用户默认展示 |
| --- | --- | --- |
| **18765** | 本地伴侣 HTTP | 可写作「伴侣地址」；不必强调数字。 |
| **18081** | 本机分割（SamLocal）HTTP | 默认不展示；诊断页可写「分割服务（本机）」。 |

## 6. 执行 backlog（建议优先级）

以下为**可拆 issue** 列表；实施时请同步相关 UI（**网站 `components/SettingsSection.tsx`**、**桌面壳 `companion-desktop/shell/index.html`**、**伴侣 `local-companion`** 的 runtime-status / 调试接口）及文档链接。

### P0 — 必须优先（直接减少「看不懂」）

| ID | 任务 | 建议动作 | 验收 |
| --- | --- | --- | --- |
| P0-1 | **主状态一条结论** | 桌面壳首页/托盘与网站设置「本地伴侣」区：合成 **正常 / 需修复 / 未启用 / 离线**；子状态折叠。 | 与「子进程未运行」同时出现「已就绪」时，主结论为 **需修复** 并附一句解释。 |
| P0-2 | **`exit=1` 产品化映射** | 将 `sam_local_not_running` + `exit`/`signal`/`error` 映射为人话；附 **打开安装日志** / **重新一键安装** / **查看诊断**。 | 用户无需理解 exit code 即可点下一步。 |
| P0-3 | **诊断一键导出（可选）** | 聚合：伴侣版本、平台、`runtime-status` 摘要、最近一次 sam 错误、端口探测结果（脱敏）。 | 支持复制到剪贴板，便于支持工单。 |

### P1 — 强体验（闭环与一致性）

| ID | 任务 | 建议动作 | 验收 |
| --- | --- | --- | --- |
| P1-1 | **统一「修复本机能力」入口** | 桌面壳 + 网站设置：同一文案与同一套后端动作（重启子进程、检测端口、引导重装）。 | 用户不区分「修伴侣」还是「修 Sam」。 |
| P1-2 | **自管进程 vs 随启** | 若检测到 18081 已被占用且健康，随启失败不应只显示「未运行」；应提示「已有本机分割在运行（外部进程）」或自动切到「仅检测 HTTP、不强制随启」策略（需产品拍板）。 | 减少「其实能用但黄灯」的误判（见历史讨论）。 |
| P1-3 | **非 Windows 说明对齐** | `shell/index.html` 非 Win 区块与网站文档一致：最短开发路径、无一键安装时的预期。 | 非 Win 用户不因「已就绪」误解。 |

### P2 — 架构演进（中长期）

| ID | 任务 | 说明 | 验收 |
| --- | --- | --- | --- |
| P2-1 | **伴侣内反向代理** | 对外仅 `18765`（或配置项单端口），内部分流到 SamLocal/rembg 等。 | 新用户文档可不写 18081。 |
| P2-2 | **能力注册表** | 新本机能力注册到同一「健康检查 + 修复」框架，避免每能力一套独立 UI 逻辑。（**进展**：`localEnginesRegistry` + `runtime-status.localEnginesStatus`；Sam HTTP、**rembg `import rembg` 子进程探测** 已接线。） | 新增能力时复用同一状态组件与诊断接口。 |
