## 1. 目标

把一个供应商从“目录里能看到”推进到“接上 Key、发布模型、前端可选、任务可执行”的完整闭环。

最终体验：

1. 管理员在供应商中心配置供应商 Key。
2. 管理员对供应商模型或 route 执行真实 Smoke Test。
3. 管理员发布通过验证的 canonical model。
4. 工作台按生成类型展示已发布且可执行的模型。
5. 用户选择模型并提交任务。
6. AI Gateway 根据 canonical model 选择 route、获取 Key、调用 adapter、写回结果和计费信息。

---

## 2. 状态解释

### 待后端

`待后端` 是供应商 route 能力状态，表示模型目录或供应路径已经登记，但还没有完整接入后端执行链路。

通常缺少：

- adapter
- 请求参数映射
- 鉴权和 Key 池取 Key
- 响应解析
- 错误标准化
- 任务结果写回
- 计费和健康事件

### Gateway 待接

`Gateway 待接` 是 AI Gateway runtime 状态，表示这个模型即使被发布，当前统一 Gateway 也不会放行执行。

后端会在创建任务前拦截，常见错误码：

| 错误码 | 含义 |
|---|---|
| `AI_GATEWAY_MODEL_ADAPTER_PENDING` | 模型目录存在，但 adapter 未接 |
| `AI_GATEWAY_MODEL_ROUTE_NOT_FOUND` | 没有可执行 Gateway route |
| `AI_GATEWAY_PROVIDER_KEY_UNAVAILABLE` | route 已接，但没有可用平台 Key |
| `AI_GATEWAY_MODEL_NOT_PUBLISHED` | 模型未发布到工作台 |

## 3. 五块开发任务

### 3.1 Adapter 接入

每个供应商要有对应 adapter，把平台统一任务格式转换成供应商真实 API。

主要落点：

- `server/ai-gateway/workers/`
- `server/ai-gateway/adapters/`
- `server/ai-gateway/provider-router.js`
- `shared/aiGatewayModelRoutes.js`

adapter 必须实现：

- 读取 AI Gateway job input。
- 映射供应商 endpoint、model id、参数名。
- 支持 Abort/timeout。
- 返回统一 artifact：image、video、model3d、music、file。
- 标准化错误码和 HTTP 状态。
- 成功/失败后更新 AI Gateway job。
- 将上游 usage 或预估用量写入 metadata，供计费使用。

验收标准：

- 有最小单测覆盖请求构造和响应解析。
- `createAuthAiGatewayJob` 能创建该供应商任务。
- 成功任务能在 AI 任务中心看到输出。
- 失败任务有清晰错误码，不吞异常。

---

### 3.2 Key 池执行

供应商 adapter 不应直接读散落的环境变量或前端配置，平台 Key 路径应统一走 Key 池。

主要落点：

- `server/ai-gateway/provider-key-store.js`
- `components/admin/AdminProviderKeysPanel.tsx`
- `services/adminProviderKeysClient.ts`
- 具体 adapter

执行规则：

1. adapter 根据 `providerId` 调 `acquireProviderKey(providerId)`。
2. 没有 Key 时返回 `AI_GATEWAY_PROVIDER_KEY_UNAVAILABLE`。
3. 上游 401/403 记录 Key 错误。
4. 上游 429/5xx 记录健康事件，并触发冷却策略。
5. 多 Key 按优先级和 rpm 做轮询。
6. env key 和后台 Key 行为尽量一致。

验收标准：

- Key 缺失时任务不会落到上游。
- Key 错误会写 provider key health event。
- Key 冷却后不会继续被分配。
- 供应商中心能看到最近成功、失败、冷却记录。

---

### 3.3 Route 放行

发布模型不等于可执行。Gateway 必须确认 canonical model 有可执行 route。

主要落点：

- `shared/aiGatewayModelRoutes.js`
- `server/ai-gateway/model-route-guard.js`
- `services/modelRegistry/modelRouteCatalog.ts`
- `components/admin/AdminProviderKeysPanel.tsx`

开发步骤：

1. 在共享规则中登记供应商 runtime route。
2. 将 route 状态从 `adapter_pending` 改为 `gateway_ready`。
3. 在前端 route catalog 中显示 `Gateway 可执行`。
4. 后端 guard 放行该 canonical model。
5. 若需要平台 Key，guard 必须检查 Key 池可用性。

验收标准：

- 管理端 Routes 中显示 `Gateway 可执行`。
- 后端 metadata 写入 `modelRouteGuard`。
- 待接模型仍被 `AI_GATEWAY_MODEL_ADAPTER_PENDING` 拦截。
- 已接模型能进入 adapter 执行。

---

### 3.4 前端选择器

工作台不能只接文本/图片，所有生成类型都应从发布模型清单读取。

主要落点：

- `services/modelRegistry/publishedModelCatalog.ts`
- `services/modelRegistry/merge.ts`
- `hooks/useEffectiveTextModelRows.ts`
- `hooks/useEffectiveImageGearRows.ts`
- 视频/3D 对应 preset 和工作流配置组件
- `components/CapabilityPresetSection.tsx`
- `components/WorkspaceQuickComposeBar.tsx`

目标行为：

| 能力 | 模型来源 |
|---|---|
| 文本 | published canonical text models |
| 图片 | published canonical image models |
| 视频 | published canonical video models |
| 3D | published canonical model3d models |
| 音乐 | published canonical music models |

展示规则建议：

- 默认只展示 `published + gateway_ready`。
- 管理员预览或高级模式可显示 `Gateway 待接`，但置灰。
- 模型提交必须带 `canonicalModelId`。
- 前端错误提示要翻译 Gateway 错误码。

验收标准：

- 管理员取消发布后，工作台不再显示该模型。
- 管理员发布可执行模型后，工作台可选择并提交。
- 发布但待接的模型不会误导用户可用。
- 视频和 3D 不再只依赖硬编码默认模型。

---

### 3.5 真实 Smoke Test

当前 Smoke Test 主要检查凭证字段是否完整。可用闭环需要升级为真实上游探活。

主要落点：

- `server/ai-gateway/provider-key-store.js`
- 新增或扩展 `server/ai-gateway/smoke-test-*`
- `components/admin/AdminProviderKeysPanel.tsx`

Smoke Test 分层：

| 层级 | 目标 |
|---|---|
| Key 级 | Key 是否有效，账号是否能访问供应商 |
| Provider Model 级 | 指定 provider model 是否能最小调用 |
| Route 级 | canonical model + provider route 是否能完整执行 |
| Artifact 级 | 输出是否符合平台统一 artifact 格式 |

规则：

- Smoke Test 不自动发布模型。
- Smoke Test 成功写 `lastVerifiedAt`。
- 失败写 `lastErrorAt`、`lastErrorCode`、`lastErrorMessage`。
- 测试请求必须低成本、低风险。
- 视频/3D 可先使用 dry-run、查询模型、极小任务或专门测试 endpoint。

验收标准：

- 管理员能对单 Key、单模型或单 route 触发测试。
- 成功后供应商中心状态更新。
- 失败原因能直接指导修复：缺 Key、权限不足、模型不存在、余额不足、限流、参数错误。
- 测试结果不影响已发布模型，除非后续明确设计自动下线策略。

## 4. 推荐接入顺序

### 第一批：已有执行基础

1. Gemini / Vertex 图片和文本
2. Tripo 3D
3. 即梦视频

目标：最快达到“发布后工作台可用”。

### 第二批：标准协议供应商

1. OpenAI 官方文本/图片
2. ToAPIs OpenAI-compatible
3. VectorEngine / Gemini-compatible
4. Google AI Studio

目标：沉淀 OpenAI-compatible 和 Gemini-compatible adapter 模板。

### 第三批：多模态平台

1. 火山方舟文本
2. 火山方舟图片
3. 火山方舟视频
4. 火山方舟 3D

目标：按能力逐段接，不一次性宣称全模态完成。

### 第四批：专项能力

1. 腾讯混元 3D
2. 数字人
3. 音乐
4. 其他视频供应商

## 5. 单个供应商接入清单

每接一个供应商或能力，按以下清单完成：

- [ ] `providerCatalog` 中供应商状态正确。
- [ ] `providerModelCatalog` 中模型 ID、文档、状态正确。
- [ ] `canonicalModelCatalog` 中有工作台逻辑模型。
- [ ] `modelRouteCatalog` 中有 provider route。
- [ ] `shared/aiGatewayModelRoutes.js` 中 Gateway route 状态正确。
- [ ] 后端 adapter 完成。
- [ ] adapter 走 `acquireProviderKey`。
- [ ] 缺 Key、Key 错、429、5xx 有标准错误和健康事件。
- [ ] AI Gateway job 能进入 running/succeeded/failed。
- [ ] artifact 输出格式统一。
- [ ] 计费预估和成功结算路径可用。
- [ ] 管理员可执行真实 Smoke Test。
- [ ] 管理员发布后，工作台可选择。
- [ ] 用户提交时带 `canonicalModelId`。
- [ ] 相关 vitest/eslint 通过。

- 输出 artifact
- job metadata

---

## 7. 不建议一次性做的事

- 不要一次性把所有供应商标为可执行。
- 不要只因为 Key 能保存就把模型发布给用户。
- 不要让前端直接绕过 AI Gateway 调平台 Key。
- 不要把 BYOK 和平台 Key 计费混在一起。
- 不要让 Smoke Test 自动发布模型。
- 不要把视频/3D 大文件直接长期写入免费云端 job store。

---

1. 视频和 3D 前端选择器读取 published canonical models。
2. Tripo 3D、即梦视频的真实 Key/route Smoke Test。
3. OpenAI 官方文本/图片 adapter。
4. 将 `Gateway 待接` 模型在工作台置灰或隐藏。
