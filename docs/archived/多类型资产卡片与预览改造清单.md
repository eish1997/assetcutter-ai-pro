## 1. 背景与目标

当前工作台资产以图片为中心演进：图片是一等资产，文字已有 `assetKind: 'text'`，分镜表和资产集也有专用类型；但视频和 3D 更多是挂在图片资产的结果槽上，音乐/音频还没有完整资产表达。

后续工作台固定支持文、图、视频、3D、音乐，资产层需要从“图片卡片 + 特例分支”升级为“统一资产对象 + 类型渲染器”。

目标体验：

1. 资产卡片可稳定展示文、图、视频、3D、音频、分镜表、资产集、组合资产。
2. 打开资产预览后，右侧可切换资产树和版本树。
3. 切到任意资产或版本，中央预览器自动切换为对应类型。
4. 文本资产不再只是 SVG 缩略图，而是具备阅读、复制、下载、加入输入框、结构化查看能力。
5. 复制、下载、拖拽、加入输入框、能力区接收判断全部走统一资产协议。

一句话原则：**资产不是图片的附属结果；图片、文字、视频、3D、音频只是同一资产系统下的不同渲染器。**

## 2. 当前现状

### 2.1 已有资产表达

当前 `WorkflowAsset.assetKind` 主要包括：

| 类型 | 当前表达 | 备注 |
|---|---|---|
| 图片 | `assetKind` 缺省或 `image` | 主路径，`original/results/displayKey` 均围绕图片 |
| 文字 | `assetKind: 'text'` + `textTitle/textBody/textResults` | 已支持拖入文生文、文生图等 |
| 分镜表 | `assetKind: 'storyboard_table'` | 有专用结构数据 |
| 资产集 | `assetKind: 'asset_set'` | 有专用结构数据 |
| 组合 | `isGroup/assetIds/cutImageGroup` | 更像容器或视图，不是独立媒体类型 |
| 视频 | `resultMeta[key].mediaKind === 'video'` | 结果槽媒体类型，不是一等资产 |
| 3D | `modelUrls/stepModelUrls/stepModelFormats` | 挂在图片结果槽上 |
| 音频/音乐 | 暂无完整表达 | 后续需补 |

### 2.2 当前 UI 特征

- 资产网格使用 `getAssetDisplayImage()` 解析当前显示图。
- 视频缩略通过 `workflowResultUsesVideoPreview()` 判断 `<video>` 预览。
- 3D 预览依赖 `ImagePreviewOverlay` 的 `modelUrls` 和 `model3d` 模式。
- 文字资产通过 `workflowTextAsset.ts` 生成缩略逻辑，但卡片阅读体验有限。
- 大图预览仍以 `ImagePreviewOverlay` 为中心，非图片类型是附加能力。
- 右侧缩略条是资产列表，不是完整资产树/版本树。

### 2.3 主要问题

1. **类型语义分散**：图片、文本、视频、3D 分别散落在 `assetKind`、`results`、`textResults`、`resultMeta.mediaKind`、`modelUrls` 中。
2. **预览层命名和职责偏图片**：`ImagePreviewOverlay` 已承载图片、3D、文本下载等多类能力，后续继续塞视频/音频会失控。
3. **视频/3D 不是一等资产**：复制、下载、拖拽、选择、版本切换需要靠特例判断。
4. **文本预览不够产品化**：不能像商业工具里的文档/提示词资产一样阅读、复制、结构化查看。
5. **能力区输入判断仍偏图文**：未来音乐、视频、3D 输入/输出会让判断分支继续膨胀。
6. **降级态不统一**：模型、视频、音频打不开时，需要统一展示文件信息、错误原因和下载入口。

## 3. 目标资产模型

### 3.1 AssetKind

建议扩展资产类型：

```ts
export type WorkflowAssetKind =
  | 'image'
  | 'text'
  | 'video'
  | 'model3d'
  | 'audio'
  | 'storyboard_table'
  | 'asset_set'
  | 'group'
  | 'file';
```

兼容策略：

- 缺省 `assetKind` 仍视为 `image`。
- `isGroup === true` 派生为 `group`。
- `storyboardTable/assetSet` 继续支持旧数据自愈。
- 视频、3D、音频先不强制改存量数据，而是通过 `resolveAssetVariants()` 从旧字段派生。

### 3.2 AssetVariant

引入统一资产版本/产物槽：

```ts
export type WorkflowAssetVariant = {
  id: string; // original / stepId / generated artifact id
  label: string;
  kind: 'text' | 'image' | 'video' | 'model3d' | 'audio' | 'file';
  source: 'original' | 'result' | 'derived' | 'uploaded' | 'external';
  url?: string;
  objectKey?: string;
  companionKey?: string;
  text?: string;
  mimeType?: string;
  posterUrl?: string;
  posterObjectKey?: string;
  posterCompanionKey?: string;
  durationMs?: number;
  width?: number;
  height?: number;
  modelUrls?: string[];
  modelCompanionKeys?: string[];
  modelFormats?: Array<'glb' | 'gltf' | 'fbx' | 'obj'>;
  meta?: Record<string, unknown>;
};
```

### 3.3 派生入口

新增统一解析入口：

```ts
resolveWorkflowAssetKind(asset): WorkflowAssetKind
resolveWorkflowAssetVariants(asset): WorkflowAssetVariant[]
resolveWorkflowAssetActiveVariant(asset): WorkflowAssetVariant | null
resolveWorkflowAssetCardPreview(asset): AssetCardPreview
```

这些函数应该收敛现有字段：

- `original`
- `originalObjectKey`
- `originalCompanionKey`
- `results`
- `resultsObjectKeys`
- `resultsCompanionKeys`
- `textBody`
- `textResults`
- `resultOrder`
- `resultMeta`
- `modelUrls`
- `modelCompanionKeys`
- `stepModelUrls`
- `stepModelCompanionKeys`
- `stepModelFormats`

## 4. 资产卡片改造

### 4.1 统一卡片骨架

卡片分为骨架和渲染器：

```text
WorkflowAssetCardShell
  - selection / hover / context menu / drag handle
  - type badge / status badge / version count
  - title / source step / created time
  - quick actions
  - AssetCardPreviewRenderer
```

`AssetCardPreviewRenderer` 按类型选择：

| 类型 | 卡片展示 |
|---|---|
| text | 标题、正文摘要、字数、标签；真实 DOM 文本 |
| image | 缩略图、比例、标签、步骤名 |
| video | poster、播放标识、时长、分辨率 |
| model3d | poster/截图、3D 标识、格式、文件数量 |
| audio | 波形缩略、时长、播放状态 |
| storyboard_table | 表格封面、镜头数、缺图/待处理数量 |
| asset_set | 拼贴封面、组件数、类型构成 |
| group | 多资产堆叠/拼贴、成员数量 |
| file | 文件图标、扩展名、大小 |

### 4.2 文本卡片优化

文本卡片不再用大块 SVG 伪图作为主展示，应改为：

- 标题行：优先 `textTitle`，否则取正文第一行。
- 正文：显示 3 到 6 行，按容器高度动态截断。
- 底部元信息：字数、段落数、当前版本标签。
- 支持 Markdown/JSON/Prompt 类型的轻量识别，但不做复杂渲染。
- 可直接选中预览内文本；卡片本身仍保持拖拽/打开能力。

### 4.3 状态与降级

所有卡片都应有统一状态：

| 状态 | 展示 |
|---|---|
| ready | 正常预览 |
| loading | 骨架屏/转圈 |
| missing | 文件丢失，展示恢复/下载提示 |
| unsupported | 当前浏览器不可预览，展示文件信息 |
| error | 展示错误摘要和重试入口 |

## 5. 预览层改造

### 5.1 从 ImagePreviewOverlay 过渡到 AssetPreviewOverlay

建议新增外壳：

```text
AssetPreviewOverlay
  - AssetPreviewChrome
  - AssetPreviewTree
  - AssetVariantTimeline
  - AssetPreviewRenderer
```

迁移原则：

- `ImagePreviewOverlay` 先保留为图片渲染器，不立即删除。
- 新的 `AssetPreviewOverlay` 根据 active variant 类型决定渲染器。
- 图片能力（标注、裁剪、SAM、去背景、全景、高度 3D）继续由图片 viewer 承担。
- 3D 模型 viewer 从“图片预览里的模式”逐步升级成 `model3d` variant 的专属 viewer。

### 5.2 右侧资产树

右侧从单纯缩略条升级为“资产树 + 版本树”：

```text
项目资产
- 文本 A
  - 原文
  - 改写结果
  - 文生图结果
- 图片 B
  - 原图
  - 局部重绘
  - 生视频结果
  - 生成 3D 模型
- 视频 C
  - 原视频
  - 截帧
- 3D D
  - GLB
  - FBX
  - 预览截图
```

交互规则：

1. 点击资产节点：切换 active asset，并默认选中当前显示版本。
2. 点击版本节点：切换 active variant，同时同步 `displayKey` 或后续新状态。
3. 图片版本显示图片工具栏。
4. 文本版本显示文本工具栏。
5. 视频/音频/3D 显示各自工具栏。
6. 不可预览的版本仍可下载、复制 ID、查看元信息。

### 5.3 中央 Viewer

| Viewer | 功能 |
|---|---|
| TextAssetViewer | 阅读、原文、结构、复制、下载 txt/md |
| ImageAssetViewer | 复用现有图片大图能力 |
| VideoAssetViewer | 播放、暂停、时间轴、截图、下载 |
| Model3DAssetViewer | 轨道控制、材质/线框、下载模型、截图 |
| AudioAssetViewer | 播放、波形、时间轴、下载 |
| StoryboardAssetViewer | 进入分镜表结构预览或打开编辑面板 |
| AssetSetViewer | 组件清单、拼贴预览、打开资产集面板 |
| FileAssetViewer | 文件信息、下载、复制链接 |

## 6. 文本资产预览专项设计

### 6.1 卡片态

文本卡片应像“小文档”而不是“图片占位符”：

- 左上角类型角标：文。
- 标题使用正文第一段或 `textTitle`。
- 正文按行展示，保留基础换行语义。
- 底部显示字数、来源步骤、版本数量。
- 对 prompt/JSON/Markdown 做轻量标签，不做复杂编辑器。

### 6.2 大预览态

文本 viewer 建议三个标签页：

| 标签 | 用途 |
|---|---|
| 阅读 | 排版后的正文，适合长文阅读 |
| 原始 | 保留原始换行、Markdown、JSON、Prompt |
| 结构 | 标题、摘要、标签、来源步骤、输入快照、生成元信息 |

操作：

- 复制全文
- 下载 TXT/MD
- 加入输入框
- 作为提示词继续生成
- 与某个图片/视频/3D 资产建立引用关系

### 6.3 文本版本

文本资产的版本包括：

- 原文
- 文生文结果
- 图生文结果
- 文生图结果（kind 为 image）
- 文生视频结果（kind 为 video）
- 文生音乐结果（kind 为 audio）

因此文本资产不能只被当作纯文本，必须支持混合版本。

## 7. 交互闭环

### 7.1 拖拽协议

拖拽数据建议统一：

```ts
type WorkflowAssetDragPayload = {
  assetId: string;
  variantId?: string;
  kind: WorkflowAssetVariant['kind'];
  role?: 'main' | 'reference' | 'mask' | 'audio' | 'prompt';
};
```

能力区接收不再只判断“有没有图/有没有文字”，而是判断：

```text
capability.input.accepts includes variant.kind
```

兼容期仍可由 `workflowAssetAllowedForCapabilityDrop()` 调用新解析器。

### 7.2 复制策略

| 类型 | 复制行为 |
|---|---|
| text | 复制当前文本 |
| image | 复制图片 |
| video | 复制链接/资产 ID，后续可支持复制文件 |
| model3d | 复制模型链接/资产 ID |
| audio | 复制链接/资产 ID |
| file | 复制链接/资产 ID |

### 7.3 下载策略

| 类型 | 下载 |
|---|---|
| text | `.txt` 或 `.md` |
| image | `.png/.jpg/.webp` |
| video | `.mp4/.webm` |
| model3d | `.glb/.fbx/.obj` |
| audio | `.mp3/.wav/.m4a` |
| storyboard_table | `.json/.csv` 或导出视频 |
| asset_set | 资产集包或组件文件 |

### 7.4 加入输入框策略

| 类型 | 行为 |
|---|---|
| text | 追加正文 |
| image | 添加图片引用 |
| video | 添加视频引用或截帧引用 |
| model3d | 添加模型引用 |
| audio | 添加音频引用 |

需要在 UI 中明确显示加入的是“正文 / 图片引用 / 视频引用 / 模型引用 / 音频引用”。

## 8. 商业产品参考做法

常见商业产品不会把所有媒体塞进一个图片组件，而是采用：

1. **统一资源对象**：资源有类型、版本、来源、元数据。
2. **统一预览壳**：顶栏、侧栏、操作栏一致。
3. **类型专属 Viewer**：文档、图片、视频、音频、3D 分别渲染。
4. **版本/历史可切换**：生成式产品尤其重视 prompt、结果、变体、回滚。
5. **文件不可预览也可管理**：不支持预览时仍能下载、复制、看元信息。
6. **缩略图和 poster 是基础设施**：视频、3D、音频都要有可缓存封面。
7. **资产可作为下一步输入**：所有资产都能被拖到适合的能力，而不是只有图片能被复用。

可参考的产品思路：

- Figma：统一画布和资产面板，不同对象有不同属性面板。
- Runway：视频/图片/生成结果统一进入资产库和时间线。
- Canva：媒体库统一管理图片、视频、音频，类型决定预览和操作。
- Notion：文件、图片、视频、文本块共享页面结构，但有不同 block renderer。
- Blender/Unity 资产面板：3D、材质、贴图、音频都有统一资源入口和专属 inspector。

## 10. 风险点

| 风险 | 说明 | 缓解 |
|---|---|---|
| 旧数据兼容 | 存量项目没有新字段 | 先通过解析器派生，不做迁移强制 |
| 预览层过大 | `ImagePreviewOverlay` 已很重 | 新壳包旧 viewer，逐步拆分 |
| 卡片性能 | 多类型缩略可能增加解码成本 | poster 缓存、懒加载、IntersectionObserver |
| 文本和图片混合版本 | 一个文本资产可能产生图片/视频 | 以 variant kind 为准，不以 asset kind 为唯一依据 |
| 拖拽判断复杂 | 能力输入类型越来越多 | 用 capability accepts + variant kind 统一判断 |
| 3D/视频本地文件丢失 | companion/blob/R2 来源不同 | variant 中保留 objectKey/companionKey/url 三层来源 |
| UI 信息过载 | 类型、版本、状态太多 | 卡片只显示核心信息，详情放预览树和右侧面板 |
