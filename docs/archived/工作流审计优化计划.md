## 1. 背景与问题陈述

### 1.1 设计意图（已有）

项目将创作过程拆成 **三环**（详见架构文档 §3）：

| 环 | 回答的问题 | 真源 / 存储 |
|----|-----------|-------------|
| **步骤时间线** | 资产上发生过哪些 **正式提交**？ | `resultOrder` + `resultMeta`（P0 **只读派生**） |
| **审计环** | 有无 **失败 / 导出 / 敏感** 需查？ | `workflowAuditEvents`（session + scoped local + IDB，**尾部最多 200 条**） |
| **Overlay 快照** | **未提交前**标注画到哪了？ | `workflowOverlaySnapshots`（session + scoped local **有 900KB 上限** + IDB；侧栏恢复 UI 已有） |

### 1.2 当前痛点（2026-06 复核）

1. **写多读少**：P2 打点已覆盖 `runTask` 失败、导出、VGP 拒绝、overlay 关窗/恢复；**无产品读 UI**（架构 §14 仍建议 Console 调 `readWorkflowAuditRing()`）。
2. **体验割裂**：成功步骤在大图侧栏「步骤时间线 + 详情」可见；失败/导出/拒绝在隐藏环内。卡片上仅有 **`assetErrors` Map** 的即时错误文案，**无历史**、**无导出记录**。
3. **React 不刷新审计环**：Overlay 有 `setOverlaySnapshotRingBump`；审计 **append / hydrate 后无 bump**，即便做 Panel 也需先补订阅机制（§2.5）。
4. **两套审计不通**：工作流环 vs 平台 `audit_logs`（登录/admin）— 模型、存储、UI 全分离。
5. **本机 scoped**：换设备 / 清站点即失；与云同步优先方向未对齐。
6. **产品决策未闭合**：附录 A（丢弃成功、pending 关页、上云）— 见 §5。

### 1.3 优化总目标

| 目标 | 说明 |
|------|------|
| **可感知** | 默认：**审计专用 Activity 视图**（失败/导出/敏感）；可选开关合并步骤（避免与上方时间线重复） |
| **可检索** | 按资产、级别、code 筛选；R3 再导出 JSON/CSV |
| **可协作** | R2 起事件带 `userId` + `projectId` |
| **可演进** | **不推翻三环写分层**；读层统一为 `ActivityFeed` |
| **可控成本** | R0～R3 分期；每阶段有验收 |

**范围边界（本计划不含）**：

| 区域 | 说明 |
|------|------|
| 对话临时库 / `App.tsx` 聊天下载 | 非工作区资产；若需审计另立 `CHAT_EXPORT_*` 或不做 |
| 分镜表 `StoryboardTablePanel` 下载 | 非 `WorkflowAsset` 主路径；R0 不纳入 |
| 平台 `auth.*` 审计 | 仍走 `AdminAuditLogsPanel`；R3 仅只读聚合 **工作区** 上云审计 |

**非目标**：法律级不可抵赖、全量 `onLog` 落库、操作录屏式时间线、跨项目审计联邦（与架构 §8 一致）。

## 2. 现状盘点

### 2.1 工作流审计：已实现写入

**存储栈**（与 Overlay **对称但不相同**）：

```text
appendWorkflowAuditEvent
  → sessionStorage（ac_workflow_audit_ring_v1）
  → localStorage（scoped：ac_workflow_audit_ring_v1_local + preferenceScope）
  → IndexedDB（ac_workflow_audit_ring_idb_v1；写入内容为 events 数组，与 session 同步截断为 MAX_EVENTS=200）
hydrateWorkflowAuditRingSessionFromIdbOrLocalIfEmpty（IDB 优先 → local → session）
readWorkflowAuditRing：按 event.id 合并 session + local，再按 ts 排序并取尾部 200
```

**已注册 `code`** — 完整列表见 `WORKFLOW_AUDIT_CODES`（约 20+，含全套 `RUN_TASK_*`）。

| 类别 | code 示例 | 打点位置 |
|------|-----------|----------|
| 队列失败 | `RUN_TASK_*` | `WorkflowSection.runTask` → `appendWorkflowRunTaskFailureAudit` |
| 导出 | `EXPORT_IMAGE`、`EXPORT_TEXT_PREVIEW` | 大图下载、归档 `ArchivedDetailModal` |
| 敏感 / 拒绝 | `DISCARD_BLOCKED_VGP` | `discardResult` 被 VGP 阻止 |
| Overlay | `LIGHTBOX_OVERLAY_*` | 关窗 Modal、侧栏恢复 |

**读路径**：仅 `readWorkflowAuditRing()` — **无 UI**。

### 2.2 步骤时间线（P0）

- 派生：`deriveWorkflowStepTimelineRows` ← `resultOrder` + `resultMeta`。
- UI：`WorkflowStepTimelinePanel` + `WorkflowStepTimelineDetailPanel`（大图侧栏，与 `WorkflowGenerationRecordPanel` 已分工，**勿再建第三套「生成记录」UI**）。
- 限制：缺 `executedAt` →「时间未记录」；**丢弃成功**会从 `resultOrder` / `resultMeta` **物理删除**，无法复盘删了什么（§5 A1）。

### 2.3 Overlay 快照（P1）

成熟度高；差距在不上云。与审计 **勿合并存储**。

### 2.4 平台管理审计

| 项 | 现状 |
|----|------|
| 存储 | Postgres / `auth-db.json`，约 2000 条滚动 |
| 覆盖 | `auth.*`、admin companion、部分 admin API |
| UI | `AdminAuditLogsPanel` — 无 meta 展开/筛选 |
| 与工作流 | **无关联** |

### 2.5 复核发现的实现缺口（优化前必知）

| # | 问题 | 影响 | 建议修复阶段 |
|---|------|------|-------------|
| G1 | 审计 append/hydrate **无 React bump** | 做 Panel 也不刷新 | **R0** 增加 `auditRingBump` 或 Context |
| G2 | `discardResult` 成功时 **delete resultMeta[actionType]** | 「ghost 写在 resultMeta」**不可行** | A1 应用 **审计 tombstone** 或 **`discardedSteps[]`** / P3 `stepTimeline[]` |
| G3 | 批量/卡片下载 **`downloadWorkflowAssetsFromSources`** 无 EXPORT 审计 | §6 映射漏 | **R0** |
| G4 | **3D 模型** `handleLightboxDownloadModel` 无 EXPORT 审计 | 导出缺口 | **R0**（`EXPORT_MODEL` 或 `EXPORT_IMAGE` + detail.format） |
| G5 | **`assetErrors` 与审计环双源** | R1 badge 可能重复 | Activity 优先读审计；卡片 badge 与 `assetErrors` 去重 |
| G6 | 审计事件 **`executedAt` 无关**；步骤 `executedAt===0` | 合并排序不稳定 | 读模型：步骤用 `resultOrder` 序号作 tiebreaker |
| G7 | 失败任务 **`pending` 可能已移除** | R1「重试」链可能 dead | 链到 **再执行同 action** 或只读展示 message |
| G8 | **访客 `__guest` scope** | R2 上云仅登录用户；guest 仍仅本机 200 条 | 文档与 UI 空态说明 |

## 6. 目标架构（优化后）

### 6.1 写层：集中 EXPORT 与 bump

**EXPORT 收口**（避免 R0.6 散落 grep）：

```text
services/workflowAuditExport.ts（建议）
  auditWorkflowExportImage({ assetId, displayKey, context, ... })
  auditWorkflowExportText(...)
  auditWorkflowExportModel(...)
  → 内部 appendWorkflowAuditEvent + 触发 auditRingBump（或 emit）
```

调用方：`WorkflowSection` 大图/模型、`downloadWorkflowAssetsFromSources`（批量 detail.count）、`ArchivedDetailModal`（已有，迁到 helper）。

**React 订阅**：

```text
auditRingBump: number  // 与 overlaySnapshotRingBump 对称
append / hydrate 成功后 bump
WorkflowActivityPanel 依赖 bump 重读 readWorkflowAuditRing()
```

### 6.2 读模型：`workflowActivityFeed.ts`

**原则**：三环 **仍为写真源**；本模块 **只读聚合**，禁止第三套持久化数组（除 A1 明确新增的 `discardedSteps` tombstone）。

```typescript
type WorkflowActivityKind = 'audit' | 'step_committed' | 'discarded'; // discarded 依赖 A1

type WorkflowActivityEvent = {
  id: string;
  ts: number;
  kind: WorkflowActivityKind;
  assetId: string;
  displayKey?: string;
  taskId?: string;
  resultKey?: string;
  level?: 'info' | 'warn' | 'error';
  code?: string;
  title: string;
  sortKey: number; // 步骤：resultOrder 索引；审计：ts；discarded：ts
};
```

**合并与排序**：

- 默认（A7=①）：**仅 `kind==='audit'`**（+ 可选 `discarded`）。
- A7=②：`audit` + `step_committed` interleave；步骤 `ts` 取 `executedAt`，为 0 时用 `sortKey`（order 索引）保证稳定。
- 按 `assetId` 过滤；无 `assetId` 的审计（若有）仅在「项目级 Activity」显示（R1+）。

### 6.3 UI：`WorkflowActivityPanel`

**位置**：大图侧栏 — 与「步骤时间线 / 标注草稿快照」**Tab 或折叠**（避免侧栏过高：建议 **Tab**：时间线 | 活动 | 快照）。

**列**：时间、级别、`title`（来自 `workflowAuditCodeLabels`）、短码 `displayKey`。

**操作**：

- `RUN_TASK_*` + `taskId`：展示 message；R1 尝试链到同 asset 的 **再执行**（非假设 pending 仍存在 — **G7**）。
- `EXPORT_*`：只读。
- `DISCARD_*`：只读。

**空态**：说明本机 200 条限制；guest 说明不上云。

### 6.4 上云（R2，方案 A3=③）

```text
appendWorkflowAuditEvent（本地不变）
  → debounce POST /api/workspace/audit-events
      body: { projectId, event: WorkflowAuditEvent + userId }
服务端：workspace_audit_events 表（append-only，按 project_id 索引）
读：GET ?projectId=&since=&assetId= → 与本地按 id merge
```

**禁止**：把审计 JSON 塞进 `workflow bundle` 或 `liteStructure`（体积、合并语义、跨设备 URL 规则均不合适）。

**字段**：`userId`、`projectId`；仍 **禁止** prompt 全文（可用 `promptFingerprint`）。

### 6.5 平台审计

R3 再增强 `AdminAuditLogsPanel`；可选只读 Tab 查 **workspace_audit_events**（admin + projectId），与工作流 Panel **不同受众**。
