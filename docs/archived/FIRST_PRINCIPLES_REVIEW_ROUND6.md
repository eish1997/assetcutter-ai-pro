# 第一性原理代码审查报告（第六轮）

## 本轮目标
第六轮聚焦一个问题：

1. `App.tsx` 中对话裁切、目标检测、版本切换与临时库回填仍然耦合在页面层

## 第一性判断
- 对话“后处理链路”本质上也是独立状态域，包含版本状态、裁切交互、目标检测状态、裁剪导出与临时库回填，不应继续散落在 `App.tsx` 中。
- 版本切换、检测结果展示、裁切产物落盘都依赖同一份当前显示版本，应该由同一抽象统一维护，避免 UI 层自己拼状态。

## 已完成优化
- 新增 [`hooks/useDialogPostProcessing.ts`](../hooks/useDialogPostProcessing.ts)，集中管理：
  - 当前显示版本解析与版本切换
  - 裁切状态、拖拽选择与裁切确认
  - 识别图中物体与结果展开/收起
  - 单个/批量裁剪下载
  - 单个/批量加入临时库
  - 将当前版本保存到资产库
  - 将当前版本回填为对话输入图
- 在 [`App.tsx`](../App.tsx) 中移除大段后处理逻辑，改为消费 `useDialogPostProcessing()` 返回的状态与事件。
- 让对话发送编排 hook 与后处理 hook 通过 `setDialogVersionIndex` 协作，明确“生成阶段”和“后处理阶段”的职责边界。

## 收益
- `状态分层更清楚`：对话域已经拆成“工作区状态”“发送编排”“后处理链路”三个层次。
- `页面负担更低`：`App.tsx` 进一步回到 UI 装配角色，不再自己管理版本与裁切细节。
- `后续补测试更容易`：检测、裁切和版本切换现在有了清晰的单独边界，便于后续补最小必要单测。

## 验证结果
- `npm run typecheck` 通过
- `npm run lint` 通过（仍保留历史 warning，未新增 error）
- `npm run test` 通过
- `npm run build` 通过

## 剩余风险
- 对话区 JSX 仍然偏长，显示层和交互按钮布局还没有继续拆成子组件。
- 当前对话 hook 仍缺少针对裁切、检测与版本切换的自动化测试。

## 下一轮建议
- 第七轮优先拆对话消息渲染区，把消息卡片、版本条、检测结果条、裁切弹层拆成组件。
- 然后补 `useDialogGeneration` / `useDialogPostProcessing` 的最小必要单测，锁住关键交互行为。
