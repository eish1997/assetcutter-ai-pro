# 第一性原理代码审查报告（第五轮）

## 本轮目标
第五轮聚焦一个问题：

1. `App.tsx` 中对话发送、理解、生图、重生成与取消链路耦合过深

## 第一性判断
- 对话发送链路本质上是一段“状态机式编排”，包含输入落盘、理解、问答、生图、取消、失败恢复、生成记录写入，不应继续和页面装配代码混写在一起。
- 同一条链路里的取消、失败、版本落盘和临时库回写应该走统一入口，否则未来改一个分支时极易漏掉其他分支。

## 已完成优化
- 新增 [`hooks/useDialogGeneration.ts`](../hooks/useDialogGeneration.ts)，集中管理：
  - 发送对话消息
  - 仅问答回复
  - 文生图/图生图生成
  - 重新生成
  - 从“理解结果”继续生成图片
  - 取消进行中的生成
- 在 [`App.tsx`](../App.tsx) 中删除大段发送编排逻辑，改为消费 `useDialogGeneration()` 返回的状态与事件。
- 把“取消提示”“失败提示”“生成记录写入”“临时库回写”“版本索引更新”等公共步骤收口到 hook 内部，减少重复分支。

## 收益
- `入口职责更纯`：`App.tsx` 更接近页面装配层，发送链路不再淹没主组件。
- `行为一致性更强`：发送、重生成、从理解结果生成现在共享同一套取消与落盘规则。
- `后续更容易测试`：下一步如果要补对话链路单测，已经有了明确的编排边界。

## 验证结果
- `npm run typecheck` 通过
- `npm run lint` 通过（仍保留历史 warning，未新增 error）
- `npm run test` 通过
- `npm run build` 通过

## 剩余风险
- `App.tsx` 中对话裁切、目标检测、临时库面板与 UI 交互仍较重，尚未完全模块化。
- 当前自动化测试仍未覆盖对话发送编排本身，回归验证主要依赖类型检查与构建通过。

## 下一轮建议
- 第六轮优先拆对话“后处理链路”，把裁切、检测、版本切换、临时库回填进一步从 `App.tsx` 中分离。
- 然后再考虑为 `useDialogGeneration` 补最小必要单测，锁住关键分支行为。
