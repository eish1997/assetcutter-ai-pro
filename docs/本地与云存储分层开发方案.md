# 本地与云存储分层开发方案（含能力预设账号云同步）

本文用于统一 `assetcutter-ai-pro` 的数据落盘策略，目标是同时满足：

- 大文件场景下的性能与成本（3D/贴图/中间产物）
- 跨设备可用性与账号体验（预设、项目索引）
- 可恢复与可演进（版本迁移、崩溃恢复、冲突合并）

---

## 0. 第一性原理（产品化总纲）

以下三条是本方案的最高优先级约束，后续实现与评审以此为准：

1. **字节真相在本地**：大文件（模型/贴图/中间产物）只在本地伴侣作为真相源，云端只存引用和索引。
2. **能力真相在账号**：能力（`CustomAppModule`/`CapabilitySet`）是账号级资产，不属于项目级数据。
3. **恢复真相在任务**：所有外部长任务必须有可恢复锚点（如 taskId）、可分流动作（继续查/重提）与结构化日志。

> 一句话标准：**本地持有字节真相、账号持有能力真相、任务持有恢复真相。**

---

## 1. 决策总览（先定规则）

1. **能力（预设/复合能力）**：账号级资产，自动上传云端，按账号强绑定（随账号走），**不属于项目级数据**。
2. **项目内容**：本地优先存储，尤其是模型与大图等重资产。
3. **云端项目数据**：默认存轻量索引与结构，不强制存文件本体。
4. **执行链路**：优先本地文件引用；云端主要负责“可见、可检索、可协作”。

## 2. 本地与云分别存什么

### 2.1 本地存储（Local Companion 主存）

- 文件本体：`glb/gltf/fbx/obj/stl/usdz`、原图、贴图、导出包
- 中间产物：切割中间图、修缝中间图、流程临时结果
- 高频缓存：缩略图缓存、预览快照、临时 blob
- 恢复上下文：任务游标、重试状态、局部运行日志
- 项目文件：`project.json` + `assets/` + `journal/`（建议目录模式）

### 2.2 云存储（账号与协作层）

- 账号级能力预设（必上云）
- 项目索引：项目名、更新时间、封面、状态、schemaVersion
- 工作流结构：节点、步骤参数、结果引用 key（不含大文件字节）
- 资产轻索引：`assetId -> localKey/hash/previewKey/mime/size`
- 可选低清预览：用于项目列表秒开（非原始大图）
- 协作信息：owner、成员、权限、审计

### 2.3 明确禁止上云内容

- API Key / Token / 本机绝对路径 / 本机内网地址
- 全量本地调试日志（尤其原始敏感上下文）
- 可重建的大体积中间缓存

## 3. 能力预设云同步（账号强绑定）

> 强约束：能力是账号级内容，不是项目级内容。项目只能引用能力 ID 或能力快照，不能拥有“账号主能力”的所有权。

## 3.1 同步对象

- `CustomAppModule`（能力预设）
- `CapabilitySet`（复合能力编排）

## 3.2 同步语义

- 云端主键：`userId + presetId`
- 变更触发：本地保存预设后自动增量同步
- 拉取时机：登录后、切换账号后、定时轻量对账
- 冲突规则：`updatedAt` 新者胜（MVP）
- 删除规则：软删除（`deletedAt`），支持撤销/恢复

## 3.3 安全边界

- 预设同步时过滤敏感字段（key、token、本机地址）
- 预设可带“执行参数快照”，但不带用户密钥

---

## 4. 项目数据模型建议

## 4.1 本地项目目录（推荐）

```txt
<project-root>/
  project.json
  assets/
    <content-hash>.<ext>
  previews/
    <asset-id>.jpg
  journal/
    <timestamp>.ndjson
```

## 4.2 `project.json` 最小字段

- `projectId`, `name`, `schemaVersion`, `updatedAt`
- `assets[]`（仅引用，不塞大字节）
- `workflow`（节点关系与步骤参数）
- `resultRefs`（`assetKey`/`previewKey`）
- `runtimeHints`（可恢复但非强一致字段）
- `capabilityRefs`（仅引用 `presetId` / `setId`，可选附带执行快照）

**项目字段禁区（必须禁止）**：

- 禁止把账号级能力全集写入项目文件
- 禁止项目覆盖账号主能力定义
- 禁止项目内携带能力相关敏感配置（密钥/令牌/本机地址）

## 4.3 引用规范

- 使用相对 key 或 `asset://<hash>`，禁止写死本机绝对路径
- 跨设备/跨账号打开时按 key 解析本地资源
- 缺失资源显示“可重拉/可重建”状态，不直接崩溃

## 5. 跨账号与打开策略

## 5.1 本地工作区目录打开策略（离线模式）

- 网站不再提供“手输绝对路径打开/另存为项目文件”入口。
- 统一由本地伴侣 `workspace root` 扫描子目录作为项目来源。
- 任何账号可打开这些本地项目目录（符合创作工具直觉）。
- 打开后进入“本地来源项目”状态，默认不并入账号云空间。

## 5.2 绑定账号工作区（显式动作）

- 用户确认后执行“导入为副本”或“绑定该项目”
- 绑定后仅同步结构索引与预设引用，不自动上传大文件本体
- 当前最小落地：项目列表支持“绑定到当前账号”，并弹窗明确“仅同步索引，不上传本地大文件”。
- 当前最小落地补齐：已支持“解绑当前账号”动作，解绑仅更新索引绑定状态，不删除本地目录与内容。
- 当前最小上传补齐：已支持“手动上传”动作（仅对“已绑定当前账号”项目可见）；上传前二次确认“可能耗时且占用云空间”，上传执行显式调用 `pushWorkflowBundleToCloud`，不影响默认索引同步路径。
- 当前可用性补齐：手动上传确认弹窗新增上传前预估（资产数/预览图数/模型引用数/预估体积），上传成功后在项目索引记录 `lastManualUploadAt/lastManualUploadAssetCount/lastManualUploadBytesApprox` 并在项目卡片展示“最近手动上传”。
- 当前效率补齐：手动上传支持“全量上传 / 仅上传新增或变更”两种模式。增量模式会先读取云端 `workflow.json` 作为基线，仅上传差异资产；若基线读取失败，前端明确记录日志并回退全量上传，不做静默降级。
- 当前稳态补齐：手动上传会记录“最近一次上传结果明细”（尝试数/成功数/失败资产 id 列表/错误摘要/模式），项目卡片可直接看到成功失败摘要；若存在失败项，支持“一键重试失败项”（强制增量模式，仅上传失败资产集合）。
- 当前诊断补齐：新增“失败项详情”弹层（模式/时间/尝试与成功统计/错误摘要/失败 `assetId` 列表），支持勾选后“重试所选失败项”；若所选资产本地已不存在，执行时会按跳过项计数写日志，不做静默吞掉。
- 当前交互补齐：失败详情弹层支持“全选 / 全不选 / 仅选本地仍存在”快捷选择；重试按钮旁展示“将重试 N 项（不可用 M 项）”，并在执行前写入 `selection_total/selection_existing/selection_missing` 统计日志。
- 当前列表检索补齐：失败详情弹层支持按 `assetId` 关键字过滤列表（显示匹配数/总数），并提供“仅选当前列表”一键将勾选范围设为当前可见项。
- 当前排障补齐：失败详情弹层支持「复制当前列表」「复制已勾选」到剪贴板（首行注释含项目名、`projectId`、模式、可选上传时间；正文为每行一个 `assetId`），成功/失败写入运行日志。
- 当前剪贴板兜底：`navigator.clipboard` 失败时依次尝试 `document.execCommand('copy')`；仍失败则弹出只读文本区供手动复制，并支持 Esc / 遮罩 / 关闭按钮关闭；失败详情弹层支持 Esc 关闭并清空过滤关键字。

## 5.3 预设缺失兜底

- 项目引用的 `presetId` 在当前账号不存在时：
  - 用项目内执行快照参数继续跑
  - 同时提示“保存为我的预设”
- 若用户选择“保存为我的预设”，创建新的账号级能力记录，不回写污染原项目引用语义。

## 6. 常见问题与产品化建议

- **问题：项目跨账号直接打开会不会越权？**  
  建议：本地可打开，但进入“未绑定账号”态；云操作需二次确认。

- **问题：大文件是否要自动云同步？**  
  建议：默认不自动；提供“上传到云（pin）”按钮按需上云。

- **问题：版本升级会不会打不开旧项目？**  
  建议：引入 `schemaVersion + migrate()`，每次升级补迁移脚本。

- **问题：崩溃导致文件损坏怎么办？**  
  建议：临时文件写入 + 原子替换 + journal 恢复。

## 7. 分阶段实施（建议里程碑）

### M1（立即）

- 预设自动云同步（账号隔离、增量上传、`updatedAt` 合并）
- 项目本地目录“保存/打开”闭环

### M2

- 项目 schema 版本化与迁移器  
  现状（浏览器 bundle）：`WorkflowProjectBundle.workflowBundleSchemaVersion` + `WORKFLOW_BUNDLE_SCHEMA_CURRENT`（`services/workspaceProjectStore.ts`），加载时 `migrateWorkflowBundleSchema`、保存时写入当前版本。后续字段演进在同一处叠迁移步骤即可。  
  项目目录侧原子写 / `journal/`：**本地伴侣** 已实现 manifest + 对象文件写入策略；浏览器 IndexedDB 仍为合并写入 + `flushWorkspaceBundleIdbWrites`，不另建 journal 文件。
- 本地原子写与 journal 恢复（目录级仍以伴侣为准；浏览器端见上）

### M3

- 云端项目轻索引同步（不含大文件）
- 项目列表跨设备可见

### M4

- 按资产上云（pin）与回源策略
- 共享/协作的权限与审计

## 8. 本仓库落地优先级（结合现状）

1. 继续强化本地伴侣作为文件主平面（当前方向正确）。
2. 将能力预设同步抽成独立“账号配置通道”，不与项目文件耦合。
3. 项目持久化坚持“引用优先”，避免把大文件塞进工作流 JSON。
4. 所有持久化 URL 维持相对路径/可解析 key，禁止写死 `localhost`。

---

## 9. 一句话标准

**预设是账号资产（自动云同步），项目是内容资产（本地优先），云端负责索引与协作，不做默认全量大文件托管。**  
**登录不等于「任意浏览器自动出现同一张画布」**：跨设备继续编辑依赖同一本地伴侣工作区根目录，或导出 / 手动上云等显式动作；产品界面与设置页已对该预期做可见说明。

## 11. 本地保存 MVP（历史）与收口

### 11.1 自动化冒烟（已验证）

  - 输入 `assets/pending/capabilityRefs` 可成功写入
  - 重新读取后结构一致（样本：`opened=1, pending=1, refs=1`）

### 11.3 历史失败场景（仅兼容接口）

## 12. 本地仓库项目目录对齐（新增决策）

为对齐产品化体验，项目管理改为“本地伴侣仓库路径”为唯一来源：

1. 本地伴侣设置一个**工作区根目录**（workspace root）。
2. 根目录下每个**项目文件夹**对应网站工作区中的一个项目。
3. 网站“新建项目”时，本地伴侣在根目录创建对应项目文件夹。
4. 网站项目列表由本地伴侣扫描根目录返回，不再以网页本地缓存作为项目真相源。

### 12.1 目录约定（第一版）

```txt
<workspaceRoot>/
  <projectName>/
    manifest.json
    assets/
    scratch/
    exports/   # 可选：本地项目文件导出
```

### 12.2 同步语义

- 网站新建/重命名/删除项目 -> 调本地伴侣项目 API（由伴侣落盘）
- 网站读取项目列表 -> 调本地伴侣扫描结果
- 网站仅缓存 UI 态，不维护独立项目真相源

### 12.3 兼容接口策略（已定）

- `POST /v1/projects/save-as`、`POST /v1/projects/open` 仅保留兼容，不再作为产品主流程。
- 兼容接口返回 `deprecated` 提示，并携带弃用响应头；禁止新增业务依赖这两个接口。
- 新功能一律基于 `/v1/workspace/projects*`（含回收站）实现。
