# 宿主中心真实软件验收记录

状态：待验收  
目标：为 `docs/宿主中心-Copilot添加宿主改造计划.md` 的最终门禁留下机器可读证据。

## 验收原则

1. 只能在真实软件启动并产生真实连接信号后记录成功。
2. 只安装文件、只看到卡片、只看到目录存在，都不能记录成功。
3. 未安装软件、路径错误、探测失败时可以记录失败，但不能用于通过最终门禁。
4. 每完成一项后运行 `npm run host-bridges:acceptance:check` 复查七类进度。

## 记录命令

成功记录：

```powershell
npm run host-bridges:acceptance:record -- <host-id> --ok --message "写清软件版本、路径、探测成功信号"
```

失败记录：

```powershell
npm run host-bridges:acceptance:record -- <host-id> --fail --message "写清失败原因和下一步"
```

总门禁检查：

```powershell
npm run host-bridges:acceptance:check
```

## 2026-08-09 已打开软件识别后启动修复

问题：宿主中心能识别已经打开的软件，但之后点击“启动宿主”仍提示找不到软件路径。

原因：

1. 本机 `custom-host-targets.json` 中已保存 Maya、Unreal、Substance Painter 的 exe 路径。
2. 该文件里的中文 label 曾发生编码损坏，导致 JSON 失效。
3. 读取失败后，本地 companion 把已保存路径当作不存在。
4. 前端启动时还可能把脚本目录或插件目录的安装目标 id 作为启动 `targetId` 发送，导致启动解析提前停在“版本记录不存在”。

修复：

1. `readCustomHostTargets()` 增加损坏 JSON 抢救逻辑，只要 `id`、`inputPath`、`resolvedPath` 等关键字段还在，就恢复可用启动路径。
2. 运行中识别保存的 label 改为 ASCII 稳定文本，避免长期配置再次因为中文标签损坏。
3. 启动解析收到非启动版本 targetId 时，会继续回退到已保存路径、正在运行进程和常见安装目录。
4. 已修复本机损坏的 `custom-host-targets.json`，当前可读到 Maya、Unreal、Substance Painter 三条已识别路径。

验证：

1. `npx vitest run tests/hostAppProcess.test.ts`
2. `npm run local-companion:typecheck`
3. `npx vitest run tests/hostAppProcess.test.ts tests/shellHostCenterUi.test.ts tests/agentToolSchema.test.ts`

## 2026-08-10 Copilot 安装参数映射修复

问题：使用 Copilot 做宿主真实验收时，安装步骤连续失败。ZBrush 日志中可见 Copilot 尝试了多个真实目录：

1. `C:\Program Files\Maxon ZBrush 2025\ZScripts`
2. `C:\Program Files\Maxon ZBrush 2025\ZStartup\ZPlugs64`
3. `C:\Users\Public\Documents\ZBrushData2025\ZStartup`
4. `C:\Users\Public\Documents\ZBrushData2025\ZStartup\ZScripts`

但工具均返回 `no_zbrush_scripts_dir`。

原因：

1. Copilot 工具 `ac.companion.host_bridge.install` 为了降低用户理解成本，只暴露统一字段 `targetDir`。
2. 内置宿主安装路由实际需要各自的字段，例如 `scriptsDirs`、`projectDirs`、`pluginDirs`、`startupDirs`、`prefsDirs`、`userDirs`。
3. ZBrush 路由只读取 `scriptsDirs`，所以 Copilot 传入的真实 `targetDir` 被忽略，最终误报“没有脚本目录”。

修复：

1. `companion-desktop/agent-body-host.cjs` 增加内置宿主安装字段映射，把 Copilot 的 `targetDir` 转成对应宿主需要的字段。
2. ZBrush HTTP 路由增加 `targetDir` 兼容，直接调用 `/v1/bridges/zbrush/install` 时也不会再忽略目录。
3. 保持用户侧仍只需要提供一个目录，不要求理解宿主技术模板或底层字段名。

验证：

1. `node --check companion-desktop/agent-body-host.cjs`

5. 本地接口 smoke：`POST /v1/bridges/zbrush/install` 只传 `targetDir`，结果 `ok: true`，写出 `AssetCutter_ZBrush_Bridge.txt`。
