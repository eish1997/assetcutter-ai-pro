# 本地伴侣 · 本地程序开发说明

本文描述 **本仓库内可运行的本地伴侣进程**（`local-companion/`）：自带 **浏览器界面（用户向称本机管理页）**，当前固定两个产品模块——**插件**、**仓库**——后续可在同一界面扩展更多 Tab 或子路由。

**总架构与插件模型**仍以 [`本地伴侣-存储与计算规范.md`](./本地伴侣-存储与计算规范.md) 为准；**站点中转（Relay）** 协议见 [`本地中转应用开发文档.md`](./本地中转应用开发文档.md)。**运行时能力插件 vs 桌面壳/宿主插件包发行**（可否热更、R2 登记、用户下载入口）见 **[`本地伴侣-插件与发行.md`](./本地伴侣-插件与发行.md)**。**桌面壳全局 Copilot（可插拔大脑、Agent Store、身体 Tool `ac.*`、可选 Body MCP）** 见 **[`本地伴侣-全局Agent规格.md`](./本地伴侣-全局Agent规格.md)**（v0.3：产品篇 + 资产篇 + 工程契约）。**产品与技术已决**（安装壳、合并策略、安全模型等）见 **[`本地伴侣-待决策清单与建议.md`](./本地伴侣-待决策清单与建议.md)**；**错误码**见 **[`附录-伴侣错误码.md`](./附录-伴侣错误码.md)**。**主站部署与「第一版」范围**（与桌面安装包区分）见 **[`网站与发布检查清单.md`](./网站与发布检查清单.md)**；**桌面壳打包**见 **[`本地伴侣-发布前检查清单.md`](./本地伴侣-发布前检查清单.md)**。

## 1. 定位

| 项 | 说明 |
|----|------|
| **进程形态** | Node.js（≥20）+ 本机 `http` 服务，仅绑定 **`127.0.0.1`**。 |
| **界面形态** | 内置静态页 `public/index.html`：**总览**（runtime + capabilities）、**插件**、**仓库**；开发期可直接 Node 打开浏览器，亦可用 **`companion-desktop/`** 托盘壳（见 **§6.1**）。 |
| **与主站关系** | 主站「设置 → 本地伴侣」探测 `GET /v1/health`、`GET /v1/capabilities`，成功后可展开 **Relay**、**`compute.seamRepair`** 摘要；`GET /v1/runtime-status` 拉取 **`localCapabilityUi`** 与 **`rembgPythonProbe`** 等；「打开本机管理页」即本进程 **`/`**。业务可调用 **`submitCompanionSeamRepairJob`**、**`listCompanionHostPluginBundles`**、**`submitCompanionHostBundleProbeJob` / `submitCompanionHostBundleExecJob`**（`services/companionClient`）；设置页已提供 **刷新已安装宿主包 → 下拉选择 → 运行 probe/exec**，并与下方 **任务进度**（`jobId` / `pullCompanionJobEvents` 支持 `jobIdOverride`）共用。 |

### 1.1 目标交付形态（产品体验，已决）

**产品目标**：**Electron 安装包** + **系统托盘（必选）** + **主窗口（可选）** + **设置页配对**（本机通信密码、允许的网站地址）；**默认不开机自启**；卸载 **默认保留** 本机卷，可选勾选删卷。进程名 **`AssetCutterCompanion`**；安装与数据路径 **英文**（如 `%LOCALAPPDATA%\AssetCutterCompanion\`），Volume **不**默认进 `Program Files`。

**与当前仓库的关系**：`local-companion/` 为 **开发期 Node 宿主**（协议与安装版一致）；Electron 壳 **内嵌/启动该 Node 进程**，管理页 HTML 可继续用 `public/index.html` 或迁入 WebView。仓库内已有 **`companion-desktop/`**（M0：托盘 + 子进程拉起宿主），根目录执行 **`npm run companion-desktop:start`**（须先在各目录 `npm install`）。

**安全（安装包版）**：**Origin 白名单 + 配对 Token**（与 auth-api / bridge 对齐）；开发期 `npm run dev` 可维持宽松 CORS 便于联调（见已决清单 §3）。

| `POST` | `/v1/compute/jobs` | Job 体：`type` 可为 **`stub.ping`**、**`seam_repair`**、**`host_bundle.probe`**、**`host_bundle.exec`**（后两者 **`inputs: { dirName }`** 须与 `host-bundles` 下目录名一致；**命令行仅读磁盘 `run.json`**，请求体不得注入 argv）；可选 **`projectId`**（元数据）；支持外包 `{ "job": { … } }` |

### 3.2 `runtime-status` 与本机引擎探测

- **`GET /v1/runtime-status`** 在 JSON 中含 **`localCapabilityUi`**（一条主结论，已合并 Sam HTTP 与 rembg Python 探测）、**`samSegmentHttpProbe`**、**`rembgPythonProbe`**、**`paddleOcrHttpProbe`**、**`localEnginesStatus`**（注册表聚合）。  
- 为减轻高频轮询开销，伴侣在 **`httpHandler`** 内对 Sam HTTP 与 rembg 子进程探测使用 **短 TTL 内存缓存**：环境变量 **`COMPANION_RUNTIME_PROBE_CACHE_MS`**（毫秒，未设置默认 **8000**；**`0` 或负数** 表示关闭缓存；合法值夹在 **500～120000**）；`relay` / `samLocal` 等仍每次从 `buildRuntimeStatus` 现算。  
- 主站 **`services/companionClient`**：`fetchCompanionRuntimeStatus`、`probeCompanionSamSegmentHealth`、`probeCompanionRembgHealth`、**`probeCompanionPaddleOcrHealth`** 分别对应 **`/v1/runtime-status`**、**`/v1/debug/sam-segment-health`**、**`/v1/debug/rembg-health`**、**`/v1/debug/paddleocr-health`**。PaddleOCR 规格见 **[`本地伴侣-PaddleOCR-开发文档.md`](./本地伴侣-PaddleOCR-开发文档.md)**。

`POST`/`PUT`/`DELETE` 与 `GET` 使用同一套 CORS（`Access-Control-Allow-Methods: GET, POST, PUT, DELETE, OPTIONS`）。**单文件上传**大小默认 **100MB 封顶**，可用 **`COMPANION_MAX_UPLOAD_BYTES`** 调整（硬顶 512MB）。**默认**（未配置白名单时）JSON 接口仍 **`Access-Control-Allow-Origin: *`**（或回显 `Origin`），便于 https 开发站跨域探测本机。若设置 **`COMPANION_ALLOWED_ORIGINS`**（逗号分隔的 Origin 列表），则带 `Origin` 头的请求 **不在列表中** 时返回 **403**（`AUTH_ORIGIN_DENIED`）；列表可含 **`http://localhost:*`**、**`http://127.0.0.1:*`** 以匹配任意端口。无 `Origin` 的请求（同源管理页、curl 等）**不**因白名单被拒。

> 项目管理已统一到 `/v1/workspace/projects*`；`/v1/projects/save-as` 与 `/v1/projects/open` 仅为兼容保留，并会返回弃用标识（`deprecated` + `Deprecation`/`Sunset` 头），禁止新增业务依赖。

### 3.1 manifest 扫盘补登记（与主站工作区对齐）

**问题**：若磁盘上已有 `projects/<projectId>/assets/<key>/object`，但 **`manifest.json` 未登记** 该 key（异常中断、手工拷贝目录等），`GET /v1/projects/:projectId/assets/:key` 仍依赖 manifest；仅靠浏览器无法把「孤儿文件」登记回 manifest。

**伴侣实现**：`local-companion/src/storage/assetBlob.ts` 中 **`reconcileManifestOrphansFromDisk(projectId)`** —— 扫描 `assets/*/` 下存在名为 `object` 的文件、且 key 通过路径安全校验的目录；对 manifest 缺失的条目 **upsert**（`mime` 等由文件头嗅探：常见位图与 glTF 二进制魔数），并 **同步写回** `manifest.json`。

**HTTP**：**`POST /v1/projects/:projectId/manifest/reconcile`**（见上表）。成功：**`{ ok: true, added, keys }`**；失败：4xx + **`error` / `code`**。`pluginRegistry` 的 `storage.reconcileManifest` 字段与上述路径一致，供管理页/探测 JSON 自描述。

**主站**：**`services/companionClient/storage.ts`** → **`reconcileCompanionManifestFromDisk`**。打开工作区项目时（已配置伴侣 base）：**`App.tsx`** 在 **`getCompanionManifest`** 后若 **`findCompanionKeysMissingFromManifest`** 发现缺口，**先** POST reconcile，**再** 拉一次 manifest 重算缺口；仍缺的再告警并 **`attemptRepairCompanionManifestKeyGaps`**（仅当内存里仍有可规范为 data URL 的图时才重新 PUT）。与分层方案 **M2 补充**、**`docs/交接文档.md`** 中对应条目一致。

**可选共享 Token**：设置 **`COMPANION_SHARED_TOKEN`**（非空）后，除 **`GET /v1/health`**、**`GET /`**、**`GET /index.html`** 外，所有路径需 **`Authorization: Bearer <与变量值一致>`**，否则 **401**（`AUTH_TOKEN_REQUIRED` / `AUTH_TOKEN_INVALID`）。主站设置「本地伴侣」可保存同名 Token，**`services/companionClient`** 会自动附加该头。**`/v1/capabilities`**、**`/v1/projects`** 等在启用 Token 后亦需携带 Bearer。`GET /v1/capabilities` 与 **`GET /v1/runtime-status`** 的 JSON 中含 **`access`** 摘要（白名单是否启用、是否要求 Bearer），便于管理页展示。

**环境变量（宿主）**：`COMPANION_HTTP_PORT`、`COMPANION_VOLUME_ROOT`、`COMPANION_OPEN_BROWSER` 见上；另 **`COMPANION_RELAY_CMD`**（可选）拉起 Relay 子进程；**`COMPANION_RELAY_CHILD_HTTP_PORT`** 控制子进程 `COMPANION_HTTP_PORT`（默认 `0`，`keep` 不覆盖），见 **§5**；**`COMPANION_ALLOWED_ORIGINS`**、**`COMPANION_SHARED_TOKEN`** 见上（安装包收紧模型，与已决清单 §3 对齐）。**本机分割子进程（可选）**：**`COMPANION_SPAWN_SAM_LOCAL_CMD`**（shell 命令，如 `npm run dev:sam-local`）、**`COMPANION_SPAWN_SAM_LOCAL_CWD`**（子进程工作目录，常为 monorepo 根），见 **`local-companion/src/samLocalSupervisor.ts`**。**修缝 Adapter**：**`COMPANION_SEAM_REPAIR_URL`**（默认 `http://127.0.0.1:8008/api/repair`）、**`COMPANION_SEAM_REPAIR_TIMEOUT_MS`**（默认 `120000`）。**宿主插件包**：**`COMPANION_HOST_BUNDLE_TRUST_HOSTS`**（非 R2 下载域名白名单）、**`COMPANION_HOST_BUNDLE_MAX_BYTES`**（体积上限）、**`COMPANION_HOST_BUNDLE_EXEC_TIMEOUT_MS`**（`host_bundle.*` 子进程超时，默认 `300000`，范围约 `1000`～`3600000`）。

## 4. 两个模块（产品语义）

### 4.1 插件（本地计算等）

- **当前**：`POST /v1/compute/jobs` 已接；`type: "stub.ping"` 在内存中 **直接标记完成**；**`seam_repair`** 已接 **真实 Adapter**：从当前 **`projectId`** 的 Volume 读取 **`inputs`**（`{ objKey, textureKey, maskKey?, outputKey? }` 或规范 §5.1 式 `inputs[]` 角色 `mesh`/`texture`/`mask`），`multipart` 转发至 **WebSeamRepair** **`POST /api/repair`**（默认 **`http://127.0.0.1:8008/api/repair`**，见 **`COMPANION_SEAM_REPAIR_URL`**、**`COMPANION_SEAM_REPAIR_TIMEOUT_MS`**）；若设 **`outputKey`** 则将 PNG 写回 **`PUT` 同一路径语义** 的 asset。  
- **宿主插件包计算**：**`host_bundle.probe`** / **`host_bundle.exec`** 由 **`compute/hostBundleExecAdapter.ts`** 实现：仅根据 **`inputs.dirName`** 定位 **`host-bundles/<dir>/`**，读取 **`extracted/run.json`** 中对应段，在 **extracted** 根下解析 **`cwd`** 后 **`spawn`**（stdout/stderr 截断、超时见 **`COMPANION_HOST_BUNDLE_EXEC_TIMEOUT_MS`**）。**`capabilities.compute.jobTypes`** 含上述 `type`；管理页 **联调** Tab 与主站 **设置 → 本地伴侣** 均可提交（主站会附带当前 **`activeWorkspaceProjectId`** 作 **`projectId` 元数据**，伴侣执行逻辑不依赖）。  
- **后续**：**WS 进度**（见总规范 §5.3）、scratch 目录与 Job 取消的硬约束；Relay 可通过 **`COMPANION_RELAY_CMD`** 由宿主子进程承载（**§5**），长期再并入单进程。网站侧 **`services/companionClient/relay.ts`** 可从 **`/v1/capabilities.relay`** 读 M1 状态（不直连 WSS）。

#### 新增开源能力时的默认做法（通用）

- **优先“调用”**：在宿主新增一个 Adapter，通过 HTTP/子进程/SDK 调开源项目。  
- **少改上游源码**：除非遇到阻断 bug、必要特性或不可绕过的性能问题。  
- **网站不直连开源项目**：网站只提交 `Job`，由伴侣统一编排输入输出与资产落盘。  
- **文档同步**：每新增一个能力，补 4 件事：任务 `type`、`inputs/params`、环境变量、错误码。  
  - **宿主包 run.json**：约定见 **[`本地伴侣-插件与发行.md`](./本地伴侣-插件与发行.md)**（`schemaVersion: 1`、`probe` / `exec` 的 `command`/`cwd`/`env`）；实现见 **`hostBundleRunSpec.ts`** + **`hostBundleExecAdapter.ts`**。

### 4.2 仓库

- **Volume 根**：环境变量 **`COMPANION_VOLUME_ROOT`**；未设置时为 **`~/.assetcutter-companion/volume`**。  
- **项目布局**：`projects/<projectId>/manifest.json`、`assets/<key>/object`、`scratch/` 预留（与总规范 §4.2 一致；**manifest 单进程内单写者**）。  
- **`projectId` / `key`**：仅允许安全字符类 `[a-zA-Z0-9._-]` 等，防路径穿越。  
- **指标**：`/v1/repository/summary` 仍为卷根浅层；**catalog / 跨项目索引** 为 P1+。

## 5. 与 A-Driver `local-bridge` 的关系

- **A-Driver** 中的 `apps/local-bridge` 可继续承担 **Relay + WS** 等重逻辑；本包侧重 **主仓库可维护的宿主壳 + 双模块管理页 + 与网站一致的 HTTP 探测面**。  
- **默认端口均为 `18765`**：同一台机器上 **不要** 让两个进程 **同时绑定** 同一端口。推荐：**宿主仅 `local-companion` 占 `18765`**，通过 **`COMPANION_RELAY_CMD`** 拉起 `local-bridge` 子进程，并由宿主注入子进程 **`COMPANION_HTTP_PORT=0`**（默认）关闭子进程自带伴侣 HTTP，仅保留 WS 等（可用 **`COMPANION_RELAY_CHILD_HTTP_PORT`** 覆盖，`keep` 表示不覆盖）。  
- **长期**：单进程合并（pluginhost 加载 relay），见总规范 §11 与已决清单。

### 6.1 Electron 托盘壳（`companion-desktop`，M0）

**用语**：**本机管理页** 仍指 `local-companion` 在浏览器中提供的 **`http://127.0.0.1:<COMPANION_HTTP_PORT>/`**（高级调试、联调、完整 API 说明）；**日常主界面** 为桌面壳自带的 **小窗口**（`companion-desktop/shell/index.html`），**左侧图标栏**切换 **三页**：**首页**（连接状态 +「打开网站」+ `/v1/capabilities` 插件列表）、**工作台**（`BrowserView` 内嵌设置中的主站 `siteUrl`；**侧栏右键** 刷新 / 硬刷新 / 浏览器打开主站）与 **设置**（主站地址、**与网站配对**、存储、复制本机 API 根、浏览器打开管理页）。详见 **`docs/本地伴侣-桌面壳工作台与WebView方案.md`**。壳启动 **不再** 自动打开浏览器管理页；单独运行 `local-companion` 时默认亦 **不** 自动打开浏览器（需设 **`COMPANION_OPEN_BROWSER=1`** 恢复旧行为）。

**网站调起桌面壳**：安装并注册协议后，网站可使用链接 **`assetcutter-companion://open`**（主站「设置 → 本地伴侣」已提供「调起桌面伴侣」）；壳在 **second-instance** / **open-url（macOS）** 时聚焦或打开主窗口。开发期未安装协议时，仍以 **二次启动壳进程** 或托盘打开窗口为准。

**环境变量**：**`COMPANION_DESKTOP_NO_AUTO_SHELL=1`**：不自动弹出桌面小窗口（仅托盘）。**`COMPANION_OPEN_BROWSER`**：仅影响 **单独** 运行 `node local-companion` 时是否自动打开浏览器；壳子进程始终注入 **`COMPANION_OPEN_BROWSER=0`**。

1. **`local-companion/`** 与 **`companion-desktop/`** 各执行一次 `npm install`。  
2. 仓库根：`npm run companion-desktop:start`（或 `cd companion-desktop && npm start`）。  
3. 壳会设置 **`COMPANION_OPEN_BROWSER=0`** 并 `spawn` **`node --import tsx src/main.ts`**（工作目录为 `local-companion/`）；托盘菜单含 **「打开桌面窗口」**、**「在浏览器打开本机管理页」**、**「重新启动本地伴侣」** 等；**Windows 左键单击托盘** 打开 **桌面窗口**（非浏览器）。  
4. 自定义 Node 可设 **`COMPANION_NODE`**；二次启动同一壳会 **单实例**：聚焦已有 **主窗口**。

**配对（设置页）**：**不再**使用独立首次向导窗口。请在桌面壳 **设置 → 与网站配对** 填写 **本机通信密码** 与 **允许打开的网站地址**（落盘 **`userData/pairing-config.json`**，与向导时代一致）。**`userData`** 默认 **`%LOCALAPPDATA%\AssetCutterCompanion\sandbox\desktop-shell`**（沙盒根见 **`docs/本地伴侣-沙盒目录.md`**）。桌面壳启动 `local-companion` 时会在未显式配置环境变量的前提下自动注入配对变量。托盘菜单含 **状态行**、**「打开桌面窗口」**、**「在浏览器打开本机管理页」**、**「重新启动本地伴侣」** 等（无单独向导入口）。当 `local-companion` 启动失败/异常退出，或轮询 `GET /v1/runtime-status` 检测到 **Relay 已配置但未运行**、**401（配对不一致）**、**站点登录态失效** 时，托盘会弹出异常提示。正式 **开机自启勾选生效** 等仍按已决清单后续实现。

### 6.2 打包脚本（P1 基础）

- 根脚本：`companion-desktop:pack`、`companion-desktop:dist:win`、`companion-desktop:dist:portable`。  
- 重试脚本：`companion-desktop:dist:retry`（`scripts/companion-desktop-dist.ps1`，支持 `-UseMirror` 注入镜像变量）。  
- 发布预检脚本：`companion-desktop:release:check`（可选加 `-RequireSigning` / `-RequirePublishUrl`）。  
- `companion-desktop/package.json` 已补 `electron-builder` 基础配置（`appId`、`productName`、`nsis/portable` 目标；**产物根目录** **`dist/`**，便携 / 安装包 / pack 分 **`dist/portable`**、**`dist/installer`**、**`dist/pack`**）。  
- Windows **exe 命名**：**`AssetCutterCompanion-<version>-<buildTag>-x64.exe`**；`<buildTag>` 由 **`scripts/electron-build-with-suffix.cjs`** 注入，默认 **`yyyyMMdd-HHmmss`**，可用 **`COMPANION_ARTIFACT_SUFFIX`** 覆盖（见 **`companion-desktop/README.md`** §打包）。  
- 已实测：`companion-desktop:pack` 可产出 **`dist/pack/win-unpacked`**。  
- 在当前网络环境下，`dist:win` / `dist:portable` 可能因 `electron-builder-binaries`（如 `nsis-resources`）下载失败中断；**代码签名**仍须在发布机构建机上配置 `CSC_LINK` 等（见发布检查清单）。
- 发布流程清单见：`docs/本地伴侣-发布前检查清单.md`。

### 6.3 自动更新（M2 骨架，可选启用）

- 依赖：`companion-desktop` 已引入 **`electron-updater`**。  
- **环境变量 `COMPANION_UPDATE_FEED_URL`**：设为 **generic 更新根 URL**（与 `electron-builder` 发布的 `latest.yml` 同目录，见 [electron-updater generic](https://www.electron.build/auto-update)）。设置后壳会：约 **20s** 后静默检查一次更新；托盘菜单增加 **「检查更新…」**；发现新版本时弹窗询问是否下载，下载完成后可 **退出并安装**。  
- 未设置该变量时：**不**注册更新逻辑，菜单中亦无「检查更新」，避免开发期误连。
