## 1. 背景

当前资产预览已经从图片预览扩展到文本、视频、3D、高度 3D、资产集等多种内容，但整体体验仍偏向“图片预览壳上叠加类型分支”。如果继续给每种资产类型分别加工具栏、菜单、任务面板和结果区，预览界面会很快变重：

- 顶部工具栏会随着资产类型切换频繁变化，用户很难形成稳定心智。
- 3D、图片、视频等类型都有大量专属操作，全部平铺会压缩预览空间。
- 高级功能往往需要输入参数、发起任务、等待进度、生成新资产，不能只作为普通按钮处理。
- 生成结果需要保存、替换、另存为新资产、加入工作流或继续作为下游输入，不能散落在各个 viewer 内部。
- 后续若接入更多 AI 能力、供应商和本地伴侣能力，预览层会变成新的业务分支堆积点。

本改造目标是把资产预览升级为一个稳定的“资产工作台”：预览壳负责通用体验，资产类型适配器声明各自能做什么，高级能力通过统一执行层完成输入、运行、进度和输出回填。

一句话原则：

> 预览壳保持稳定，资产类型只注入渲染器和能力，高级生成走统一能力执行链路。

## 2. 目标与非目标

### 2.1 目标

1. 建立统一的 `AssetPreviewShell`，承载预览布局、顶部工具栏、右侧面板、状态、任务进度和输出结果。
2. 为每种资产类型建立 `AssetPreviewAdapter`，由 adapter 声明预览组件、快捷操作、面板分组和可用能力。
3. 建立 `AssetCapability` 协议，让高级功能以“输入参数 → 执行任务 → 输出资产”的方式注册和运行。
4. 避免把每种资产的所有功能都塞到顶部工具栏，改为“通用工具栏 + 类型快捷入口 + 右侧面板 + 更多菜单 + 结果区”的分层信息架构。
5. 支持后续图片、3D、视频、音频、文本等资产类型逐步追加高级功能，而不持续改大预览壳。
6. 与现有 `ImagePreviewOverlay`、`components/preview/*`、工作流资产模型兼容，允许渐进迁移。

### 2.2 非目标

1. 不在第一阶段一次性重写所有预览 UI。
2. 不把所有图片工具、3D 工具和视频工具同时迁入新架构。
3. 不强制立刻改变存量 `WorkflowAsset` 数据结构。
4. 不在首版实现完整能力编排、批处理和多资产组合输入。
5. 不把 3D viewer 内部的渲染逻辑塞进通用预览壳。

## 3. 总体架构

```text
AssetPreviewShell
  AssetPreviewTopBar
    CommonActions
    PrimaryTypeActions
    MoreActionsMenu

  AssetPreviewBody
    AssetPreviewTree / VariantRail
    AssetPreviewViewport
      AdapterPreviewComponent
    AssetPreviewInspector
      MetadataSections
      TypeSettingSections
      CapabilityEntries

  CapabilityPanel
    InputForm
    RunStatus
    ProgressDetail

  OutputTray
    GeneratedAssets
    Save / Replace / AddToProject / UseAsInput
```

### 3.1 三层分工

| 层级 | 职责 | 不负责 |
|---|---|---|
| `AssetPreviewShell` | 布局、通用操作、状态、任务入口、结果展示、快捷键、错误态 | 具体媒体渲染、具体 AI/工具调用 |
| `AssetPreviewAdapter` | 按资产类型声明 viewer、快捷操作、设置面板、能力列表 | 运行任务、持久化结果、跨类型流程 |
| `AssetCapability` | 定义高级功能的输入、执行、输出、可用条件 | 大预览布局、按钮位置、全局资产导航 |

## 4. 预览壳设计

### 4.1 `AssetPreviewShell`

`AssetPreviewShell` 是资产大预览的稳定外壳。它只理解当前资产、当前版本、当前类型和当前能力运行状态，不理解“线框怎么渲染”“法线图怎么生成”“视频怎么抽帧”。

建议职责：

- 打开 / 关闭 / 焦点管理 / Esc。
- 当前资产、当前 variant、当前 adapter 的解析。
- loading / error / missing / unsupported / empty 状态。
- 顶部工具栏布局和操作分组。
- 中心预览区尺寸和滚轮/快捷键仲裁。
- 右侧 inspector 的挂载和折叠。
- 能力面板的打开、输入表单渲染、运行状态展示。
- 输出结果托盘展示。
- 生成结果保存为新资产、替换当前资产、加入项目、继续作为输入。

建议不放入：

- Three.js 场景、相机、材质、灯光实现。
- 图片裁切、抠图、分割、标注算法。
- 视频播放器内部控制。
- 供应商 API 直连。
- 本地伴侣具体文件写入逻辑。

### 4.2 顶部工具栏

顶部工具栏需要稳定，避免每种资产类型都换一整排按钮。

建议分为三类：

| 区域 | 放什么 | 示例 |
|---|---|---|
| 通用操作 | 所有资产都有的动作 | 关闭、下载、复制链接/引用、适配窗口、全屏、更多 |
| 类型快捷操作 | 当前类型最常用的 3-5 个动作 | 3D 重置视角、网格开关、截图；图片适配、标注；视频播放/暂停 |
| 更多菜单 | 低频或高级动作入口 | 显示设置、导出选项、调试信息、高级生成 |

顶部工具栏不是类型控制台。低频功能和需要参数的功能应进入右侧面板、弹窗或能力面板。

### 4.3 右侧面板

右侧面板用于承载当前资产的详情、类型设置和高级能力入口。

建议结构：

```text
PreviewInspector
  AssetSummarySection
  VariantSection
  TypeSettingsSection
  CapabilitySection
  SourceAndStorageSection
```

其中 `TypeSettingsSection` 由 adapter 注入，例如 3D 的灯光、背景、材质显示模式；图片的标注、裁切、透明背景；视频的抽帧、字幕、码率信息。

### 4.4 输出结果区

高级功能生成的结果不要只用 toast 表示。应有统一的 `OutputTray`：

- 展示本次运行产生的资产。
- 支持快速预览输出。
- 支持保存为新资产。
- 支持替换当前资产或当前 variant。
- 支持加入资产集 / 工作流输入。
- 支持失败重试和查看错误。

## 5. 资产类型适配器

### 5.1 Adapter 协议

建议定义：

```ts
export type AssetPreviewAdapter = {
  type: WorkflowAssetKind;
  label: string;
  PreviewComponent: React.ComponentType<AssetPreviewComponentProps>;
  getToolbarActions?: (context: AssetPreviewContext) => PreviewAction[];
  getInspectorSections?: (context: AssetPreviewContext) => InspectorSection[];
  getCapabilities?: (context: AssetPreviewContext) => AssetCapabilityRef[];
  getInputPolicy?: (context: AssetPreviewContext) => PreviewInputPolicy;
};
```

其中：

- `PreviewComponent` 只负责中心预览。
- `getToolbarActions` 只返回少量高频快捷动作。
- `getInspectorSections` 返回类型设置和信息面板。
- `getCapabilities` 返回当前资产可运行的高级能力。
- `getInputPolicy` 声明滚轮、快捷键、拖拽等输入是否由 viewer 接管。

### 5.2 Adapter 注册表

建议引入注册入口：

```ts
export const assetPreviewAdapterRegistry = {
  image: imagePreviewAdapter,
  model3d: model3dPreviewAdapter,
  video: videoPreviewAdapter,
  audio: audioPreviewAdapter,
  text: textPreviewAdapter,
  file: filePreviewAdapter,
};
```

注册表负责从 `WorkflowAssetKind` 或 `WorkflowAssetVariant.kind` 找到对应 adapter。首版可以先覆盖图片和 3D，其他类型保留降级 adapter。

### 5.3 3D Adapter 示例

```ts
export const model3dPreviewAdapter: AssetPreviewAdapter = {
  type: 'model3d',
  label: '3D',
  PreviewComponent: Model3DPreview,
  getToolbarActions: () => [
    { id: 'reset-camera', placement: 'primary' },
    { id: 'toggle-grid', placement: 'primary' },
    { id: 'capture-preview', placement: 'primary' },
    { id: 'display-mode', placement: 'menu' },
  ],
  getInspectorSections: () => [
    { id: 'model-info' },
    { id: 'view-settings' },
    { id: 'lighting' },
    { id: 'material-display' },
    { id: 'model-capabilities' },
  ],
  getCapabilities: () => [
    { capabilityId: 'generate-lod' },
    { capabilityId: 'bake-texture' },
    { capabilityId: 'optimize-mesh' },
    { capabilityId: 'generate-model-preview-image' },
  ],
  getInputPolicy: () => ({ captureGlobalWheel: true }),
};
```

## 6. 能力系统设计

### 6.1 能力定义

高级功能应以能力形式存在，而不是写在某个 viewer 组件内部。

```ts
export type AssetCapability = {
  id: string;
  label: string;
  description?: string;
  assetTypes: WorkflowAssetKind[];
  inputSchema?: CapabilityInputSchema;
  outputKinds: WorkflowAssetKind[];
  availability?: (context: CapabilityContext) => CapabilityAvailability;
  run: (context: CapabilityRunContext) => Promise<CapabilityRunResult>;
};
```

能力需要声明：

- 支持哪些资产类型。
- 需要哪些输入参数。
- 会产生什么类型的输出。
- 当前资产是否满足运行条件。
- 如何执行任务。
- 输出如何被预览壳消费。

### 6.2 输入 Schema

首版输入 Schema 不需要做成复杂低代码系统，但要能覆盖常见控件：

```ts
export type CapabilityInputSchema = Array<
  | { name: string; type: 'text'; label: string; defaultValue?: string; required?: boolean }
  | { name: string; type: 'number'; label: string; defaultValue?: number; min?: number; max?: number; step?: number }
  | { name: string; type: 'boolean'; label: string; defaultValue?: boolean }
  | { name: string; type: 'select'; label: string; options: Array<{ label: string; value: string }> }
  | { name: string; type: 'asset'; label: string; acceptedKinds: WorkflowAssetKind[] }
>;
```

UI 渲染规则：

- `select` 不使用原生 `<select>`，沿用 `CustomDropdown` 或现有自定义下拉。
- 布尔值使用 toggle / checkbox。
- 数值使用 slider、stepper 或 number input。
- 低频高级参数默认折叠。

### 6.3 执行上下文

```ts
export type CapabilityRunContext = {
  asset: WorkflowAsset;
  variant: WorkflowAssetVariant;
  input: Record<string, unknown>;
  source: 'preview_toolbar' | 'preview_inspector' | 'more_menu';
  projectId?: string;
  workflowId?: string;
  signal?: AbortSignal;
  onProgress?: (event: CapabilityProgressEvent) => void;
};
```

执行层应统一处理：

- 任务开始。
- 输入校验。
- 供应商 / 本地伴侣 / 浏览器内处理分流。
- 进度事件。
- 取消。
- 失败重试。
- 结果标准化。
- 资产回填。

### 6.4 输出协议

```ts
export type CapabilityRunResult = {
  status: 'succeeded' | 'failed' | 'cancelled';
  outputs?: CapabilityOutputAsset[];
  error?: {
    code?: string;
    message: string;
    retryable?: boolean;
  };
};

export type CapabilityOutputAsset = {
  kind: WorkflowAssetKind;
  label: string;
  url?: string;
  objectKey?: string;
  companionKey?: string;
  mimeType?: string;
  posterUrl?: string;
  meta?: Record<string, unknown>;
};
```

预览壳拿到输出后，不直接假设它是图片，而是按 `kind` 进入对应 adapter 预览或结果托盘。

## 7. 界面信息架构

### 7.1 默认露出原则

默认露出少量高频操作，其他都进入面板或菜单。

| 类型 | 顶部快捷操作建议 | 右侧/更多承载 |
|---|---|---|
| 图片 | 适配、标注、裁切、下载、更多 | 抠图、超分、格式转换、法线图生成、局部重绘 |
| 3D | 重置视角、网格、显示模式、截图、更多 | 线框、灯光、材质模式、LOD、重拓扑、贴图烘焙、UV |
| 视频 | 播放/暂停、静音、截图、更多 | 抽帧、字幕、压缩、转码、分镜提取 |
| 音频 | 播放/暂停、静音、波形适配、更多 | 降噪、人声分离、转码、节拍/字幕分析 |
| 文本 | 复制、下载、加入输入、更多 | 改写、翻译、摘要、结构化解析、生成提示词 |

### 7.2 高级能力入口

高级能力可以出现在三个位置：

1. 顶部更多菜单：适合低频但明确的命令。
2. 右侧能力分组：适合需要用户看参数、看说明、看运行条件的功能。
3. 输出结果区：适合对生成结果继续处理，例如“继续优化”“生成贴图”“转为视频”。

不要把需要输入参数的高级功能伪装成一个普通 toolbar 按钮。按钮最多打开能力面板。

## 8. 首期落地建议

### 8.1 P0：建立壳和协议

目标：先让结构跑通，不追求一次性迁完所有功能。

建议范围：

1. 新增 `AssetPreviewShell` 骨架。
2. 新增 adapter 类型定义和 registry。
3. 用图片和 3D 作为首批 adapter。
4. 让 `ImagePreviewOverlay` 可以作为图片 adapter 的内部 viewer 继续复用。
5. 让 3D viewer 只暴露少量快捷动作：重置视角、网格、截图、更多。
6. 新增最小 `CapabilityPanel`，支持输入表单、运行中、成功、失败。
7. 新增 `OutputTray`，支持展示输出和保存为新资产。

### 8.2 P1：迁移高频功能

建议优先迁移低风险功能：

- 图片：下载、复制、裁切入口、抠图入口。
- 3D：重置视角、网格、背景/显示模式、截图。
- 文本：复制、下载、加入输入。
- 视频：截图、抽帧入口。

### 8.3 P2：接入高级生成

开始接入真正“输入 → 任务 → 输出”的能力：

- 图片生成法线图。
- 图片超分。
- 3D 生成 LOD。
- 3D 贴图烘焙。
- 视频抽帧并生成图片资产。
- 文本结构化解析并生成文本/JSON 资产。

### 8.4 P3：批处理与跨资产输入

在单资产能力链路稳定后，再考虑：

- 多资产输入。
- 批量运行。
- 能力链编排。
- 输出自动加入资产集。
- 与工作流节点能力区完全打通。

## 9. 与现有代码的关系

当前已有基础：

- `components/preview/PreviewShell.tsx` 已经具备预览子系统雏形。
- `components/preview/types.ts` 已有 `ImagePreviewLayoutMode`、`PreviewDescriptor`、`previewPolicyForMode()`。
- `components/preview/registry.tsx` 已承载图片类 viewer 的懒加载注册。
- `components/ImagePreviewOverlay.tsx` 仍是当前大图预览主入口。
- `WorkflowAsset` 已包含图片、文本、3D、视频结果槽位等存量字段。

建议迁移方式：

1. 不立即删除 `ImagePreviewOverlay`。
2. 先把它作为 `imagePreviewAdapter.PreviewComponent` 或兼容 viewer 使用。
3. 新增 `resolveWorkflowAssetKind()`、`resolveWorkflowAssetVariants()` 等解析函数，把旧字段归一为预览壳能理解的资产类型和 variant。
4. 让新 `AssetPreviewShell` 在小范围入口试运行，再逐步替换旧大预览入口。
5. 每迁移一种类型，都补齐 adapter 的 UI 合同和降级状态。

## 10. 3D 预览专项建议

3D 是最适合验证新架构的类型，因为它既有 viewer 控制，又有大量潜在高级能力。

首版 3D 不建议平铺大量功能。建议：

顶部快捷：

- 重置视角。
- 网格开关。
- 显示模式。
- 截图。
- 更多。

右侧设置：

- 模型信息：格式、文件数量、尺寸、来源。
- 视图设置：背景、网格、坐标轴、包围盒。
- 灯光设置：默认光、环境光、阴影。
- 材质显示：原材质、灰模、线框、法线、UV。
- 高级能力：LOD、优化、贴图烘焙、预览图生成。

能力示例：

```ts
{
  id: 'generate-lod',
  label: '生成 LOD',
  assetTypes: ['model3d'],
  outputKinds: ['model3d'],
  inputSchema: [
    { name: 'targetRatio', type: 'number', label: '目标面数比例', defaultValue: 0.5, min: 0.1, max: 1, step: 0.05 },
    { name: 'preserveUv', type: 'boolean', label: '保留 UV', defaultValue: true },
  ],
  run: async (context) => {
    return runModelLodCapability(context);
  },
}
```

## 11. 状态与降级

所有资产类型和能力都应走统一状态：

| 状态 | 含义 | UI |
|---|---|---|
| `ready` | 可正常预览或运行 | 正常 viewer / 正常按钮 |
| `loading` | 资源加载中 | 骨架屏 / loading |
| `missing` | 文件或 key 缺失 | 缺失说明 + 恢复/下载入口 |
| `unsupported` | 当前环境不支持预览 | 文件信息 + 下载入口 |
| `error` | 加载或执行失败 | 错误摘要 + 重试 |
| `running` | 能力执行中 | 进度、取消、日志摘要 |
| `succeeded` | 能力成功 | 输出结果托盘 |
| `failed` | 能力失败 | 错误、重试、保留输入 |

降级策略需要由预览壳统一展示，adapter 只提供错误原因和建议动作。

## 12. 风险与约束

1. **壳层过度抽象**：不要在首版做过重插件系统，先以 TS 类型和 registry 满足当前扩展。
2. **工具栏膨胀**：严格限制顶部快捷动作数量，需要参数的能力只打开面板。
3. **旧字段兼容复杂**：通过 resolver 统一旧字段，不在 viewer 内继续散落判断。
4. **生成结果回填不一致**：所有 capability 输出必须走统一 `CapabilityOutputAsset`。
5. **本地 URL 持久化风险**：输出资源持久化时遵守跨设备 URL 规则，不写死 `localhost`、`127.0.0.1` 或机器 IP。
6. **直接存储访问风险**：新 UI 状态和偏好不要直接调用 `localStorage` / `sessionStorage`，使用 `services/clientPersist.ts` 或已有 store。
7. **3D 性能风险**：3D viewer 的渲染、dispose、ResizeObserver、纹理释放仍归 viewer 自己负责，预览壳不介入。

## 13. 验收标准

P0 完成时应满足：

- 打开资产预览时看到稳定的外壳，而不是每种类型独立弹窗。
- 图片和 3D 至少各有一个 adapter。
- 3D 顶部只显示少量快捷操作，高级设置进入右侧或更多。
- 至少一个能力可以通过 `CapabilityPanel` 收参数、运行、展示结果。
- 生成输出可以进入 `OutputTray`，并能保存为新资产或继续预览。
- 缺资源、加载失败、不支持预览时走统一降级态。
- 旧 `ImagePreviewOverlay` 仍可兼容运行，不影响现有大图预览。

## 16. 2026-07-22 UI 修正决策：工作流预览不重复绘制壳层工具栏

在 P0/P1 首轮接入后，真实工作流预览界面出现了左上角 `AssetPreviewShell` 工具栏与现有预览工具栏、右上角通用操作栏重复的问题。图片、文本、视频、3D 等预览类型已经在当前大预览壳、中心工具栏、右上通用操作栏或类型自身控制区里有可用入口；新壳层不应再绘制一套不完整的可见操作栏。

当前落地原则：

- 工作流大预览继续以 `ImagePreviewOverlay`、中心工具栏、右上通用操作栏和类型自身控制区作为操作入口和视觉来源。
- `AssetPreviewShell` 暂不挂载到工作流大预览路径，避免留下“各类型也走新壳层工具栏，只是隐藏”的错误心智。
- `AssetPreviewShell`、adapter、capability panel、output tray 先作为能力系统实验件保留，不作为当前可见预览 chrome。
- P2 高级能力接入时，不把能力入口简单堆到新的左上角工具栏；应优先接入现有工具栏的“更多”、详情区、右侧面板、底部输入区或类型专属控制区。

这条决策的重点是：预览壳不是要替换已经稳定的工作流预览 chrome。后续每个资产类型接能力时，先判断该类型在现有预览体系中应该挂在哪个入口；只有当某个全新预览场景没有成熟 chrome 时，才重新评估是否启用壳层工具栏。
