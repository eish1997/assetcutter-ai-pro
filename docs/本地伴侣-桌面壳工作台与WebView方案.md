# 桌面壳 · 工作台（WebView）与侧边导航 — 开发规格

本文细化 **Electron 桌面壳**（`companion-desktop/`）内嵌 **主站网页** 的方案，以及将现有 **底部文字标签** 改为 **左侧图标导航**，并新增 **「工作台」** 一页。  
**定位**：实施前规格（产品交互 + 技术选型 + 改造清单）；与总览 `**[本地伴侣-本地程序开发.md](./本地伴侣-本地程序开发.md)`**、已决清单 `**[本地伴侣-待决策清单与建议.md](./本地伴侣-待决策清单与建议.md)`** 对齐。

---

## 1. 背景与目标


| 目标              | 说明                                                                                                                                                                   |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **工作台**         | 在桌面小窗口内提供一页 **「工作台」**，用 **WebView**（Chromium 子表面）加载 **与设置里「主站地址」完全相同的 `siteUrl`**（见 **§4.3a**），网页端 **照常开发、部署**；用户刷新或下次打开即跟线上版本（受 HTTP 缓存 / Service Worker 策略影响，见下文）。 |
| **导航改版**        | 将当前 `**shell/index.html`** 底部 `**nav.shell-nav`** 的「首页 / 设置」**横向文字标签**，改为 **窗口左侧纵向图标栏**（仅图标为主，窄条）；**新增第三个入口：工作台**。                                                   |
| **非目标（首版可不做的）** | 壳内多标签同时挂多个不同域名；在 WebView 内嵌 `local-companion` 管理页（仍可通过托盘「浏览器打开管理页」或设置区按钮）。                                                                                           |

## 2. 现状摘要（便于对照改造）


| 项          | 当前实现                                                                                                                                                                                               |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **壳窗口**    | `companion-desktop/main.cjs` 创建 `BrowserWindow`，加载 `shell/index.html`。                                                                                                                             |
| **导航**     | `companion-desktop/shell/index.html`：**左侧 `nav.shell-sidebar`** 三图标（首页 / 工作台 / 设置）；底部标签已移除。                                                                                                        |
| **主站 URL** | 设置页读写 `**companion-shell-settings.json`** 的 `siteUrl`；首页「打开网站」走 `**shell.openExternal`**；**工作台** 由主进程 `**BrowserView.loadURL(siteUrl)`**（`main.cjs`）。                                              |
| **CSP**    | `shell/index.html` 头部 `**Content-Security-Policy`** 含 `**connect-src 'none'`**，与壳内 **自行 fetch 127.0.0.1** 的探测逻辑需继续兼容；**内嵌任意 https 主站** 若用 `<iframe>` 会受 **frame-ancestors** 等限制，**不推荐 iframe 整站**。 |

## 3. 用户交互（产品）

### 3.1 布局

- **整体**：标题栏不变；**主内容区** = **左侧图标栏（固定窄宽）** + **右侧内容面板（flex 占满剩余宽度）**。
- **左侧栏**：
  - **宽度**：建议 **52～64px**（触控友好可略增）；**仅图标**，不默认显示文字标签（避免与窄窗口冲突）。
  - **条目（自上而下）**：**首页** → **工作台** → **设置**（顺序可按产品再调；建议 **工作台夹在中间**，符合「先状态、再干活、最后配置」）。
  - **交互**：单击切换页面；当前页 **高亮**（背景块或左边条 + 图标着色，与现有 `--accent` 一致）。在 `**nav.shell-sidebar`** 上 **右键** 弹出 **工作台相关** 菜单（刷新工作台、硬刷新、在浏览器中打开主站）。
  - **可访问性**：每个按钮保留 `**aria-label`** / `**title`**（悬停显示「首页」「工作台」「设置」）。
- **底部**：**移除**原底部 `**nav.shell-nav`**（或改为仅占位 0 高度，避免 `body` 仍留 `padding-bottom: 56px` 造成浪费；改版时一并调整 `**body` padding**）。

### 3.2 各页职责


| 页面      | 内容                                                                                                                                               | 备注                                                        |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------- |
| **首页**  | 保持现有：伴侣状态、打开网站（外置浏览器）、内置服务表、宿主插件包区等。                                                                                                             | 「打开网站」仍可保留；与「工作台」内嵌形成 **外置 / 内置** 双入口。                    |
| **工作台** | 全幅（除左侧栏）展示 **WebView 中的主站**；**入口 URL = 设置中的主站地址**（`siteUrl`），无单独「工作台 URL」配置。**刷新 / 硬刷新 / 在浏览器中打开主站** 在 `**nav.shell-sidebar` 上右键** 弹出菜单（无顶栏工具条）。 | 与 `**siteUrl`** 同源策略见 **§4.4**。                           |
| **设置**  | 保持现有表单与逻辑不变。                                                                                                                                     | 修改主站 URL 后，工作台应 **reload** 或提示用户刷新（见 **§4.3**、**§4.3a**）。 |


### 3.3 图标建议（实现期再定稿）

- 首页：房屋 / 仪表盘类（与当前 `⌂` 一致可继续用 Unicode 或换 SVG）。
- 工作台：窗口 + 地球或「layout」类图标，语义为「主站」。
- 设置：齿轮（与当前 `⚙` 一致）。

## 4. 技术方案

### 4.1 推荐：**主进程 `BrowserView` + IPC**

**理由**：

- **不依赖** `shell/index.html` 的 CSP 放行第三方 `connect-src` / `frame-src`；WebView 与壳内静态页 **分层安全**。
- 不受主站 `**X-Frame-Options` / CSP frame-ancestors** 限制（整页导航在独立 **BrowserView** 中，而非被嵌入为子 frame）。
- 布局控制清晰：主进程根据窗口 `**contentBounds`** 减去 **左侧栏宽度**，`**setBounds`** 定位 BrowserView；切换离开展示页时可 `**mainWindow.removeBrowserView`** 或 `**setBounds` 高宽为 0** 隐藏。

**流程概要**：

1. `preload-shell.cjs` 暴露例如 `**shell:setShellView(view)`**（`'home' | 'workbench' | 'settings'`）或细分 `**shell:workbenchNavigate`**。
2. `shell/index.html` 左侧按钮点击 → `**ipcRenderer.invoke**` 通知主进程。
3. `main.cjs`：
  - `view === 'workbench'`：创建或复用 `**BrowserView**`，`webPreferences` 建议 `**nodeIntegration: false**`、`**contextIsolation: true**`；`**partition**` 使用 **独立 persistent partition**（如 `persist:assetcutter-workbench`）以便登录态与壳其它能力隔离。
  - 读取当前 `**siteUrl`**（与现有 `readShellSettings()` 一致），`**view.webContents.loadURL(siteUrl)`**。
  - `view === 'home' | 'settings'`：从窗口移除或隐藏 BrowserView，壳内 HTML 通过现有机制显示对应 `div.view`（或由主进程发 IPC 让渲染进程切换 `hidden` 类）。

**与「网页自动更新」**：BrowserView 加载的是 **远程 https**，行为与 Chrome 打开同一 URL 一致；**部署即生效**取决于缓存；可通过 **侧栏右键菜单** 触发 **硬刷新（绕过缓存）**（`webContents.reloadIgnoringCache()`）。

### 4.2 备选：`<webview>` 标签

- 需在 `**BrowserWindow` `webPreferences`** 中 `**webviewTag: true`**，并收紧 **preload**、**CSP**。
- 与当前 `**connect-src 'none'`** 的壳页探测逻辑并存时，要仔细区分 **谁** 发起网络请求。
- **结论**：可作为二期简化；**首版优先 BrowserView**。

### 4.3 **siteUrl** 变更与工作台

- 设置页保存 `**siteUrl`** 后，若当前正在展示工作台，主进程应 `**loadURL` 新地址** 或对 BrowserView `**reload`**。
- 若工作台未打开，仅记录配置即可，下次进入工作台再加载。

### 4.3a 主站地址与工作台 URL（开发约定）

- **单一数据源**：工作台 `**BrowserView.loadURL(...)` 必须使用** 与首页「打开网站」、设置页「主站 → 地址」**同一字段**——`**readShellSettings().siteUrl`**（落盘 `**companion-shell-settings.json`**）。**不设**「工作台专用 URL」或第二套输入框，避免联调时两处不一致。
- **语义**：用户在设置里 **主站地址写什么，工作台就打开什么**；本地开发把主站指到本机 dev server 即可在壳内验页面，无需改壳代码。
- **开发期示例**（按你本机实际端口填写）：
  - Vite 默认：`http://localhost:5173`
  - 其他框架 / 端口：`http://127.0.0.1:3000` 等
  - 与浏览器能直接打开的地址 **保持一致**（含 `http://` / `https://`）；末尾 `**/` 可有可无**，若主站路由对 base 敏感，建议与日常开发习惯统一。
- **与 `local-companion` 配对**：进入工作台时，桌面壳会按当前 **`siteUrl` 的 origin** 自动更新 `pairing-config`（并注入与网站 `companionLocalPrefs` 一致的 `localStorage` 键），一般 **无需** 再手工在壳设置里填「允许的网站地址」。若本机另有独立启动的伴侣进程，须自行重启以使新 `COMPANION_ALLOWED_ORIGINS` 生效。工作台内页面请求 `**127.0.0.1:<伴侣端口>`** 时仍须满足 `**accessGate`** 的 Origin/Bearer 规则，与在系统浏览器里打开主站 **同一套规则**。
- **安装包默认**：未保存过设置时，`main.cjs` 中 `**defaultShellSiteUrl()`** 的默认值仍作用于 `**siteUrl`**；工作台与「打开网站」一致使用该默认，直至用户在设置中覆盖。

### 4.4 安全（与已决模型对齐）


| 点                          | 建议                                                                                                                             |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| **仅允许导航到配置的 siteUrl 及其同源** | 监听 `**will-navigate` / `did-navigate-in-page`**（或 `**setWindowOpenHandler`**），对 非同源 外链可选择 `**openExternal**` 或拦截，避免钓鱼域在壳内全屏展示。 |
| **本机伴侣 API**               | 工作台里的网页与用户在浏览器访问主站 **一致**；**Bearer Token、配对** 仍走主站与 `**local-companion`** 既有链路，**不在壳内注入 Node**。                                |
| **DevTools**               | 仅开发包或环境变量开启，避免生产默认暴露。                                                                                                          |


### 4.5 Windows / 高分屏

- `**resize` / `move`** 时重算 BrowserView `bounds`，避免侧栏缩放后 WebView 错位。

## 6. 风险与对策


| 风险                                 | 对策                                                                                                       |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------- |
| 主站登录依赖 **第三方 OAuth 弹窗**            | `**setWindowOpenHandler`** 中对外部授权 URL 使用 `**openExternal`** 或允许 `**nativeWindow: true**` 子窗口（按主站实际行为选型）。 |
| **Service Worker** 导致「已部署但用户仍见旧页** | **侧栏右键** 使用 **硬刷新**；文档上对用户说明与浏览器一致。                                                                      |
| **混合内容** 或 **证书错误**                | WebView 内 `**certificate-error`** 策略与浏览器一致，生产环境不自动忽略。                                                    |
