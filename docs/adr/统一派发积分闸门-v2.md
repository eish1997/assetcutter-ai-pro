# ADR：统一派发积分闸门 v2

**状态**：已实施（2026-07-07，Wave A～C MVP）  
**取代/演进**：`aiBillingGate` v1（UI 预扣 + 分散 assert + L2 手标 `meta.byok`）  
**关联**：
- `docs/adr/统一积分制-手动发放-v1.md`
- `docs/adr/计费与套餐-v1.md`（P4 BYOK 只记量不计价）
- `docs/adr/可观测性与计费统一架构-v1.md`
- `docs/错题本.md`（BYOK L2 误扣等）

---

## 1. 背景与问题

v1 已引入 `aiBillingGate.plan*Routes` 与 `traceUnifiedAiCall`，但仍存在：

| 问题 | 后果 |
|------|------|
| **L1 多层重复** | UI 预扣、`traceUnifiedAiCall`、`getDialogTextResponse` 内 assert、proxy-bundle 各自 precharge |
| **L2 与 L1 脱节** | BYOK 依赖各 `emit*` 手动 `meta.byok`，漏标即误扣（OpenAI 生图已踩坑） |
| **出口不统一** | 对话/贴图/擂台 re-export 无 trace；腾讯 3D 不经 gateway |
| **3D 路由粗糙** | `workflow_generate_3d` 单 jobKind，Tripo/腾讯规则不一致 |
| **上下文脆弱** | 扣费决策靠 `correlationContext` peek，并发/异步易串台 |

**目标**：每次 **向上游发请求前** 单点决策；UI **不预扣**；L2 **继承同一决策**。

---

## 2. 产品拍板（冻结）

| ID | 决策 |
|----|------|
| **G1 闸门时机** | **每次** `upstream HTTP` 前（理解步、生图步、3D 建任务等各算一次） |
| **G2 UI 入队** | **策略 B**：只读检查「余额 ≥ 当前步 platform 最低消耗」；**不预扣**；不够则禁止入队 |
| **G3 UI 文案** | 展示 **分步明细**（例：理解 ≈ X 积分｜生图：自备 Key）；platform 写「至少 X，按用量结算」 |
| **G4 BYOK** | 自备 Key **不扣本站积分**；**仍记用量**（`creditsCharged=0`，`meta.byok=true`） |
| **G5 Tripo 3D** | 有 Tripo Key → **BYOK**（不扣积分）；代理 **限速**（见 §7） |
| **G6 腾讯 3D** | 有 SecretId/Key → **BYOK**（与 Tripo 同线） |
| **G7 即梦/生视频/vertex** | **platform**，扣本站积分 |
| **G8 失败** | 仅 **成功** L2 扣费（沿用 P5）；reserve/precharge **失败须 release** |
| **G9 并发** | 入队 B 不防并发 tab；**执行层 reserve** 防双花 |

## 3. 核心概念

### 3.1 `BillingRouteKind`

```ts
type BillingRouteKind = 'platform' | 'byok' | 'exempt';
```

**唯一规则源**：`shared/billingRoute.ts`（或 `services/billingRoute.ts`，前后端同逻辑）

```ts
resolveBillingRoute(input: {
  jobKind: string;
  registryId?: string;
  role?: 'text' | 'image';
  generate3dProvider?: 'tripo' | 'tencent';
  hasTripoApiKey?: boolean;
  hasTencentCreds?: boolean;
}): BillingRouteDecision
```

| 输入 | routeKind |
|------|-----------|
| `pickBinding` → `vertex-proxy` | platform |
| `pickBinding` → BYOK channel | byok |
| `generate3dProvider=tripo` + Key | byok |
| `generate3dProvider=tencent` + 密钥 | byok |
| 即梦 / 生视频 jobKind | platform |

> **禁止**在 `emit*`、`WorkflowSection`、`geminiService` 内重复写 BYOK 判定。

### 3.2 `BillingDecision`（显式传递，不依赖全局 peek）

```ts
type BillingDecision = BillingRouteDecision & {
  jobKind: string;
  registryId: string;
  role: 'text' | 'image';
  channel?: ChannelId;
  minCredits: number;           // platform 时 >0
  platformReserve?: PlatformReserve; // 见 §4
};

type PlatformReserve = {
  reserveKey: string;
  estimatedCredits: number;
  release: (outcome: 'success' | 'failed') => Promise<void>;
};
```

**硬约束**：`runMeteredAiCall` → `fn()` → `emitMeteredUsage({ billingDecision })` **同一条调用链传参**；`correlationContext` 仅作审计附加。

### 3.3 两层职责划分

| 层 | 模块 | 职责 |
|----|------|------|
| **规划（只读）** | `aiBillingGate.plan*Routes` | UI 估算、入队 B 检查、分步明细 |
| **派发（执行）** | `aiDispatchGate.gateBeforeUpstream` | 登录、reserve、拒绝 |
| **结算** | `pipeline.emitMeteredUsage` | 读 `billingDecision`；platform 扣费；byok 记量 |

## 4. 执行层：单点闸门 + Reserve 策略

### 4.1 唯一入口

```text
unifiedAiGateway.runMeteredAiCall(params, fn)
  → decision = resolveBillingRoute(params)
  → if platform: reserve = acquirePlatformReserve(decision)
  → await fn({ billingDecision: decision })
  → on success: emitMeteredUsage({ billingDecision, reading })
  → finally: reserve?.release(outcome)
```

**替换** `traceUnifiedAiCall` 命名；所有 AI 导出（含 dialog/texture/arena/腾讯 3D）必须经此包装。

### 4.2 `acquirePlatformReserve`（合并 proxy-bundle，禁止双轨）

| 上游类型 | reserve 实现 | 说明 |
|----------|--------------|------|
| **vertex-proxy**（bulk/async） | 现有 `getCreditsProxyRequestHeaders` → `/api/auth/credits-proxy-bundle`（内部 `prechargeCredits`） | **gate 内调用**，不在 `geminiService` 散落 |
| **即梦** | 服务端 `assertJimengCreditsGate`（保持） | 客户端 gate 可 no-op，以 server 为准 |
| **生视频 / Tripo 以外 task** | `prechargeCredits(minCredits, scopeKey)` 或短 TTL reserve | scopeKey = `correlationId` |
| **byok / exempt** | 无 reserve | 直接放行 |

> **ADR 结论**：去掉「UI 任务级 precharge」≠ 去掉「request 级 reserve」。  
> vertex 路径 **仍 precharge**，但 **只在 `gateBeforeUpstream` 触发一次**，不与 UI / `getDialogTextResponse` 重复。

### 4.3 多步任务（理解 + 生图）

- **每步独立** `runMeteredAiCall`（符合 G1）。
- **同一 workflow task** 可选 `taskScopeKey`：第一步 reserve 略大于单步 min（`sumPlatformMinCredits` 仅含 platform 步），后续 platform 步在同 scope 内 **allocate**，避免能力集合中途余额被别的 tab 抢走。
- **实现优先级**：MVP 可先 **逐步 reserve**；task-scope 作为 P1.5 增强。

### 4.4 删除/禁止

| 删除 | 原因 |
|------|------|
| `WorkflowSection` 内 `assertAiGateForSteps(..., prechargeAmount)` | 违反 G2 |
| `beginCreditsPrechargeSession` / `endCreditsPrechargeSession` 业务调用 | 由 `PlatformReserve.release` 取代 |
| `getDialogTextResponse` 内 `assertPlatformAiCreditsForGeminiTask` | 重复 L1 |
| 各 `emit*` 手标 `meta.byok` | 改读 `billingDecision`（可保留兜底） |

## 5. L2 结算

```ts
// pipeline.buildMeteredUsageEvents
if (billingDecision.routeKind !== 'platform') {
  meta.byok = true;
  costUsdEst = null;
}
// platform: creditsCharged = f(costUsdEst)，关联 reserveKey 结算/退差
```

- **Poll 免费**（P7）：`getTripoTask`、gemini async poll **不经 gate、不 emit**。
- **异步交付**：`emitMeteredUsageAfterDelivery` 仍须携带 **同一 `billingDecision` 快照**（闭包或参数），禁止事后 peek context。

## 6. UI 规范（G2 + G3）

### 6.1 入队（策略 B）

```ts
const plan = planWorkflowActionRoutes(...);
const block = isSubmitBlockedForPlatformPlan(
  plan.filter(step => isNextExecutableStep(step)), // 仅下一步
  userId, balance, loading
);
// block.blocked → 禁用提交；不调用 assertAiGate / precharge
```

### 6.2 分步明细（新组件或现有 estimate 区）

示例：

```text
本次将执行：
  ① 理解意图 — 约 10 积分（Gemini 代理）
  ② 生成图片 — 自备 OpenAI Key，不扣积分
```

gen_image 预设可配置默认 **skipUnderstand**，减少混合计费困惑。

## 7. BYOK 代理成本（G5 运营）

Tripo / OpenAI 等 BYOK 仍经站点代理时：

| 措施 | 说明 |
|------|------|
| **记量** | `usage_events` 照常写，`creditsCharged=0` |
| **限速** | Tripo `/api/tripo/*` 按 `userId` RPM；复用 fairness 模式 |
| **文档** | 帮助页写明：「Key 自理上游费用；站点提供连接与归档」 |

---

## 8. 服务端对齐

- **规则单源**：`shared/billingRoute.ts` 供客户端；服务端 gate **import 同文件**（或编译拷贝），禁止分叉。
- **gemini-proxy-credits-gate**：继续校验 `X-AC-Credits-Reserve`；与客户端 `acquirePlatformReserve` 对齐。
- **Tripo 代理**：不扣积分；可选 Admin 监控 BYOK 调用量。

## 9. 实施阶段（修订）

### Wave A — 契约与 L2 防再犯（≈1d）

1. 新增 `shared/billingRoute.ts` + `services/aiDispatchGate.ts`
2. `BillingDecision` 类型入 `shared/`
3. `pipeline` 读 `billingDecision` 自动 byok
4. 修复腾讯/Tripo L2（临时 `extraMeta.byok` 直至 Wave B）
5. 测试：`billingRoute.test.ts`、`credits.test.ts` 扩展

### Wave B — 执行层单点（≈1.5d）

1. `runMeteredAiCall` 替换 `traceUnifiedAiCall`
2. `acquirePlatformReserve` 收拢 `getCreditsProxyRequestHeaders`
3. 删除 `geminiService` 重复 assert
4. `createTripoTask` / 腾讯 3D 经 gateway + provider 路由
5. 测试：`unifiedAiGateway.test.ts`、`proxyCreditsGate.test.ts` 修订

### Wave C — UI 去预扣 + 分步明细（≈1d）

1. `WorkflowSection` 删 precharge 调用链
2. 入队改 B-only `isSubmitBlockedForPlatformPlan`
3. 分步积分明细 UI
4. deprecate `creditsPrechargeSession` 对外 API

### Wave D — 全站出口 + 运营（≈1.5d）

1. dialog / texture / arena / SiteAssistant 包装
2. eslint：业务禁止 `import geminiService`（测试除外）
3. Tripo 代理限速配置
4. 更新 `workflowAiPickIndex`
5. 帮助文档「何时扣费 / 失败是否退」

**MVP 可交付**：Wave A + B + C（Tripo BYOK + OpenAI 不误扣 + UI 不预扣）。

**Wave D（2026-07-07）**：dialog/贴图/擂台/检测等经 `runMeteredAiCall`；腾讯 3D start 包装；Tripo 代理 RPM；eslint 边界；`WorkflowSection` 改走 gateway。
