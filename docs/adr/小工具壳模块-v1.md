# ADR：小工具壳模块 v1

**状态**：已采纳（2026-06-24）  
**决策者**：架构评审（小工具架规格 v0.2）  
**关联**：`docs/本地伴侣-小工具架开发规格.md`

## 背景

桌面壳需第四页「工具」，支持可插拔 `shell_tool_bundle`。需在「足够灵活」与「安全、可维护、可热更」之间拍板 UI 与脚本边界。

## 决策

| 议题 | 结论 |
|------|------|
| UI 形态 | **壳模块**：统一 `tools-module.js` 渲染 `panel.json` 白名单控件；**非**包内 HTML 页 |
| 包内 JS | **禁止**壳侧 `import` / `eval` 包内脚本；`scripts/` 仅宿主 **spawn** |
| `handlers.mjs` | **首版否决**；复杂交互 Phase 2 单独立项 |
| params 注入 | 首版 **仅** `paramsMode: "env"` |
| 安装 | **`bundleInstallCore`** 与 `host_plugin_bundle` 共用；**staging + 原子 rename** |
| 升级回滚 | 保留 **一份** `extracted.bak` |
| `run` 语义 | 首版 **同步** HTTP；长任务 Phase 2 → `compute/jobs` |
| 发行安装 | `publicInstallUrl` 时 **免登录**（与扩展包一致） |

## 理由

1. **安全**：JSON panel 消除包内 XSS；命令仅来自磁盘 `tool.json`。
2. **一致性**：与主壳 home/settings 同一桌面范式；下拉走 CustomDropdown 规范。
3. **可热更**：渲染器发壳一次；工具逻辑在 ZIP 内迭代。
4. **可实施**：声明式 panel 足以验证「路径 + 运行 + 日志」全链路（如图片转换）。

## 后果

- 新控件类型须递增 `panel.schemaVersion` 且 **发壳**。
- 工具作者不能自带 React/Vue 整页；重度 UI 须等 `shell_window` 或 Phase 2 方案。
- 须实现 `bundleInstallCore` 重构，避免与 `hostPluginBundles` 双份逻辑。
- CI 须含 `validate:shell-tools`（JSON Schema）。

## 替代方案（未采纳）

| 方案 | 未采纳原因 |
|------|------------|
| 工具页 BrowserView 加载远程页 | 与工作台混淆；权限与离线差 |
| 每工具独立 HTML bundle | XSS 与 UX 碎片化 |
| `params-file` 与 `env` 并存首版 | 脚本接口分裂 |
| 升级直接覆盖 `extracted/` | 半态风险高 |
