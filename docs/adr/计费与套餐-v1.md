# ADR：计费与套餐 v1（Phase 0 拍板）

**状态**：已采纳（2026-06-19）  
**决策者**：产品 + 架构（会话纪要）  
**关联**：`docs/用量计费商业化开发清单.md`

## 背景

站点已有试用次数配额（`trial-gemini`）、云存储字节账本、公平队列权重，但缺少可扩展到专业 SaaS 的 **统一用量事件** 与 **美元估算**。Phase 0 先建计量基础，不改动用户付费流程。

## 拍板结论（P1～P12）

| ID | 决策 |
|----|------|
| P1 计费主体 | **账号级**（`user_id`）；表结构预留 `workspace_id` / `project_id` |
| P2 用户可见单位 | Phase 0 **仅 Admin**；Phase 1 起对用户展示 **积分 + 明细可展开美元估算** |
| P3 套餐模型 | Phase 2 再做；当前保持试用次数并行 |
| P4 自带 Key | **只记量不计价**（`cost_usd_est = null`，`meta.byok = true`） |
| P5 失败扣费 | **仅成功记账**（`status = succeeded`） |
| P6 异步任务 | **成功时记账**；poll 不写 event |
| P7 轮询查询 | **免费**（Tripo `getTripoTask`、gemini async poll 不记账） |
| P8 定价 | Phase 0 价目 **0% markup**，对齐官方公示价估算 |
| P9 超额 | Phase 2；当前不改变 `trial-gemini` 行为 |
| P10 保留期 | 事件 **13 个月**（Phase 4 清理任务） |
| P11 隐私 | **不存 prompt**；仅 token 数、SKU、taskId 等 |
| P12 与审计 | **独立 `usage_events`**；可选 `workflow_step_id` / `audit_log_id` 关联 |

## 架构约束

1. **双账本**：用户 `usage_events` ≠ GCP 账单；月末对账为 Phase 4。
2. **单写入口**：浏览器经 `POST /api/usage/events`（登录会话）；服务端幂等 `idempotency_key`。
3. **闸门记账**：优先在 `bulkProxyGenerateContentAsync`（代理完成点）、`createTripoTask`（任务创建点）写入。
4. **功能开关**：`USAGE_BILLING_ENABLED` 默认 `true`；设为 `false` 时 API 返回 204 跳过写入。

## 后果

- 需维护 `price_catalog` 种子与 `billingSku` 映射。
- BYOK / 直连 SDK 路径 Phase 0 可能无 `usageMetadata`，暂不记账或后续补采。
- 试用配额与用量事件 **双写并存**，直至 Phase 2 统一准入。
