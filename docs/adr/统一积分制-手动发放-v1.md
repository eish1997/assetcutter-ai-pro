# ADR：统一积分制 — 手动发放 v1

**状态**：已采纳（2026-07-06）  
**决策者**：产品 + 架构  
**版本**：v1.1（架构评审修订）

**关联文档**：

| 文档 | 关系 |
|------|------|
| `docs/adr/计费与套餐-v1.md` | Phase 0 计量底座；本 ADR 叠加 **L1 准入 + 积分扣减** |
| `docs/adr/可观测性与计费统一架构-v1.md` | L2 计量管线；积分扣减 **不得** 写入 adapter |

## 0. 决策摘要（Executive Summary）

在现有 `usage_events` + `price_catalog` 之上，引入 **账号级积分余额** 与 **append-only 流水**，由管理员 **手动发放/扣回**，替换登录用户的 `trial-gemini` 日次闸门。

**核心约束**：

1. **积分扣减唯一入口**：`meteringPipeline` 成功 emit 后，经 `credit-store.consumeCredits` 与 `usage_events` **同一事务**写入。
2. **价目 → 积分换算唯一函数**：`usdEstToCredits(costUsdEst)`，禁止 UI / adapter 各自换算。
3. **余额不可为负**；超额 **硬停**（`CREDITS_EXCEEDED`）。
4. **云存储字节配额** 与积分 **正交**，不合并。

---

## 1. 背景

### 1.1 问题陈述

当前三套并行机制无法支撑「公司给员工的 AI 额度管理」：

| 机制 | 位置 | 缺陷 |
|------|------|------|
| 试用日次 | `trial-gemini-quota-store.js` | 与 SKU 成本脱钩；无法按人配额度 |
| 用量账本 | `usage_events` | 只记不扣；无余额概念 |
| 云存储 | `workspaceQuotaBytes` | 正确独立，但 UI 易与 AI 混淆 |

Phase 0/1 已具备计量与 Admin 读模型；缺 **L1 统一准入** 与 **可分配余额**。

### 1.2 目标用户与场景

**内部 SaaS**：IT/运营创建账号 → 手动发放积分 → 员工在工作流消耗 → 管理员查余额/流水/用量。

### 1.3 非目标（v1 边界）

| 不做 | 理由 |
|------|------|
| 订阅 / 套餐 / 月赠 cron | 产品决策：仅手动发放 |
| Stripe / 自助充值 | Phase 3，不在本 ADR |
| 组织 / 部门 / 多租户 | 预留 `user_id`，不建 org 表 |
| 云存储兑换积分 | 计量单位不同（byte vs cost） |
| 访客积分账户 | 降低滥用面；访客保留日次 |
| Admin CSV 批量发放 UI | 可脚本化；不挡 v1 |

## 2. 架构定位（分层）

对齐 `可观测性与计费统一架构-v1` 的 L0～L5：

```text
L5 展示   Admin 用户详情 / 用量页 / 工作流 chip / 设置页余额
L4 读模型 GET /api/credits/* 、Admin credits API
L3 关联   credit_ledger.ref_id ↔ usage_events.id ↔ audit_log
L2 计量   meteringPipeline → estimateCostUsd → usdEstToCredits
L1 准入   credit-store.check / consume（替换 trial-gemini @ 登录用户）
L0 契约   shared/credits.ts 、错误码 CREDITS_EXCEEDED
```

**禁止**：

- 在 `geminiService` / `tripoService` adapter 内直接改 balance
- 在浏览器侧 `localStorage` 维护登录用户余额
- 用公平队列 `costWeight` 代替用户积分扣减

## 3. 关键决策（含备选方案）

### 3.1 产品拍板 D1～D6

| ID | 议题 | 结论 |
|----|------|------|
| D1 | 新用户默认积分 | **0**；须管理员发放 |
| D2 | 扣回 | 支持；`delta < 0`，备注必填 |
| D3 | 余额下限 | **≥ 0**；硬停 |
| D4 | 存量用户上线 | balance = 0；管理员批量 grant，**不**自动折算 trial 次数 |
| D5 | 访客 | localStorage 日次；无积分账户 |
| D6 | 发放权限 | 独立 `credits.write`；读合并 `users.read` |

### 3.2 架构拍板 A1～A8

| ID | 议题 | 备选 | **采纳** | 理由 |
|----|------|------|----------|------|
| A1 | 积分锚定 | 固定档位表 / USD 换算 | **`ceil(usd × 1000)`** | 复用价目表；涨价单点维护 |
| A2 | 余额存储 | 纯 ledger 聚合 / 余额表 + ledger | **余额表 + ledger** | 准入需 O(1) 读；ledger 审计 |
| A3 | 扣费时机 | 预扣 + finalize / 成功后扣 | **成功后扣（v1）** | 实现简单；异步超额风险见 §8.3 |
| A4 | 扣费入口 | 各 proxy 分散 / 管线统一 | **meteringPipeline 尾部** | 与 Wave 2 计量收敛一致 |
| A5 | usage_events 关联 | 加列 `credits_charged` / 仅 ledger ref | **加列 `credits_charged`** | 读模型 JOIN 简单；双写一致 |
| A6 | JSON 镜像模式 | 仅 PG / 双写 | **双写**（对齐 usage-billing） | 本地 dev 无 PG 可跑 |
| A7 | 功能开关 | 单开关 / 双开关 | **`CREDITS_BILLING_ENABLED`** 独立于 `USAGE_BILLING_ENABLED` | 可「只记账不扣费」灰度 |
| A8 | trial-gemini | 并行 / 立即移除 | **登录用户移除**；访客保留 | 避免双闸门逻辑漂移 |

### 3.3 沿用 Phase 0 规则

| 项 | 规则 |
|----|------|
| 计费主体 | 账号 `user_id` |
| BYOK | 记 `usage_events`；`cost_usd_est = null`；**不扣积分** |
| 失败 | 不扣、不写 succeeded event |
| 异步 | 成功扣；poll 免费 |
| 隐私 | 不存 prompt |

## 4. 系统不变量（Invariants）

实施与 Code Review 必须维护：

| # | 不变量 |
|---|--------|
| I1 | `user_credit_balances.balance >= 0` 恒成立 |
| I2 | 任意时刻 `balance = Σ(credit_ledger.delta)`（可按 user 对账修复） |
| I3 | 每条 `kind=consume` 的 ledger **恰有 1 条** `status=succeeded` 的 usage_event（`ref_id` 关联） |
| I4 | `credits_charged = usdEstToCredits(cost_usd_est)` 或 BYOK 时为 0 |
| I5 | 同一 `usage_events.idempotency_key` 不得重复 consume |
| I6 | `lifetime_granted = Σ(delta where delta > 0 and kind in grant)` |
| I7 | `lifetime_spent = Σ(|delta| where kind = consume)` |

违反 I2/I3 时触发 **对账告警**（§11），不静默覆盖。

## 5. 积分换算

### 5.1 唯一函数

```ts
// shared/credits.ts — 前后端共用，禁止重复实现
export const CREDITS_PER_USD = 1000;

export function usdEstToCredits(costUsdEst: number | null | undefined): number {
  if (costUsdEst == null || !Number.isFinite(costUsdEst) || costUsdEst <= 0) return 0;
  return Math.ceil(costUsdEst * CREDITS_PER_USD);
}
```

### 5.2 示例

| 操作 | cost_usd_est | credits |
|------|--------------|---------|
| Gemini Flash ~1.4K tokens | ~0.0014 | 2 |
| Gemini Pro Image ×1 | ~0.134 | 134 |
| Tripo 3D ×1 task | ~0.50 | 500 |

### 5.3 特殊路径

| 路径 | credits | usage_events |
|------|---------|--------------|
| BYOK | 0 | 写，`cost_usd_est = null`, `meta.byok = true` |
| 上游失败 | 0 | 不写 succeeded |
| 轮询 | 0 | 不写 |

## 6. 数据模型

迁移：`server/migrations/011_user_credits.sql`

### 6.1 实体关系

```text
users 1──1 user_credit_balances
users 1──* credit_ledger
credit_ledger *──0..1 usage_events  (ref_type='usage_event')
usage_events  optional credits_charged
```

### 6.2 `user_credit_balances`（读模型 / 热路径）

```sql
CREATE TABLE user_credit_balances (
  user_id TEXT PRIMARY KEY REFERENCES users(id) ON DELETE CASCADE,
  balance BIGINT NOT NULL DEFAULT 0 CHECK (balance >= 0),
  lifetime_granted BIGINT NOT NULL DEFAULT 0,
  lifetime_spent BIGINT NOT NULL DEFAULT 0,
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

- **写路径**：仅 `credit-store` 内 UPDATE（持行锁）
- **读路径**：准入检查、UI 展示
- JSON 镜像：`server/data/user-credit-balances.json` + ledger 镜像（dev 无 PG）

### 6.3 `credit_ledger`（审计真源）

```sql
CREATE TABLE credit_ledger (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  delta BIGINT NOT NULL,
  balance_after BIGINT NOT NULL,
  kind TEXT NOT NULL CHECK (kind IN ('grant', 'admin_deduct', 'consume', 'refund')),
  ref_type TEXT NULL,
  ref_id TEXT NULL,
  idempotency_key TEXT NULL UNIQUE,  -- consume 必填；admin adjust 可选
  note TEXT NULL,
  created_by TEXT NULL REFERENCES users(id),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_credit_ledger_user_created ON credit_ledger(user_id, created_at DESC);
CREATE INDEX idx_credit_ledger_ref ON credit_ledger(ref_type, ref_id) WHERE ref_id IS NOT NULL;
```

| kind | delta | created_by |
|------|-------|------------|
| grant | > 0 | 管理员 |
| admin_deduct | < 0 | 管理员 |
| consume | < 0 | NULL（系统） |
| refund | > 0 | 管理员或系统 |

### 6.4 `usage_events` 扩展

```sql
ALTER TABLE usage_events ADD COLUMN IF NOT EXISTS credits_charged BIGINT NULL;
```

### 6.5  deliberate 不建

`credit_plans`、`user_credit_plans`、周期 cron — 见 §1.3。

**扩展预留**（不实现）：`credit_ledger.meta_json` 可 future 存 `{ planId, period }`，v1 不建列。

## 7. 核心模块：`credit-store`

**路径**：`server/credit-store.js`（单数，与 `auth-store` 命名一致）  
**类型**：`shared/credits.ts`

### 7.1 公开 API

```js
/**  advisory 预检；非权威 — 并发下仍可能 consume 失败 */
precheckCredits(userId, estimatedCredits) → { ok, balance, required }

/** 管理员调整；delta≠0；note 必填 */
adjustCredits(userId, delta, { note, createdBy, idempotencyKey? }) → { balanceAfter, ledgerId }

/** 与 insertUsageEvent 同事务；credits=0 时仅写 event（BYOK） */
consumeCreditsInTx(client, userId, credits, { usageEventId, idempotencyKey }) → { balanceAfter }

getCreditBalance(userId) → { balance, lifetimeGranted, lifetimeSpent }
listCreditLedger(userId, { limit, cursor }) → { entries, nextCursor }
```

### 7.2 并发与事务

```text
consumeCreditsInTx:
  SELECT balance FROM user_credit_balances WHERE user_id = $1 FOR UPDATE
  IF balance < credits → ROLLBACK, throw CREDITS_EXCEEDED
  UPDATE balance, lifetime_spent
  INSERT credit_ledger (kind=consume, idempotency_key=usage.idempotency_key)
  INSERT/UPDATE usage_events (credits_charged=credits)
  COMMIT
```

- Postgres：**必须** `FOR UPDATE` 行锁
- JSON 镜像：进程内 mutex + 整文件 rewrite（与现有 store 一致；**生产应用 PG**）

### 7.3 幂等

| 操作 | 键 |
|------|-----|
| consume | `usage_events.idempotency_key` → `credit_ledger.idempotency_key` UNIQUE |
| admin adjust | 可选 `Idempotency-Key` header；24h 内重复返回同一结果 |

重复 consume：**返回已有 ledger 行**，不二次扣款（I5）。

### 7.4 与计量管线集成（唯一扣费路径）

```text
meteringPipeline.emit(drafts)
  → usageEmitFacade → insertUsageEvent (pending)
  → for each succeeded draft with !byok:
       credits = usdEstToCredits(draft.costUsdEst)
       consumeCreditsInTx(...)
  → on CREDITS_EXCEEDED: mark event failed? / 不写入 succeeded
```

**v1 简化**：同步请求在 proxy **响应前**完成 consume；失败则整请求 403。  
客户端 **不得** 在 emit 后再单独调 consume API。

## 8. 准入与边界情况

### 8.1 登录用户请求流

```text
invoke AI (proxy)
  → session 有效？
  → BYOK？→ 跳过积分；仅 L2 emit
  → precheckCredits (可选，快速失败)
  → 上游执行
  → 成功 → metering emit + consumeCreditsInTx
  → balance 不足 → 403 CREDITS_EXCEEDED（上游已成功时见 §8.3）
```

替换：`consumeTrialGeminiSlotBeforeProxyOrThrow` → `assertCreditsGateBeforeProxy`（仅检查 `balance > 0` 或 precheck）。

### 8.2 访客

保留 `services/trialGeminiQuota.ts` localStorage 日次；**不调用** `credit-store`。

### 8.3 异步任务与超额竞态（已知限制）

v1 **不实现预扣（reserve）**。并发/async 场景：

- 多请求并行可能均通过 `balance > 0` 预检，合计 consume 超出余额
- **缓解**：consume 时行锁权威判定；最后一笔返回 `CREDITS_EXCEEDED`
- **残余风险**：上游已成功但 consume 失败 → 平台承担成本；记 `usage_events.status=failed` + 告警日志

**v1.1+ 演进**：`reserveCredits` + async finalize（不阻塞本 ADR 实施）。

### 8.4 功能开关矩阵

| USAGE_BILLING | CREDITS_BILLING | 行为 |
|---------------|-----------------|------|
| off | * | 不写 usage、不扣积分 |
| on | off | 只记 usage，不扣积分（灰度） |
| on | on | **目标态**：记 usage + 扣积分 |

环境变量：`CREDITS_BILLING_ENABLED`（默认 `true`）。

### 8.5 错误契约

```json
{
  "error": "积分不足，请联系管理员补充额度",
  "code": "CREDITS_EXCEEDED",
  "balance": 42,
  "required": 134
}
```

HTTP **403**。前端统一映射；工作流 runTask 捕获后 Toast。

## 9. HTTP API

### 9.1 用户（需登录）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/credits/balance` | `{ balance, lifetimeGranted, lifetimeSpent }` |

### 9.2 管理端

| 方法 | 路径 | 权限 |
|------|------|------|
| GET | `/api/admin/users/:id/credits` | `users.read` |
| POST | `/api/admin/users/:id/credits/adjust` | `credits.write` |
| GET | `/api/admin/users/:id/credits/ledger` | `users.read` |

**adjust body**：`{ delta: number, note: string }`  
- `|delta| >= 1` 整数

### 9.3 明确不提供

- 用户自助充值  
- 客户端直接 `POST /api/credits/consume`（**防篡改**；consume 仅服务端内部）

| consume 同事务 usage | I3 成立 |
| 重复 idempotency_key | 不双扣 |
| 并发 consume 抢余额 | 行锁；至多一笔超额 403 |
| BYOK | credits=0 |
| 访客 | 不走 credit-store |
| CREDITS_BILLING=false | 只 usage，balance 不变 |
