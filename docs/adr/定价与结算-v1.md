## 1. 背景

Phase 2 积分制已上线 L1 闸门与 L2 记账，但用户设置页缺少 **只读价目** 与 **任务收据** 读模型。Sprint A 在 L5 层补齐三类 API 与 UI，**不在组件内重算价目**（遵守 L5 约束）。

---

## 2. 决策

### 2.1 PricingEngine（`shared/pricing/pricingEngine.ts`）

| 函数 | 职责 |
|------|------|
| `listPublicPriceCatalog()` | 将 `DEFAULT_PRICE_CATALOG` 映射为用户可见行：能力 / 模型 / 积分 / 单位 |
| `quoteJobKinds(jobKinds[])` | 按 `proxyGateMinCreditsForJob` 汇总各 jobKind 最低积分（与工作流闸门对齐） |
| `imageFloorCredits(entry)` | 生图 SKU：`perUnit × CREDITS_PER_USD` 向上取整，作为 **单张起价（image floor）** |

服务端镜像：`server/pricing-engine.js`（auth-api 不可直接 import TS）。

### 2.2 BillingPresentation（`shared/billingPresentation.ts`）

| 函数 | 职责 |
|------|------|
| `presentationForSku(billingSku)` | 价目 `displayName` 或 SKU 族 fallback |
| `presentationLabelForEvent(ev)` | 事件展示名；区分 input/output/BYOK |
| `jobKindLabel(jobKind)` | 工作流步骤中文标签（quote API） |

### 2.3 Image floor 规则

- **适用**：`meterKind === 'image'` 或 `billingSku` 以 `image.` 开头且存在 `perUnit`
- **换算**：`ceil(perUnit × 1000)` 积分（与 `shared/credits.ts` `CREDITS_PER_USD` 一致）
- **公示**：价目表「积分」列展示 floor；「单位」为「张起」
- **token 类 SKU**：无固定 perUnit，公示为「按用量」

### 2.4 L5 读模型 API（session auth，与 `/api/usage/*` 同级）

| 方法 | 路径 | 响应 |
|------|------|------|
| GET | `/api/usage/price-list` | `{ items: PublicPriceCatalogItem[] }` |
| GET | `/api/usage/quote?jobKinds=a,b` | `{ steps: [{ jobKind, minCredits, label }], totalMinCredits }` |
| GET | `/api/usage/receipt?taskId=xxx` | `{ taskId, totalCredits, lines: [{ label, billingSku, credits, meterSummary }] }` |

**Receipt 关联规则**（当前用户 `usage_events`）：

1. 精确：`upstreamTaskId` / `requestId` / `meta.taskId` / `meta.correlationId`
2. 前缀：`requestId.startsWith(taskId)`（async 子请求）
3. 先 exact correlation 查询，无结果再扫最近 500 条前缀匹配

### 2.5 前端消费

- `services/usageApi.ts`：`fetchUsagePriceList` / `fetchUsageQuote` / `fetchUsageReceipt` + 再导出 presentation 助手
- `UsageSettingsPanel`：「积分价目」Tab，表格列 能力/模型/积分/单位，脚注 1 积分 ≈ $0.001
- `UsageEventsGroupedTable`：SKU 列展示 `presentationForSku`，`title` 为原始 `billingSku`

- 运营改价后台（仍用 `DEFAULT_PRICE_CATALOG` 种子）

## 4. 后果

- 价目变更须同步 `shared/usageBillingCatalog.ts` 与 `server/usage-price-catalog.js`
- `server/pricing-engine.js` 与 `shared/pricing/pricingEngine.ts` 逻辑需人工对齐（与 `credits-math.js` 模式相同）
- Receipt 前缀扫描有 500 条窗口上限；长尾任务可能需增大 limit 或加 PG 索引查询
