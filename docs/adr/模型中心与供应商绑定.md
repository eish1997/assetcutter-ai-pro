# ADR：模型 SKU 与供应商 Binding

**状态**：已接受（2026-05-27 落地 MVP）  
**决策者**：产品 + 研发  
**关联**：`docs/模型中心与供应商绑定改造清单.md`、`docs/架构宪章-店仓菜单.md`

---

## 背景

站点同时对接 Vertex 代理、ToAPIs、VectorEngine、OpenAI 官方等多条上游路径。若每增加一家中转就在产品 UI 增加一个「供应商品牌」，用户会在「Gemini 3 Pro Image」与「第 N 家中转」之间混淆，且无法表达「同一模型、多条接线、自动 failover」。

历史实现曾以全局单选供应商 + `getAI()` 互斥分支为主；现已统一为 `enabledChannels` + `pickBinding`。

## 决策

1. **产品菜单只展示模型 SKU**（`registryId`），不展示中转站品牌。
2. **运行时按 Binding 选线**：`pickBinding(registryId, role)` → `resolveUpstream` → `createClient(channel)`。
3. **Channel 与凭证分离**：`ChannelId` 枚举接线实现；Key / Base URL / 站点代理 env 在设置页按 channel 管理。
4. **用户设置唯一字段**：`enabledChannels`（本地 `ac_enabled_channels`，云 `user-config.json` 同字段）；resolve 层 `UpstreamProviderId` 仅内部映射，不对用户暴露。

## 产品策略（2026-05-27 拍板）

| 议题 | 结论 |
|------|------|
| 多 binding failover | **固定 priority 升序**：`pickBinding` 取第一条「已启用 + ready」；运营 `bindingOverrides` 可改 priority / 禁用单条；**不做**用户自定义「生图优先 Vertex」UI |
| 文本 vs 生图 channel | **允许不同**：`pickBinding(registryId, role)` 的 `role` 为 `text` \| `image`，binding 表按 role 分列；理解走文本 binding，生图走 image binding |
| 站点代理试用额度 | 走 bulk 代理且**无**用户 Gemini Key 时扣减（`consumeTrialGeminiSlotBeforeProxyOrThrow`），与 legacy `trial` 供应商枚举解耦 |

## 四层结构

| 层 | 代码锚点 | 用户感知 |
|----|----------|----------|
| 模型 SKU | `imageModels.ts`、`textModels.ts` | ✅ |
| 能力族 | `ModelFamily`（`gemini` \| `openai`） | ❌ |
| Binding | `providerBindings.ts`、`pickBinding.ts` | ❌（高级设置仅 channel） |
| 凭证 | `settingsStore.ts`、`channelCredentials.ts` | ✅ 设置页 |

## 运行时流程

```text
用户 / SystemConfig 选定 registryId
  → pickBinding(registryId, role)     // text | image
  → resolveUpstreamModelId(binding)
  → getClientForTask(registryId, role)
```

## `ChannelId` 一览

| `ChannelId` | 说明 | 默认启用 |
|-------------|------|----------|
| `vertex-proxy` | 站点 gemini-proxy + Vertex ADC | ✅ |
| `gemini-aistudio` | Google AI Studio Key 直连 | ❌（灰显 deprecated） |
| `toapis-gemini` | ToAPIs Gemini 兼容路径（与 openai 路径共用 Key） | 随用户勾选 |
| `toapis-openai` | ToAPIs OpenAI 兼容路径 | 随用户勾选 |
| `vectorengine` | VectorEngine Gemini REST | 随用户勾选 |
| `openai-official` | OpenAI 官方 API | ✅ |

**云/本地**：仅同步 `enabledChannels` 与各 channel 凭证；不读不写 `aiProvider` / `enabledAiProviders`。

## 默认优先级（family 级模板）

```text
gemini-family:  vertex-proxy > toapis-gemini > vectorengine > gemini-aistudio
openai-family:  openai-official > toapis-openai
```

具体每条 `registryId` 见 `services/modelRegistry/providerBindings.ts`；运营 JSON 可通过 `bindingOverrides` 调整单条 binding 的 `enabled` / `priority`（见 `public/model-ops.example.json`）。

## 后果

### 正面

- 加新中转 = 加 binding 行 + channel 凭证，不必加菜单模型。
- 生图与文本共用同一套选型机制。
- merge 层可表达「模型已登记但通道未就绪」的禁用原因。

### 负面 / 待办

- 运行时请求失败后的**自动换 binding 重试**未做（仅选型时 failover）。
- 用户设置与云同步仅 `enabledChannels`；本地首次加载会清除已废弃的 `ac_ai_provider` / `ac_ai_enabled_providers` 键。
