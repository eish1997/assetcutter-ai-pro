# ADR：模型 SKU 与供应商 Binding

**状态**：已接受（2026-05-27 落地 MVP；2026-05-28 产品三层表述收口）  
**决策者**：产品 + 研发  
**关联**：`docs/模型中心与供应商绑定改造清单.md`、`docs/架构宪章-店仓菜单.md`

---

## 背景

站点同时对接 Vertex 代理、ToAPIs、VectorEngine、OpenAI 官方等多条上游路径。供应商侧可随时增加**多种模型的输出口**；平台侧可随时登记**新的模型 SKU（输入口）**。二者通过 **Binding（接线）** 连接，而不是让用户在设置里选「Gemini 供应商」或「OpenAI 供应商」。

历史实现曾以全局单选供应商 + `getAI()` 互斥分支为主；现已统一为 `enabledChannels`（输出口开关 + 凭证）+ `pickBinding(registryId, role)`（型号级接线）。

---

## 产品三层（用户心智）

| 层 | 含义 | 谁维护 | 用户在哪感知 |
|----|------|--------|--------------|
| **输入口** | 平台模型 SKU，`registryId` | 研发登记 `textModels` / `imageModels`，运营可禁档位 | 工作流 / 对话 **选具体型号** |
| **输出口** | 供应商网关 / 线路，`ChannelId` + 凭证 | 研发加 channel；用户启用并填 Key | **设置 → 供应商输出口** |
| **接线** | `registryId × role` → 优先走哪条输出口（可 failover） | 默认 `providerBindings` 模板；运营 `bindingOverrides` 改单条 | 设置页型号接线面板；高级走运营 JSON |

```text
工作流选定 registryId（输入口）
  → pickBinding(registryId, role)   // 接线表
  → 在已启用且 ready 的输出口中取第一条
  → resolveUpstream → createClient
```

**原则**

1. 菜单与配置 **不以 Gemini/OpenAI 族** 作为产品选项；`ModelFamily` 仅用于默认接线模板与适配器选择。
2. 供应商目录可以比站内菜单 **更全**；未在平台登记的 `registryId` **不会**出现在菜单。
3. 凭证挂在 **输出口**（同一 ToAPIs Key 可接多条协议路径），不按单个 SKU 重复填 Key。
4. 用户设置真相源：`enabledChannels`（本地 + 云 `user-config.json`）。

---

## 决策（实现）

1. **产品菜单只展示模型 SKU**（`registryId`），不展示中转站品牌。
2. **运行时按 Binding 选线**：`pickBinding(registryId, role)` → `resolveUpstream` → `createClient(channel)`。
3. **Channel 与凭证分离**：`ChannelId` 枚举输出口；Key / Base URL / 站点代理 env 在设置页管理。
4. **resolve 层** `UpstreamProviderId` 仅内部映射，不对用户暴露。

## 产品策略（2026-05-27 拍板）

| 议题 | 结论 |
|------|------|
| 多 binding failover | **固定 priority 升序**；运营 `bindingOverrides` 可改；**不做**用户拖优先级 UI |
| 文本 vs 生图 | **允许不同输出口**：`role` 为 `text` \| `image`，binding 表分列 |
| 站点代理试用额度 | AI Worker Proxy 且**无**用户 Gemini Key 时扣减；与 `trial` 展示名解耦 |

## 代码分层

| 层 | 代码锚点 | 设置 UI |
|----|----------|---------|
| 输入口（SKU） | `imageModels.ts`、`textModels.ts` | ❌（工作流选型号） |
| 接线 | `providerBindings.ts`、`pickBinding.ts` | 型号接线面板（只读，随输出口状态更新） |
| 输出口 | `channelCatalog.ts`、`connectionCatalog.ts` | ✅ 启用 + 凭证 |
| 凭证 | `settingsStore.ts`、`channelCredentials.ts` | ✅ |

`ModelFamily`（`gemini` \| `openai`）：**仅**默认接线模板与 upstream 映射，**不**作为设置页主分类。

## 运行时流程

```text
用户 / SystemConfig 选定 registryId
  → pickBinding(registryId, role)
  → resolveUpstreamModelId(binding)
  → getClientForTask(registryId, role)
```

## 输出口（`ChannelId`）一览

| `ChannelId` | 说明 | 默认启用 |
|-------------|------|----------|
| `vertex-proxy` | 站点 ai-worker-proxy + Vertex ADC | ✅ |
| `gemini-aistudio` | Google AI Studio Key 直连 | ❌ |
| `toapis-gemini` | ToAPIs · Gemini 协议路径（与 openai 路径共用 Key） | 随用户勾选 |
| `toapis-openai` | ToAPIs · OpenAI 协议路径 | 随用户勾选 |
| `vectorengine` | VectorEngine 网关 | 随用户勾选 |
| `openai-official` | OpenAI 官方 API | ✅ |

**云/本地**：仅同步 `enabledChannels` 与各输出口凭证。

## 默认接线模板（family 级，展开为 per-SKU binding）

```text
gemini-family 模板 → 各 Gemini SKU 的 text/image binding 链
openai-family 模板 → 各 OpenAI SKU 的 binding 链
```

family 模板优先级示例：

```text
gemini-family:  vertex-proxy > toapis-gemini > vectorengine > gemini-aistudio
openai-family:  openai-official > toapis-openai
```

具体每条 `registryId × role` 见 `services/modelRegistry/providerBindings.ts`；运营 JSON 可通过 `bindingOverrides` 调整单条 priority / 禁用（见 `public/model-ops.example.json`）。

## UI 演进

| 阶段 | 设置页 |
|------|--------|
| 当前 | **供应商输出口** + **型号接线**（全量 SKU×角色，只读，反映当前启用/凭证） |
| 后续（可选） | 运营/高级用户：单 SKU 接线编辑，或完全由 `model-ops` 驱动 |

## 后果

### 正面

- 加供应商输出口 = 加 channel + binding 行，不必改「选 Gemini 还是 OpenAI」类产品开关。
- 加平台 SKU = 登记 registryId + 生成/配置 binding，与输出口扩展解耦。
- 生图与文本共用同一套选型机制。

### 负面 / 待办

- 运行时请求失败后**自动换 binding 重试**未做（仅选型时 failover）。
- 用户暂不能在 UI 编辑完整 SKU×输出口矩阵（依赖运营配置）。
