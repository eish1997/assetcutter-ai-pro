## 1. 目标节点模型（产品语言）

```text
[供应商节点]                    [平台枢纽]                 [前端]
  输出口 S1 ──model A──┐         输入 IN-a  ←──────────────┘
  输出口 S2 ──model B──┼──→      输入 IN-b  ←── ...
  输出口 …  （可空）    │         输出 OUT-x ──→ 菜单选项「Gemini 3 Pro Image」
  可继续加桩            │         输出 OUT-y ──→ 菜单选项「GPT-4o」
                      └─ 未连线的桩保持空，供应商与枢纽可独立开发
```

**原则**

| # | 原则 |
|---|------|
| P1 | 前端只连枢纽 **输出侧**（展示用 SKU / `registryId`） |
| P2 | 枢纽 **输入侧** 连供应商 **输出口**（按具体型号/桩，不是「Gemini/OpenAI 大类」） |
| P3 | 供应商目录可远大于站内菜单；**未登记 SKU 不出现在菜单** |
| P4 | 供应商桩、枢纽输入/输出桩均允许 **空（未连接）** |
| P5 | 凭证在 **供应商节点**（或输出口组），不按每个前端 SKU 重复填 Key |
| P6 | 运行时 failover：同一 SKU 可有多条输入接线，按 **priority** 选第一条 ready |

## 2. 当前实现 vs 目标（差异表）

| 维度 | 当前实现 | 目标 |
|------|----------|------|
| **供应商「输出口」** | `ChannelId`（如 `toapis-gemini` / `toapis-openai`）= **API 协议形态**，不是 per-model 桩 | 供应商 **模型级输出口**（或运营声明的 upstream id）；协议形态为实现细节 |
| **ToAPIs 设置 UI** | 一套 Key + 用户勾选「协议路径 · Gemini/OpenAI 形态」 | **一个供应商网关** + 凭证；形态由 binding/运营决定，**用户不勾协议** |
| **平台枢纽** | 隐式：`registryId` 同时充当「输入目标 + 前端输出」 | 显式：**HubInPort / HubOutPort**（可先逻辑分离、后可视化） |
| **连线** | `providerBindings` 表：`registryId×role → channel + priority` | **边表**：`HubOut(SKU) ← HubIn ← SupplierOutlet`（可映射回现有 binding） |
| **空桩** | 未启用 channel / 无 ready binding（隐含） | 数据模型与 UI 可展示 **未连接** 状态 |
| **设置页** | 输出口卡片 + 型号接线只读面板 | + 枢纽输入/输出桩列表；运营可编辑连线（或 model-ops） |
| **运行时** | ✅ `pickBinding` → `getClientForTask` | 保持；底层逐步改为解析 **边表** 而非裸 `ChannelId` |
| **云同步** | ✅ `enabledChannels` + 各 Key | 扩展同步 **运营接线配置**（若用户可编辑则另议；默认仅 ops 云配置） |

**已对齐、无需推倒**：SKU 级 `pickBinding`、凭证与接线分离、文本/生图独立 role、failover 优先级、`model-ops` 覆盖单条 binding。

## 4. 类型草案（阶段 H 参考）

```ts
/** 供应商标识（产品层，可对应 connectionCatalog.id） */
type SupplierId = "vertex-site" | "toapis" | "vectorengine" | "openai-official" | "gemini-aistudio";

/** 供应商上的模型级输出口（可空、可扩展） */
type SupplierOutlet = {
  outletId: string;
  supplierId: SupplierId;
  label: string;
  upstreamModelId: string;
  apiShape: "gemini" | "openai" | "site-proxy";
  /** 运行时映射到现有 ChannelId，过渡期必填 */
  channelId: ChannelId;
};

/** 平台枢纽输入桩（接供应商输出口） */
type HubInPort = {
  hubInId: string;
  registryId: string;
  role: "text" | "image";
};

/** 平台枢纽输出桩（接前端菜单，初期与 registryId 1:1） */
type HubOutPort = {
  hubOutId: string;
  registryId: string;
  menuLabel: string;
  visible: boolean;
};

/** 连线：供应商输出口 → 枢纽输入 */
type WiringEdge = {
  edgeId: string;
  from: { supplierId: SupplierId; outletId: string };
  to: { hubInId: string };
  priority: number;
  enabled?: boolean;
};
```

**编译规则（过渡期）**：`WiringEdge` + `SupplierOutlet.channelId` → 现有 `ProviderBinding` 行。

## 6. 验收总表（全部完成后）

| 场景 | 预期 |
|------|------|
| 用户配置 ToAPIs | 只填 Key/Base URL，**不选协议路径** |
| 用户选前端 SKU | 走 HubOut → HubIn → 已接 SupplierOutlet 链 |
| 供应商 100 模型、平台登记 10 个 | 菜单 10 个；binding/ops 决定实际接线 |
| 新增供应商输出口 | 改 ops / `supplierOutlets`，不必改前端「选 Gemini/OpenAI」 |
| 新增平台 SKU | 登记 registry + HubIn/HubOut + 接边 |
| 空桩 | UI 或 ops 可表示「未连接」；运行时不可选 |
| 跨设备 | `enabledChannels` + Key 云同步；ops 接线全局一致 |
| 线上 | 仍仅静态前端 + ai-worker-proxy env；无 localhost 硬编码 |
