# 本地中转应用开发文档（多站点版）

## 1. 背景与目标

本项目目标是构建一个安装在用户电脑上的本地中转应用，连接：

- 前端入口：用户在你的网站输入与查看消息
- 执行端：用户本机浏览器（已登录目标站点，如 Gemini）
- 回传端：将目标站点响应实时回传到你的网站

核心原则：

- 通用核心稳定，站点逻辑可插拔
- 优先复用社区适配器（`bb-sites`），但保留私有兜底
- 保障安全边界（白名单域名、用户授权、最小权限）

## 2. 范围与非范围

### 2.1 范围（本期要做）

- 本地中转进程（Windows 优先）
- 与你的网站建立认证后的长连接（WSS）
- 统一任务协议（发送、流式回传、状态、错误）
- 站点适配器机制（connector/plugin）
- 接入 `bb-sites` 作为默认适配器来源
- 健康检查、版本回滚、日志与可观测性

### 2.2 非范围（本期不做）

- 替代目标站点官方 API
- 保证所有站点永久免维护
- 绕过平台风控/条款的能力

## 3. 总体架构

```text
你的网站前端
   │ HTTPS/WSS
你的网站后端（会话、鉴权、任务路由）
   │ WSS（设备连接）
本地中转应用（用户电脑）
   │ 本机调用
bb-browser / CDP
   │
用户本机 Chrome 目标站点标签页
```

数据路径：

1. 用户在网站发送消息
2. 后端下发任务给对应设备（本地中转）
3. 中转调用站点适配器执行发送
4. 监听回复并流式回传
5. 网站前端实时渲染并落库存档

## 4. 模块设计

## 4.1 通用核心（低频变更）

- `transport`：与云端通信（WSS、重连、心跳、ACK）
- `orchestrator`：任务调度（队列、超时、重试、并发）
- `session`：设备配对、token 管理、设备 ID
- `security`：域名白名单、权限校验、命令范围限制
- `telemetry`：日志、错误码、健康上报
- `plugin-runtime`：加载和管理站点适配器

### 4.2 站点适配器（高频变更）

每个站点一个适配器，负责“说明书”逻辑：

- 页面识别与初始化
- 消息输入与发送
- 回复抓取（DOM/network/eval）
- 完成态/失败态判定

建议统一接口：

```ts
export interface SiteConnector {
  id: string;
  version: string;
  match(ctx: { url?: string; domain?: string }): boolean;
  init(ctx: ConnectorContext): Promise<void>;
  sendMessage(input: SendInput): Promise<{ requestId: string }>;
  subscribeReplies(
    cb: (event: ReplyEvent) => void
  ): () => void;
  healthCheck(): Promise<HealthResult>;
  teardown(): Promise<void>;
}
```

## 5. `bb-sites` 接入策略

定位：主适配器来源，不是零维护保险箱。

- 默认从 `bb-sites` 拉取可用适配器
- 中转启动时做兼容性检查（版本、依赖、健康）
- 更新后先灰度再全量
- 失败自动回滚到上一版本
- 对关键站点保留私有 override

推荐目录：

```text
connectors/
  community/       # bb-sites 同步内容
  overrides/       # 私有修补/兜底
  manifest.json    # 可用适配器索引
```

## 6. 协议设计（网站 <-> 本地中转）

统一消息 envelope（与具体站点解耦）：

```json
{
  "type": "task.send_message",
  "taskId": "uuid",
  "connectorId": "gemini-web",
  "threadId": "optional",
  "payload": {
    "text": "用户输入内容"
  }
}
```

回传事件建议：

- `task.accepted`
- `reply.delta`
- `reply.completed`
- `task.failed`
- `task.timeout`
- `connector.unhealthy`

## 7. 安全与合规要求

- 本地服务仅监听 `127.0.0.1`
- 所有云端通信必须 TLS
- 设备配对必须有一次性授权流程
- 只允许白名单站点被自动化
- 记录审计日志（不存敏感正文或做脱敏）
- 明示用户：需遵守目标站点 ToS

## 8. MVP 里程碑

### M1：单站点打通

- 支持 1 个站点（如 Gemini）
- 网站发消息 -> 站点回复 -> 回传展示
- 支持整段回传

### M2：流式与稳定性

- 支持 `reply.delta` 流式回传
- 完成重连、超时、重试与错误码
- 增加基本监控与日志面板

### M3：多站点与插件化

- 接入多个 `connectorId`
- 引入 `bb-sites` 自动同步
- 灰度发布 + 自动回滚

## 9. 验收标准（Done Definition）

- 可在网站上稳定收发至少 2 个站点
- 单次任务失败可定位（有错误码与日志链路）
- 适配器更新失败不影响主流程（可回滚）
- 中转离线、站点未登录、适配器失效三类场景有清晰提示
- 关键路径有自动化测试（协议、队列、回滚）

## 10. 风险清单

- 站点改版导致适配器失效（高概率）
- 平台条款与风控限制（合规风险）
- 用户端环境差异（浏览器版本、网络、权限）

应对原则：

- 主程序慢更，适配器快更
- 社区主源 + 私有兜底并行
- 强化健康检查与回滚，而不是追求“永不失效”
