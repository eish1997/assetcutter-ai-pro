# 高度 3D 预览 — 开发文档

**状态**：首版已落地（`image.heightfield` + `ImageHeightfieldViewer` + `ImagePreviewOverlay` / `WorkflowSection`）；后续可按「实现清单」续迭代。  
**相关**：`components/ImagePreviewOverlay.tsx`、`components/preview/registry.tsx`、`components/preview/types.ts`、`services/workflowModelViewerStage.ts`（灯光/IBL 复用参考：`ImageModel3DViewer`）。

## 1. 产品定义

### 1.1 是什么

**高度 3D** 是当前**预览图**的一种显示方式：把二维图像当作**高度/置换场**，在 WebGL 里生成可旋转、可缩放的「浮雕 / 地形」观感。与 **全景** 同属「同一张图的另一种看法」，**不依赖**资产是否带有 GLB。

### 1.2 不是什么

- **不是**把高度图与 GLB 模型叠在同一视口里同时渲染（除非未来单独立项「贴置换到网格」）。
- **不是**第二个独立弹窗；仍走现有 **`ImagePreviewOverlay` + `PreviewShell`**。

### 1.3 与「3D 模型预览」的关系

| 模式 | 出现条件 | 数据来源 |
|------|----------|----------|
| **平面** | 有图预览 | `imageSrc` |
| **全景** | 业务开启 `enablePanoramaMode` | `imageSrc` |
| **高度 3D** | 有图预览（第一版：任意预览图） | `imageSrc` |
| **3D 模型** | 存在可预览的 `modelUrls`（与现网一致） | `modelSrc` + 格式推断 |

**GLB 预览**：仅当资产卡片有可解析的模型 URL 时出现；**无模型则不展示该 Tab / 不参与「仅模型」的分支**。  
**高度 3D**：与 GLB **无关**，可与 GLB 模式在同一预览会话内**并存**（用户通过分段按钮或 `Q` 在多种模式间切换）。

## 2. 界面与交互

### 2.1 展示方式

- 与 **`previewLayout === 'model3d'`** 时类似：中间内容区 **`absolute inset-0`** 铺满当前大图可视区，**整屏 WebGL**，底层为统一 lightbox 壳（背景、关闭、顶栏工具等）。
- 切到高度 3D 时，**不叠**中间可缩放平移的平面 `<img>`（与模型 3D 一致），避免滚轮/拖拽与 Orbit 冲突。
- **标注 / 裁切 / 局部重绘**：第一版仅在**平面**（及已有「全景 + 标注桥接」）使用；高度 3D 为**纯预览**。若未来要在高度视图上做工具，需单独设计叠层与坐标系（本文件不展开）。

### 2.2 顶栏与快捷键

- **右上角分段控件**：在现有「平面 / 全景 / 3D 模型」基础上增加 **「高度」** 一段（图标与文案需与设计一致）。
- **`Q`**：在可切换模式列表中增加 `heightfield`（名称以代码为准，例如 `previewLayout: 'heightfield'`），顺序建议：`flat` → `pano`（若启用）→ `heightfield` → `model3d`（若有模型）。顺序可在评审时微调，但需保证 **无模型时列表里不出现 `model3d`**。
- **左上角说明文案**：按模式分支补充高度 3D 的拖拽旋转、滚轮缩放、`Q` / `Esc` 等说明（与全景、模型 3D 块并列）。
- **滚轮**：与 `image.equirect`、`image.model3d` 一致，在 `components/preview/types.ts` 的 **`previewPolicyForMode`** 中为 **`image.heightfield`** 声明 **`captureGlobalWheel: true`**，并在 **`ImagePreviewOverlay`** 的全局 `wheel` 处理里与全景、模型 3D 同等对待，避免误切图。

### 2.3 可选控件（建议第二迭代或首版极简）

- **置换强度**（`displacementScale`）：滑条或「滚轮 + 修饰键」，避免 AI 图对比度极端时太平或穿模。
- **RGB → 高度** 策略切换（若首版固定为亮度则可在文档与 UI tooltip 中写死，后续再加）。

## 3. 技术架构

### 3.1 分层原则（避免与 GLB 逻辑搅在一起）

- **`ImagePreviewOverlay`**：只负责 **layout 枚举**、**谁占满中间**、**滚轮/快捷键仲裁**、**懒加载 Suspense**，不写位移算法。
- **新 Viewer 组件**（建议名：`ImageHeightfieldViewer.tsx`）：只负责 **从 `imageSrc` 建纹理 → 高度场 → Mesh → 渲染循环**，与 **`ImageModel3DViewer`** **并列**，**不要**合并进同一文件（避免 `modelSrc` / `imageSrc` 巨型分支）。
- **可复用**：与 **`ImageModel3DViewer`** 相同层级的 **Three.js + `OrbitControls`**、**`createWorkflowModelViewerStageAsync`**（或等价灯光/环境）、**`ResizeObserver`**、卸载 **`dispose`** 模式；**不复用** GLTF/FBX/OBJ 加载链路。

### 3.2 注册表

- 在 **`components/preview/registry.tsx`** 增加一项，例如 **`image.heightfield`** → `() => import('./viewers/ImageHeightfieldViewer')`。
- **`components/preview/types.ts`**：
  - **`RegisteredImagePreviewMode`** 增加 **`'image.heightfield'`**；
  - **`previewPolicyForMode('image.heightfield')`** → `{ captureGlobalWheel: true }`。
- **`LazyImagePreviewViewerProps`**：首版仅需 **`imageSrc`**；若增加强度等，用可选 props 扩展，避免破坏现有 Viewer。

### 3.3 父级类型同步

以下位置的 **layout 联合类型**需从 **`'flat' | 'pano' | 'model3d'`** 扩展为含 **`'heightfield'`**（或项目统一抽成 **`ImagePreviewLayoutMode`** 单处导出再引用，减少三处手写不一致）：

- **`components/ImagePreviewOverlay.tsx`**（props、`useState`、`modes` 数组、`viewerCapturesWheel`、条件渲染块、顶栏分段、帮助文案）。
- **`components/WorkflowSection.tsx`**：`lightboxPreviewLayout`、`onPreviewLayoutChange` 回调、依赖「仅平面」的逻辑（如分割提示「请切换到平面」——高度 3D 与全景、模型一样应视为非平面）。
- 其他传入 **`previewLayout`** / **`onPreviewLayoutChange`** 的调用方（如 **`CapabilityPresetSection`**、**`App.tsx`** 对话临时预览若有同类 state）：全局搜索替换并自测。

**分桶规则**：若存在「平面 / 全景」标注分轨，高度 3D 与模型 3D、全景一致，**不写入平面桶**；`onPreviewLayoutChange` 同步到父级时父级应把 `heightfield` 与 `pano` / `model3d` 同等处理（非 `flat`）。

## 4. 高度场实现要点

### 4.1 RGB 图当高度图

AI 输出多为 RGB，需在 GPU 前做一次**明确的高度编码**：

- **默认**：**亮度（luminance）**，例如 `0.299*R + 0.587*G + 0.114*B`（sRGB 线性近似可用 `ColorManagement` 策略与项目其余 Three 一致）。
- **写入位移纹理**：可用离屏 **`CanvasTexture` / `DataTexture`** 将每像素压成单通道灰度再作为 **`displacementMap`**，便于与 **`MeshStandardMaterial`** 对齐；或在 **`ShaderMaterial`** 内对原图采样后算高度（灵活，但维护成本高）。**首版推荐**：Canvas 降采样生成灰度图 → `THREE.CanvasTexture`，逻辑集中、易单测像素公式。

### 4.2 几何与材质

- **`PlaneGeometry`**（或 **`PlaneBufferGeometry`**）+ 足够 **width/height segments**（按纹理短边或上限如 256～512 cap，避免 4K 图 × 全分辨率细分爆显存）。
- **`MeshStandardMaterial`**：`map` 可选（贴原图颜色）、**`displacementMap`** + **`displacementScale` / `displacementBias`**；位移后 **`computeVertexNormals()`** 或依赖材质更新法线，保证光照可读。
- **相机**：`OrbitControls` 对准平面中心；初始 **`frameCameraToObject`** 可与模型预览类似（可抽公共小函数，避免复制粘贴过长）。

### 4.3 性能

- 对 **`imageSrc`** 解码后，位移贴图 **最长边限制**（如 1024～2048）再上传 GPU。
- **`imageSrc` / `innerLayoutStableKey` 变化**时完整 teardown 纹理与 mesh，避免泄漏。

### 4.4 跨域与 URL

- 纹理加载若走 `TextureLoader`/`Image`，需遵守项目 **跨设备 / 站内 API** 规范：与现有预览图一致使用已解析的 **`imageSrc`**，禁止写死 `localhost`；CORS 失败时 Viewer 内给出可读 **`error` 状态**。

## 6. 验收用例（手工）

- 无 `modelUrls`：顶栏无「3D 模型」，**仍可**进入高度 3D；`Q` 不经过模型项。
- 有 `modelUrls`：四项（或三项无全景）均可切换；高度与 GLB **互不替代**。
- 高度 3D 下滚轮 **不**触发切图/切版本；切回平面后恢复原有滚轮行为。
- 关闭预览再打开：默认回到 **平面**（与现网换图行为一致）。
- 大分辨率图：不卡死、不 OOM；弱机可接受帧率或明确降采样。

## 7. 风险与后续

- **非高度图**当高度看可能观感怪：首版接受；后续可加「强度」默认算法或弱提示。
- **法线 / 切线**：标准材质 + displacement 在部分 Three 版本需注意；升级 Three 时回归本 Viewer。
- **与 GLB 同资产**：仅切换模式，**不自动**同步「模型 UV 上的置换」——若产品要「贴到 GLB」，属新需求。
